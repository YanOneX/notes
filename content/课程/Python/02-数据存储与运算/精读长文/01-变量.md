# 变量：数据在程序里的落脚点

上一节我们把整数、小数、字符串、布尔值这些数据一个个写成了字面量，算是把"数据在程序里怎么写"这件事摸清了。可写完之后立刻会撞上一个别扭的地方：字面量是死的。你把 `1114.1` 写进代码，它就永远是 `1114.1`；明天播放量涨到 1200 万，你还得回来改这一行、重新运行一次。而程序真正跑起来的时候，绝大多数数据是要变的。

那这些会变的数据，在程序里到底存在哪儿？这就是变量要解决的问题。

## 从播放量说起：变量是装数据的容器

> **定义**：变量是程序中用来存储单个数据的容器。

这句话里有两个限定，都得咬住。第一，它是**容器**——像生活里拿来装东西的盒子、杯子、箱子，只不过程序里的容器装的是数据。第二，它装的是**单个**数据：一个变量只能存一个数据，不是一堆。

那什么样的数据值得交给变量保管？变量这个词本身就给了答案——变量，容易变化的量。程序开发里，凡是会随时间、随用户操作而改变的数值，都适合放进变量。

平时上网，哪些数据是容易变的？就看我们自己正在刷的这个 B 站界面。课程视频的播放量，随着时间一直在往上增；弹幕的数量，一轮一轮地涨；视频下方"现在有多少人正在看"，一会儿高一会儿低；还有点赞数、投币数、收藏数、转发数，以及这门课对应的笔记数量，全都摆在界面上，全都实时在变。

所以开发这样的系统时，就可以把这些数据各自记录在一个变量里——它们会变，而变量天生就是用来接住这种变化的。

容器长什么样，看下面这张示意：

```text
              变量 number（容器）
        ┌──────────────────────────────┐
        │            1114.1            │  ← 容器里当前存放的数据
        └──────────────────────────────┘
                     ▲
                     │  通过容器名 number 取用
```

方框就是变量这个容器，框里的数字是它此刻装着的数据。容器有名字，我们靠名字找到容器，再从容器里把数据取出来。

这里有一点必须认识清楚，也是初学者最容易含混的地方：

> **易错点**：变量指的是那个**容器**，不是容器里装的数据。数据是会换的，容器始终是同一个。

我们把播放量 `1114.1`（单位：万）放进名为 `number` 的变量里，往后这个数涨到 `1200`，变的是容器里的内容，`number` 这个容器本身没变。也正因为容器一直在，我们才能通过它随时找到里面"目前"存着的那个值。

## 定义一个变量，只需要一个等号

Python 里定义变量的语法短得有点不像话：左边一个变量名，中间一个等号，右边一个值。

```python
number = 1114.1
```

拆开看，三部分的职责分得很清楚：

```text
number = 1114.1
└─┬──┘   └──┬──┘
 变量名     变量值
（容器的名字） （要放进容器的数据）
      ↑
   赋值运算符：把右边的值赋给左边的变量
```

等号前面是变量名，等号后面是变量值。`number` 是我们给这个容器起的名字，相当于"我造了一个容器，名字叫 number"；`1114.1` 是往这个容器里放的东西。中间那个等号不是数学里"两边相等"的意思，它是**赋值运算符**：把右边算出来的值，赋给左边那个变量。

所以这行代码读出来是"把 1114.1 交给 number"，而不是"number 等于 1114.1"。

光定义还不算完，我们得看看容器里到底装进去没有。把它打印出来：

```python
# 演示变量
number = 1114.1
print(number)
```

运行结果是 `1114.1`。注意 `print(number)` 打印的不是"number"这几个字母，而是 number 这个容器里记录的那个值——这也印证了前面那句话：变量是容器，取变量，取到的是容器里的东西。

运行的时候还会遇到一个小情况：右键运行执行的是整个 Python 文件，前面写过的字面量演示代码会一起跑，于是屏幕上先刷出一堆旧输出。想只看这一段，把前面的代码注释掉就行。选中前面那部分代码，按下 `Ctrl + /`，整段就被批量注释了；再按一次 `Ctrl + /`，注释取消。被注释掉的行，解释器执行时直接跳过，屏幕上就只剩这两行的结果。

还有一处代码风格上的细节，容易被当成"规定"：

> **提示**：赋值运算符的前后一般各留一个空格，写成 `number = 1114.1` 而不是 `number=1114.1`。这是 Python 官方代码风格里的建议，属于**规范**，不遵守程序照样跑；但既然官方这么建议，写代码时就顺手守上。

变量之所以叫变量，就在于里面装的东西能换。播放量涨了，不需要重新定义一个新容器，只要给同一个 `number` 再赋一次值：

```python
number = 1114.2
print(number)
```

这一次输出 `1114.2`。`number` 还是那个 `number`，容器没变，容器里的数据被换掉了，原来的 `1114.1` 就此丢弃。

更贴近实际的写法是让变量自己参与计算。假设播放量又涨了 1 万：

```python
number = number + 1
print(number)
```

等号右边先算：取出 `number` 现在存的 `1114.2`，加上 `1`，得到 `1115.2`；然后把结果重新赋回左边的 `number`。这里加的是 `1` 而不是 `10000`，因为 `number` 里存的是以"万"为单位的数，加 1 就等于加 1 万。运行输出 `1115.2`，播放量确实涨了 1 万。

> **注意**：`number = number + 1` 这种写法在数学里是不成立的，在程序里却完全合法。等号在这里是"赋值"，不是"相等"，右边的旧值先被取出来参与运算，算完再放回左边的容器，先后顺序不能颠倒。

> **注意**：在 Python 里，"定义变量"和"给变量赋值"是同一件事，没有"只写个名字、先不给值"这种写法。所以变量一定是先赋值、后使用；还没赋过值就去用，解释器会直接报错，说这个名字没有被定义。

## 变量不挑类型，但项目里最好专一

定义变量的时候，我们只写了名字和值，从没写过"这是个浮点数"、"这是个字符串"。Python 允许这么干，是因为它是**动态类型语言**：定义变量时不需要指定类型，程序运行起来之后，解释器会自动做类型检查。

动态类型带来的直接结果是，同一个变量可以先后接收不同类型的数据。`number` 一开始装的是 `1114.1`，这是一个浮点数，也就是小数；现在我给它换个值：

```python
number = "OK"
print(number)
```

`"OK"` 带引号，是字符串类型。运行输出 `OK`，`number` 这个容器现在装的是个字符串，一点问题没有。再换一次：

```python
number = True
print(number)
```

输出 `True`。`True` 是布尔类型，表示"真"，`number` 又变成了布尔类型。同一个变量，三个回合装了三种类型：

| 赋值语句 | 装进去的值 | 类型 |
| :--- | :--- | :--- |
| `number = 1114.1` | `1114.1` | 浮点数（小数） |
| `number = "OK"` | `OK` | 字符串 |
| `number = True` | `True` | 布尔值 |

语言层面允许，不等于项目里该这么写。

> **易错点**：Python 允许一个变量反复换类型，但项目开发中推荐一个变量只存一种类型。

道理说白了很简单：`number` 这个名字，我们在定义的时候就规划好它是存播放量的、是个小数，那就让它老老实实装小数。一会儿装小数、一会儿装字符串、一会儿装布尔值，读代码的人（包括几个月后的自己）看到 `number` 根本猜不出里面是什么。真需要存字符串、存布尔，另起一个变量就行，各装各的。

## 播放量案例：让变量参与计算

变量讲完了定义，还得落到一个具体需求上，才知道它到底怎么用。就用刚才那个 B 站播放量的场景：

> 基础播放量是 20.7 万，每月新增播放量 50 万，请输出未来两个月每个月的播放量。

需求里有两个数字是相对稳定的"参数"——基础播放量、每月新增量；要算的是两个月的播放总量。那就先定义两个变量，把这两个数分别存起来：

```python
base = 20.7   # 基础播放量，单位：万
incr = 50     # 每月新增播放量，单位：万
```

注释写在语句后面，比写在上面一行更容易看清哪个变量是干什么的。

第一个月的播放总量，就是基础播放量加上一个月的新增量。把这个算式直接写进 `print` 里：

```python
print("未来第一个月的播放总量为", base + incr)
```

`print` 想一次输出多项数据时，多项之间用逗号分隔：第一项是一句字符串描述，第二项是 `base + incr` 这个算出来的结果。逗号分隔的几项，最后会被拼到同一行里输出，中间自动隔开。

运行结果是 `未来第一个月的播放总量为 70.7`。`20.7 + 50 = 70.7`，没问题。屏幕上没有"万"字，因为变量里存的就是以万为单位的数，单位在人读的时候补上。

第二个月的播放总量，是在基础播放量上再加两个月的新增：`base + incr + incr`。这一行和上一行几乎一样，没必要手敲，在 PyCharm 里把光标放在这一行，按下 `Ctrl + D` 就能快速复制一行，改改文字和算式即可：

```python
print("未来第二个月的播放总量为", base + incr + incr)
```

运行后两行一起输出：

```text
未来第一个月的播放总量为 70.7
未来第二个月的播放总量为 120.7
```

> **提示**：这个案例里变量一共就两个，但分工很清楚——`base` 记住不变的起点，`incr` 记住每个月的增量。需求再往后延伸到第三个月、第四个月，也只是多加一个 `+ incr`，起点的数字一处都不用改。

## 一条语句定义多个变量

上面那两行定义，其实还有更紧凑的写法。两个变量可以合并到一行里定义：

```python
base, incr = 20.7, 50
```

读法是有讲究的：等号左边是变量名，多个变量名之间用逗号分隔；等号右边是值，多个值之间同样用逗号分隔。赋值的时候按位置一一对应——第一个值 `20.7` 交给第一个变量 `base`，第二个值 `50` 交给第二个变量 `incr`。

运行效果和分两行写完全一样，`base` 还是 20.7，`incr` 还是 50。变量一多，这种写法的好处就显出来了：相关的几个变量成组出现，一眼能看出它们是一起用的。

> **易错点**：逗号分隔的位置对应关系不能乱。写成 `base, incr = 50, 20.7`，两个变量拿到的值就正好反过来了，程序不会报错，但算出来的播放量会离谱。

## 标识符：变量名的四条硬规则

变量得有名字，名字不能随便起。Python 里给变量、函数、类这些元素起的名字，统称为**标识符**。目前我们只接触到变量，所以这一节讨论的其实就是变量名。

标识符有一套非常明确的规则。这里说的"规则"是**规定**——必须遵守，没有商量的余地，违反了程序就跑不起来。

| 规则 | 内容 | 细节 |
| :--- | :--- | :--- |
| 组成 | 只能包含字母、数字、下划线 | 字母包括大写 A–Z 和小写 a–z，数字是 0–9；符号里只认下划线 `_` 一个 |
| 开头 | 不能以数字开头 | 可以包含数字，但数字不能打头；下划线可以打头 |
| 关键字 | 不能使用 Python 的关键字 | `True`、`False`、`and`、`or`、`if`、`else`、`for`、`while` 等都是关键字 |
| 大小写 | 严格区分大小写 | `age`、`Age`、`AGE` 是三个互不相干的变量 |

第一条最容易被忽略的是"符号只认下划线"这一层：标识符里不是"可以包含字母、数字、下划线，也可以包含别的符号"，而是除了这三类，其他符号一概不行。`$`、`-`、`.`、空格，统统不许出现。

第三条的关键字，是语言自己留着用的词。`True` 和 `False` 是布尔类型对应的两个值，本身就是字面量，程序要靠它们表示真假；`and`、`or` 是后面要学的逻辑运算；`if`、`else`、`for`、`while` 是后面要学的流程控制。这些词被语言占用了，你再去定义一个同名变量，解释器就分不清你想表达哪个意思。

第四条讲的是大小写敏感。`age`、`Age`、`AGE` 长得像，在 Python 眼里是三个完全不同的变量，各装各的值，互不干扰。

## 拿一组名字逐个判一遍

规则只有四条，真拿名字来判的时候，还是有几个地方会卡住。下面这一组变量名，逐个对照上面四条规则过一遍：

| 变量名 | 判定 | 依据 |
| :--- | :--- | :--- |
| `name` | 合法 | 全小写字母，不以数字开头，也不是关键字 |
| `Name` | 合法 | 允许出现大写字母，其余条件都满足 |
| `_name` | 合法 | 下划线可以开头 |
| `__name` | 合法 | 下划线开头的个数不限，一个两个都行 |
| `na_me` | 合法 | 下划线可以出现在中间 |
| `name_` | 合法 | 下划线也可以收尾 |
| `na$me` | 非法 | `$` 不属于字母、数字、下划线，标识符里不许出现 |
| `and`、`or` | 非法 | 这两个是关键字 |
| `True`、`False` | 非法 | 布尔类型的两个值，是关键字 |
| `true` | 合法 | 全小写，不是关键字，只是名字起得像 |
| `6name` | 非法 | 数字开了头 |
| `name6` | 合法 | 数字不在开头，放在中间或结尾都可以 |
| `nameME` | 合法 | 大小写混写不违反规则 |

表格里最值得停一下的是 `true` 和 `True` 这一对。

> **易错点**：Python 的关键字是首字母大写的 `True` 和 `False`。全小写的 `true`、`false` 并不是关键字，因为它们和关键字的大小写不同，按"严格区分大小写"这条规则，它们就是两个不同的名字。所以 `true` 可以当变量名，`True` 不行。

规则记不牢也没关系，判断一个名字合不合法，最快的办法是敲进编辑器跑一把：能正常运行就是合法，跑不起来就是非法。

先试全小写的：

```python
true = 1
print(true)
```

运行正常，输出 `1`，反过来证明 `true` 确实是合法的标识符。

再把首字母改成大写：

```python
True = 1
```

运行直接报错，提示是语法错误，不允许给 `True` 赋值。原因就是 `True` 是布尔类型的字面量、是关键字，不能被当作变量名使用。

再试数字开头的：

```python
6name = "Python"
```

这一行甚至不用运行，编辑器里已经标红了——`6name` 是非法标识符，语法层面就过不去。

## 规则之上还有规范：PEP 8 的三条建议

规则是硬性的，守不住程序就崩。但符合规则的名字，未必是好名字。`a1`、`a2`、`a3` 一路排下去，每一个都合法，可它们什么都没告诉你。

Python 官方对变量名还有一套**规范**：

> **注意**：规范不是规定。不规范程序照样跑，官方只是建议这么写。

这套规范写在 PEP 8 里。PEP 是 Python 社区的一套技术文档和标准化机制，PEP 8 专门描述 Python 的代码风格与编码规范，官方文档里有完整的说明。

针对变量名，PEP 8 提了三条：

| 规范 | 做法 | 反例 |
| :--- | :--- | :--- |
| 见名知意 | 名字要能说明里面存的是什么 | `a1`、`a2`、`a3` |
| 多个部分用下划线连接 | `update_time`、`my_name`、`user_first_name` | `updatetime`、`myname` |
| 英文字母全小写 | 变量名里不出现大写字母 | `Name`、`UserName` |

第一条最好理解。`name` 一看就是名字，`age` 一看就是年龄，`color` 一看就是颜色，读代码的人不用翻别处。反过来，满屏的 `a1`、`a2`、`a3`、`a4`，谁也不知道哪个装的是什么。

这件事在小脚本里无所谓，到了大型项目里就是灾难。项目后期要维护，所谓维护难，往往就是过了几个月、过了一两年再回来看这段代码，`a1` 里存的是啥、`a2` 里存的是啥，全想不起来了，只能一行行倒推。所以这些名字虽然合法，项目里并不建议这么起。

第二条管的是"一个名字由几个单词拼成"的情况。`update` 是更新，`time` 是时间，两个词拼在一起表示"更新时间"，中间用下划线连起来，写成 `update_time`；`my` 和 `name` 拼成 `my_name`；`user`、`first`、`name` 三个词拼成 `user_first_name`，每两个相邻的单词之间都有一个下划线。而 `updatetime`、`myname` 把单词直接粘在一起，读的时候得靠猜在哪里断开，不符合规范。

这种"多个部分用下划线分隔"的写法有个专门的名字：

> **定义**：蛇形命名法（snake_case）——多个单词之间用下划线连接，整体看上去像一条蛇。

第三条最省事：变量名的英文字母全小写。注意这一条只管变量名，别的元素（比如后面要学的类）各有各的写法，现在不用混。

这三条规范不用死记。后面每次定义变量都按这个来，写得多了自然就成习惯了。

## 变量交换：两个杯子的饮料怎么换

变量定义、命名都通了，最后用一个案例把理解再压实一层。

> 有两个变量 `a` 和 `b`，`a` 的值是 10，`b` 的值是 20。把 `a` 的值赋给 `b`、`b` 的值赋给 `a`，也就是让两个变量的值互换，然后把两个变量输出到控制台。

需求看着简单，甚至简单到让人想直接写两行：

```python
a = 10
b = 20

a = b
b = a

print(a, b)
```

`a = b` 把 `b` 的值赋给 `a`，`b = a` 再把 `a` 的值赋给 `b`，读起来好像正是"交换"。但这么写是错的，跑出来两个都是 20。

错在哪儿，得一步一步跟着容器里的变化走：

```text
步骤             a 里面的值        b 里面的值
初始             10                20
a = b 执行后     20                20      ← a 原来的 10 被覆盖，彻底丢了
b = a 执行后     20                20      ← b 取到的是 a 的新值 20
```

第一行 `a = b`，把 `b` 的 20 放进 `a`，`a` 原来的 10 就此消失。第二行 `b = a`，此时 `a` 里已经是 20 了，取出来的自然还是 20，再放进 `b`，`b` 也成了 20。两行跑完，两个容器装的是同一个值，跟需求正好相反。

问题的根子在于：**直接赋值会覆盖，而被覆盖的那个值，后面还要用**。

生活里有个几乎一模一样的场景。桌上两个杯子，一个装满雪碧，一个装满可乐，现在要把两杯饮料对调——雪碧倒进第二个杯子，可乐倒进第一个杯子。不动手还好，一动手就发现没法直接倒：第一个杯子里的雪碧不倒走，可乐就没地方放；可雪碧一旦倒掉，就没了。

办法谁都会想到：再拿一个空杯子过来。

```text
① 第一个杯子的雪碧倒进空杯子    →  第一个杯子空了
② 第二个杯子的可乐倒进第一个杯子 →  第二个杯子空了
③ 空杯子里的雪碧倒进第二个杯子   →  雪碧、可乐对调完成
```

三个杯子，三步倒换，靠的就是那个"多余的"空杯子临时寄存。

变量交换是一模一样的道理。每个变量就是一个容器，只不过装的是数据。要让两个容器里的数据对调，也得借第三个容器临时寄存一下，这个容器就是第三个变量：

```python
a = 10
b = 20

c = a      # 先把 a 的值寄存到 c，此时 c 是 10
a = b      # a 被覆盖成 20
b = c      # b 取回 c 里寄存的 10

print(a, b)
```

三行代码对应三次倒换，一步都不能少：

```text
步骤        a        b        c
初始        10       20       —
c = a       10       20       10
a = b       20       20       10
b = c       20       10       10
```

`c = a` 时，`a` 还是 10，所以 `c` 拿到 10，这就是"把雪碧倒进空杯子"。`a = b` 时，`b` 还是 20，`a` 变成 20，第一个杯子腾空之后装进了可乐。最后 `b = c`，`c` 里存着原始的 10，`b` 拿到 10，雪碧回到了第二个杯子。运行输出 `20 10`，交换完成。

> **易错点**：第三行必须写 `b = c`，绝不能写 `b = a`。走到第三步时，`a` 已经被改成 20 了，再去读 `a` 拿到的是新值，等于又绕回那个"两个都变 20"的坑。

这里引入的 `c` 是**临时变量**。它不在需求里，需求只关心 `a` 和 `b`，`c` 的唯一职责就是在中途替 `a` 保存一下原值，存完就没它什么事了。临时变量这个角色在后面会反复出现，凡是"要动一个值，但后面还要用它的旧值"的场合，都需要它。

## 本讲提到的题目

> 有三个变量 `a`、`b`、`c`，`a` 是 100，`b` 是 200，`c` 是 300。将 `a`、`b`、`c` 的值分别赋值给 `c`、`a`、`b`，也就是 `c` 拿 `a` 的值、`a` 拿 `b` 的值、`b` 拿 `c` 的值，然后把三个变量输出到控制台。

这道题就是刚才变量交换的推广，只是从两个变量变成了三个，难度略微提升一点。思路完全一致：三个变量的值首尾相接转一圈，任何一次直接赋值，都会把后面还要用的旧值毁掉，所以必须先把被覆盖的值寄存在临时变量里。

解析可以这样推：先把 `a` 的 100 寄存进一个临时变量；接着让 `a` 接住 `b` 的 200；再让 `b` 接住 `c` 的 300；最后把临时变量里的 100 交给 `c`。这样转一圈，每个变量都拿到了"上一个"变量的原值，一个也没丢。

按这个顺序推下来，交换后 `a` 是 200，`b` 是 300，`c` 是 100。
