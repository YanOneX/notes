# 赋值、比较与逻辑运算符

算术运算符那一节练完，`+`、`-`、`*`、`/`、`//`、`%`、`**` 都能算出一个数了。可算出来的数如果没人接住，程序跑完就散了——结果得存进变量里，而负责"存"这件事的，是第二类运算符：赋值运算符。

顾名思义，赋值运算符就是为变量做赋值操作的。这一类符号看着不少，但真正需要费脑子理解的只有一个，其余全是从它身上长出来的。先把这一个看清楚，再打开 PyCharm 一个一个跑。

## 赋值运算符：把右边的结果交给左边的变量

一个等号 `=` 就是赋值运算符，也是最简单、用得最多的那一个。它只做一件事：把等号右侧的运算结果，赋值给左侧的变量。

```python
number = 1 + 2
```

`1 + 2` 先算出 `3`，然后 `3` 被交到 `number` 手里，所以 `number` 的值就是 3。

> **提示**：`=` 在 Python 里读作"把右边赋给左边"，不读"等于"。它不是数学里的等号——数学里的"等于"在 Python 里要写成两个等号 `==`，这个区别到比较运算符那一节还会再撞一次，现在先把印象埋下。

剩下的赋值运算符，全部基于这个等号：`+=`、`-=`、`*=`、`/=`、`//=`、`%=`、`**=`。名字都叫"某某赋值运算符"——加法赋值、减法赋值、乘法赋值……

| 运算符 | 写法示例 | 完全等效于 | 一句话含义 |
| :--- | :--- | :--- | :--- |
| `=` | `number = 2` | —— | 把 2 赋给 `number` |
| `+=` | `number += 2` | `number = number + 2` | 在原有值上加 2 |
| `-=` | `number -= 2` | `number = number - 2` | 在原有值上减 2 |
| `*=` | `number *= 2` | `number = number * 2` | 在原有值上乘 2 |
| `/=` | `number /= 2` | `number = number / 2` | 在原有值上除以 2 |
| `//=` | `number //= 2` | `number = number // 2` | 在原有值上整除 2 |
| `%=` | `number %= 2` | `number = number % 2` | 把原值对 2 取余 |
| `**=` | `number **= 2` | `number = number ** 2` | 把原值求 2 次方 |

第三列那句"完全等效于"是这一节的全部秘密：只要把 `+=` 翻译成 `number = number + 2`，其余七个就都懂了。

### 复合赋值：先算一遍，再存回原变量

先看加法。`number += 2` 等效于 `number = number + 2`，意思是：`number` 这个变量，要在它原来数据的基础上再加上 2，然后把新结果存回 `number` 自己身上。

```python
number = 3
number += 2
print(number)     # 5
```

初始值是 3，那么 `number = number + 2` 就是 3 + 2，`number` 变成 5。

```text
number += 2          （假设此时 number 是 3）

步骤 1   取出 number 当前的值        3
步骤 2   与右侧的 2 做加法           3 + 2 = 5
步骤 3   把结果写回 number 自己       number = 5
```

读这张图只记住一点：复合赋值的右边不是"另一个变量"，而是"我自己现在是多少"。所以它天然带着累积的意味——同一句 `number += 2` 连着写两遍，值就在上一次的结果上继续往上叠，而不是每次都回到最初那个数。

搞清加法赋值之后，下面的全是类似的：

- `number -= 2` 就是 `number = number - 2`，原值减 2；
- `number *= 2` 就是 `number = number * 2`，原值乘 2；
- `number /= 2` 就是 `number = number / 2`，原值除以 2；
- `number %= 2` 是取模赋值，把原值对 2 取余再存回去；
- `number //= 2` 是取整赋值，把原值整除 2 再存回去；
- `number **= 2` 是幂指数赋值。写法是 `number` 后面跟两个星号，再跟一个等号，右侧写指数：`number **= 2` 就是 `number = number ** 2`，即把 `number` 求二次方；右侧写 3 就是求三次方。

> **易错点**：`+=`、`-=`、`**=` 这些符号，虽然看起来是两个符号拼起来的，但它本质上就是一个符号。中间不能加任何其他字符，也不能加空格。`number + = 2` 是错的，`number ** = 2` 也是错的，必须连着写。

### 在 PyCharm 里把八种赋值跑一遍

演示代码从最基本的赋值起步，一路把复合赋值串下来：

```python
number = 85
print(number)

number += 10
print(number)

number -= 10
print(number)

number *= 10
print(number)

number /= 10
print(number)

number //= 10
print(number)

number %= 3
print(number)

number **= 3
print(number)
```

先别急着运行，逐行预测一遍结果——这是检验有没有真懂最快的办法。

第一行 `number = 85`，用的是最基本的赋值运算符，`number` 就是 85。接着 `number += 10`，等价于 `number = number + 10`，85 + 10 得 95。

再往下 `number -= 10`，等价于 `number = number - 10`。注意此刻 `number` 已经不是 85 而是 95，95 减 10 再赋回 `number`，`number` 又回到 85。

`number *= 10`，85 乘 10，得 850。

`number /= 10`，850 除以 10。这里要停一下：除法运算的结果是一个小数，就算 850 能被 10 整除，结果也写成 `85.0` 而不是 `85`。这一行执行完，`number` 变成浮点数 85.0。

紧接着 `number //= 10`，85.0 整除 10 得 8。但因为参与运算的 85.0 是浮点数，结果同样带小数点，是 `8.0`。

`number %= 3`，8.0 对 3 取余是 2，同样因为浮点数参与，写成 `2.0`。

最后 `number **= 3`，2 的三次方是 8，结果还是浮点数 `8.0`。

运行输出与预测完全一致：

```text
95
85
850
85.0
8.0
2.0
8.0
```

> **结论**：只要算术运算里有浮点数参与，结果就是浮点数，后面一路都带着 `.0`。这里的"传染源"是 `number /= 10` 那一句。

反过来验证一下这个判断：把 `number /= 10` 那一行注释掉，除法不存在了，`number` 就不会变成浮点数，后面的整除、取模、幂运算结果全都保持整数，不再有 `.0`。所以那一串 `.0` 不是 `//=`、`%=`、`**=` 自己带出来的，而是上一句除法的结果一路传下来的。

赋值运算符本身不改变类型，它只负责把右边算出来的东西原样存回左边。这部分要掌握到什么程度？每一种赋值运算符的具体含义和效果，都要能一眼翻译成"`number = number` 某某 几"。

练完这一节，先暂停，打开自己的 PyCharm 把这些敲一遍——`+=` 和 `-=` 尤其值得改几次数字自己试。

## 比较运算符：结果只可能是 True 或 False

算术、赋值之后，第三类是比较运算符。顾名思义，它是用来比较两个值之间的关系的，所以也叫关系运算符。

它的工作方式是：自动计算运算符左右两边的表达式（可能是两个变量，也可能是两个表达式），然后返回一个布尔值作为结果。

> **定义**：布尔值只有两个——`True` 和 `False`。`True` 为真，表示这个比较关系成立；`False` 为假，表示这个比较关系不成立。所有比较运算符的运算结果都是布尔值，没有例外。

### 六个符号的写法，逐个认一遍

常见的比较运算符一共六个：

| 运算符 | 读法 | 示例 | 什么时候是 True |
| :--- | :--- | :--- | :--- |
| `==` | 等于 | `a == b` | a 与 b 的值相等 |
| `!=` | 不等于 | `a != b` | a 与 b 的值不相等 |
| `>` | 大于 | `a > b` | a 比 b 大 |
| `>=` | 大于等于 | `a >= b` | a 比 b 大，或与 b 相等 |
| `<` | 小于 | `a < b` | a 比 b 小 |
| `<=` | 小于等于 | `a <= b` | a 比 b 小，或与 b 相等 |

第一个是等于，写两个等号。这里必须掰清楚：一个等号是赋值运算符，给变量赋值用的；两个等号连在一起写，才是比较运算符。中间不能写空格，必须连着。

`a == b` 判断 a 和 b 的值是否相等：相等，结果是 `True`，表示这个比较关系成立；不相等，结果是 `False`，表示不成立。

第二个是不等于：在等号前面加一个叹号，`!=`。叹号和等号之间同样没有任何其他字符，也没有空格。`a != b` 判断 a 是否不等于 b，确实不等于就返回 `True`，否则返回 `False`。

第三个是大于号 `>`，和数学里一样，`a > b` 判断 a 的值是否比 b 大。

第四个大于等于，这里和数学写法有差异。数学里写"大于等于"是一个大于号底下加一道横线：$\ge$。键盘上根本没有这个符号，所以编程语言里把两个符号拼在一起——前面一个大于号，后面一个等于号，`>=`。

小于和小于等于同理：小于号就是 `<`；小于等于在数学里是小于号下面画一道横线 $\le$，键盘上同样打不出来，于是写成小于号加等号 `<=`。

> **提示**：键盘上 `>`、`<`、`!` 这三个符号都不在明面上，得专门记一下位置——写比较运算符时最常缺的就是它们。

### 一组 100 的比较，验证结果一定是布尔值

演示用的例子全拿 100 开刀，一共七行：

```python
print(100 == 100)
print("100" == "100")
print(100 != 100)
print(100 < 100)
print(100 <= 100)
print(100 > 100)
print(100 >= 100)
```

逐行看：

- `100 == 100`，两边都是数字 100，相等，结果 `True`；
- `"100" == "100"`，两边都是字符串 `"100"`，两个值完全一致，同样相等，结果也是 `True`；
- `100 != 100`，100 和 100 必然相等，"不等于"自然不成立，结果 `False`；
- `100 < 100`，100 不可能小于 100，结果 `False`；
- `100 <= 100`，虽然"小于"不成立，但它还包含"等于"，结果 `True`；
- `100 > 100`，结果 `False`；
- `100 >= 100`，因为带了等号，100 等于 100 也算满足，结果 `True`。

运行输出：

```text
True
True
False
False
True
False
True
```

七个结果和预测一模一样。这一组例子把话说明白了：比较运算符组成的表达式，运算结果就是一个布尔值。`True` 表示条件成立，`False` 表示条件不成立。

### 四道需求：把一句话翻译成一个比较

写法会了，接下来是选：给一个业务需求，该用六个里的哪一个。四个需求，逐个过。

第一个：在数学计算中，判断一个数是否为偶数，要用哪个比较运算符？

先回到判断方法本身。拿 1、2、3、4 这几个数看：1 和 3 是奇数，2 和 4 是偶数。怎么判断出来的？用这个数除以 2——除完余 1，就是奇数；除完能整除、余 0，就是偶数。

所以这里先要做的是取余：让这个数对 2 取模，`% 2`。余数为 0 就是偶数，余数为 1 就是奇数。

但题目问的是比较运算符——取完余之后，还要判断这个余数"是不是等于 0"，这一层判断落到 `==` 上。完整写出来是 `number % 2 == 0`：先 `%` 取余，再用 `==` 比较。

第二个：电商项目的支付业务里，要判断银行卡余额是否充足，要用哪个运算符？

余额充足的意思是：卡里的钱得大于等于商品金额。差一点都不行，正好相等可以买，多于更可以。所以是 `>=`，写成 `balance >= price`。

第三个：电商项目里购买商品，要判断商品库存是否足够，用哪个运算符？

和余额是同一个道理：库存数量得大于等于要买的数量，`stock >= count`，还是 `>=`。

第四个：点餐项目里筛选商品，只点不超过 100 元的菜品，用哪个运算符？

"不超过 100 元"就是小于等于 100，`price <= 100`，用 `<=`。

> **提示**：这四道题最容易答错的是第一题——满脑子都是取余，答案却要落在比较运算符上。取余是算术运算符的活，比较才是这一步真正问的东西。

## 逻辑运算符：把几个条件连成一个判断

前三类运算符——算术、赋值、比较——和数学里的运算符都很像，学起来有熟悉感。第四类逻辑运算符不一样，很可能是第一次接触。

先举个例子感受一下。

在京东这类电商网站买电脑，需求是三条：价格必须在一万块钱以内；得是大品牌；还得是高配置。这三条之间是什么关系？必须同时成立才符合需求——一万以内，而且是大品牌，并且配置高。三个条件之间全是"并且"的关系：得满足第一个，而且得满足第二个，并且还得满足第三个。

连接条件与条件之间的这个"并且"，在编程里就叫逻辑运算符。Python 里用关键字 `and` 表示，`and` 就是"并且"。

换一个场景。点外卖，需求是：要么评分最高的餐厅，要么配送最快的餐厅。这两个条件是同时成立，还是满足其中一个就行？显然是满足其中一个就符合要求。这时它不再是"并且"，而是"或者"——评分最高的，或者配送最快的。Python 里用关键字 `or` 表示"或者"。

所以逻辑运算符干的事，就是把多个条件连接起来。

> **定义**：逻辑运算符用于连接多个条件表达式。条件表达式的结果是布尔值（真或假），逻辑运算符运算之后的结果同样是布尔值，表示这多个条件最终到底成不成立。

### and：两侧都成立，整体才成立

`and` 叫逻辑与，"与"就是"并且"，必须同时成立才符合条件。

两个条件表达式中间用 `and` 连起来，意思就是：你得满足第一个，并且还得满足第二个。`and` 的左右两侧都是 `True`，最终结果才是 `True`；只要左边或者右边有任何一个是 `False`，整体结果就是 `False`。

| 左侧条件 | 右侧条件 | `and` 的结果 |
| :--- | :--- | :--- |
| `True` | `True` | `True` |
| `True` | `False` | `False` |
| `False` | `True` | `False` |
| `False` | `False` | `False` |

### or：有一个成立，整体就成立

`or` 叫逻辑或，"或"就是"或者"，多个条件只要有一个符合就可以。

`a < b or b < c` 的意思是：a 小于 b，或者 b 小于 c，这两个条件有任何一个成立，结果就是 `True`。左侧成立是 `True`，右侧成立是 `True`，两侧都成立还是 `True`。

什么时候是 `False`？只有左右两个表达式的结果都是 `False`，结果才是 `False`。

| 左侧条件 | 右侧条件 | `or` 的结果 |
| :--- | :--- | :--- |
| `True` | `True` | `True` |
| `True` | `False` | `True` |
| `False` | `True` | `True` |
| `False` | `False` | `False` |

```text
条件 A ──┐
         ├──► and ──► 两侧全 True 才输出 True
条件 B ──┘

条件 A ──┐
         ├──► or  ──► 有一侧 True 就输出 True
条件 B ──┘
```

两个连接词的区别就压在最后半句：`and` 要求"全都要"，`or` 只要求"有一个"。

### not：把真假翻过来

第三个是 `not`，叫逻辑非，"非"就是取反。`True` 取反是 `False`，`False` 取反是 `True`，就一个取反操作。

`not` 这一节只交代到这儿，后面用到的时候再演示、再介绍。

## 两个案例：一个问区间内，一个问区间外

### 案例一：判断数字是否在 10~20 之间

需求：键盘上录入一个整数，判断这个数字是否在 10 到 20 之间。在就输出 `True`，不在就输出 `False`。

条件怎么拆？"在 10 到 20 之间"包含两层：这个数得大于等于 10；这个数还得小于等于 20。也就是 `number >= 10` 和 `number <= 20` 两个条件，必须同时成立——连接词是 `and`。

```python
number = int(input("请输入一个整数："))
print(f"{number} 在 10~20 之间：", number >= 10 and number <= 20)
```

两处细节值得说。

一是 `input()`：接收键盘录入的数据要用这个语句，括号里写提示信息"请输入一个整数"。它拿到的内容用一个变量接住，这里叫 `number`。

二是 `int()`：键盘上录入的所有数据都是字符串类型，而这里要做数字类型的比较，得先把字符串转成数字。`int()` 就是这个转换工具，把 `number` 传进去，转完再赋回 `number`，此时它才真的是数字。这两步可以合成一句 `int(input("请输入一个整数："))`，直接把 `input()` 的结果交给 `int()`，不用先存一次再转一次。

输出部分用格式化输出：先把"某个数在 10~20 之间"这句话拼出来，后面接一个逗号，再把判断结果输出。

`and` 连接的这两个条件什么时候是 `True`？两个条件同时成立，也就是左右两侧的运算结果都是 `True`，整体才是 `True`；否则就是 `False`——左右两侧有任何一个不成立，结果就是 `False`。

运行，输入 5：5 大于等于 10 不成立，第一个条件已经是 `False`，只要有一个不成立，结果就是 `False`。

再输入 15：15 大于等于 10 成立；15 也小于等于 20，第二个条件也成立。两个条件同时成立，结果 `True`。

再输入 60：60 大于等于 10 成立，第一个条件是 `True`；但 60 小于等于 20 不成立，第二个条件是 `False`。整体结果 `False`。

| 输入 | `number >= 10` | `number <= 20` | `and` 的结果 |
| :--- | :--- | :--- | :--- |
| 5 | `False` | `True` | `False` |
| 15 | `True` | `True` | `True` |
| 60 | `True` | `False` | `False` |

三次输入覆盖了三种情况：左边条件不成立、右边条件不成立、两边都成立。

写这段代码时 PyCharm 会在这行下面画一条波浪线。鼠标放上去，提示是"简化链式比较"，点一下那个按钮，IDE 会把代码自动改成：

```python
print(f"{number} 在 10~20 之间：", 10 <= number <= 20)
```

`10 <= number <= 20` 就是 Python 的链式比较，写法和数学里的 $10 \le number \le 20$ 一模一样，效果与 `number >= 10 and number <= 20` 完全相同——两个条件必须同时成立。

> **提示**：链式比较更短也更好读，实际开发里推荐用它。这一节为了讲清 `and` 的作用，代码里保留 `number >= 10 and number <= 20` 的写法，IDE 给出的那一行注释掉即可。

### 案例二：只把连接词换成 or

需求：键盘上输入一个整数，判断这个数字是否不在 10 到 20 之间。

一个数不在 10~20 之间，只有两种可能：要么小于 10，要么大于 20。这两个条件之间是"或者"的关系，满足其中一个就够，所以连接词是 `or`。

代码和案例一几乎一样，只需要改后面那个判断表达式：

```python
number = int(input("请输入一个整数："))
print(f"{number} 不在 10~20 之间：", number < 10 or number > 20)
```

```text
               10                        20
   ────────────┤─────────────────────────├────────────►
   number < 10                           number > 20
```

整条数轴被切成三段：左边一段是 `number < 10`，右边一段是 `number > 20`，中间夹着的 10 到 20 这一段两个条件都不成立。所以"不在区间内"只要落在左右任意一段就成立，正好对应 `or`。

`or` 连接的条件是或者的关系：只要其中有一个成立——也就是有一个表达式的结果是 `True`——结果就是 `True`；全部不成立，结果才是 `False`。

运行，输入 1：1 小于 10 成立，有一个条件成立，结果 `True`。这时顺手把输出文案里的"在"改成"不在"，否则结果对、话不对。

再输入 15：15 小于 10 不成立，15 大于 20 也不成立，两个都是 `False`。所有条件都不成立，结果 `False`。

再输入 56：56 小于 10 不成立，但 56 大于 20 成立，结果 `True`。

| 输入 | `number < 10` | `number > 20` | `or` 的结果 |
| :--- | :--- | :--- | :--- |
| 1 | `True` | `False` | `True` |
| 15 | `False` | `False` | `False` |
| 56 | `False` | `True` | `True` |

两个案例放在一起对比，正好是同一段区间从两个方向发问：`and` 问"是不是落在里面"，`or` 问"是不是落在外面"。

## 回到真实页面：登录框里的 and 与 or

逻辑运算符在实际开发里到处都是，拿 B 站的登录页面看就很清楚。

登录时要输入用户名和密码，也就是账号和密码。点下登录按钮，程序要去校验用户名的有效性和密码的有效性——校验用户名是否正确，以及密码是否正确。

什么时候才算登录成功？用户名和密码必须同时正确，这两者之间是并且的关系，用 `and`：用户名正确 `and` 密码正确。

同一个页面上还有另一种场景：可以扫左侧的二维码登录，也可以基于密码登录，还可以基于短信方式登录。这三种登录方式之间是什么关系？只要采用其中一种就能登录，所以是 `or` 的关系。

一个页面，两种连接词，区别就在于需求是"都得满足"还是"满足一个就行"。

> **结论**：`and` 连接的条件必须同时成立，结果才是 `True`；`or` 连接的条件只要有一个成立，结果就是 `True`；`not` 是取反。再加上一句更根本的——逻辑运算符是用来连接多个条件表达式的，它运算出来的结果仍然是布尔值。

到这里，Python 核心语法里"数据存储与运算"这一章就讲完了：算术运算符负责算，赋值运算符负责存，比较运算符负责比出一个布尔值，逻辑运算符负责把多个布尔条件合成一个结论。四类运算符凑齐，后面写业务逻辑才有材料可用。

## 本讲提到的题目

四个需求，问的都是"这段业务该用哪个比较运算符"。

1. 在数学计算中，判断一个数是否为偶数，要使用哪个比较运算符？
2. 在电商项目的支付功能业务中，需要判断银行卡的余额是否充足，要使用哪个运算符？
3. 在电商项目中购买商品，要判断商品的货物库存是否足够，要使用哪个运算符？
4. 在点餐项目中筛选商品，需要点不超过 100 元的菜品，要使用哪个关系运算符？

答案与解析：

| 题号 | 答案 | 解析 |
| :--- | :--- | :--- |
| 1 | `==` | 先对该数 `% 2` 取余，再判断余数是否等于 0，比较这一步用的是 `==` |
| 2 | `>=` | 余额充足，即余额大于等于商品金额 |
| 3 | `>=` | 库存足够，即库存数量大于等于购买数量 |
| 4 | `<=` | 不超过 100 元，即价格小于等于 100 |

第一题的关键在两步：取余是算术运算符 `%` 的活，判断余数是否为 0 才用到比较运算符 `==`；题目问的是后者。
