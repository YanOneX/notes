# 从一根加号出发：字符串格式化、键盘输入与算术运算符

## 加号拼接的三处不顺手

字符串拼接那个练习，敲得爽不爽？

多个字符串、多个变量拼成一句完整的话，加号当然能做到。可变量一多，别扭劲儿就上来了：字符串被切成一段一段，每两段之间杵一个加号，一行代码里加号的数量比内容还多。这种写法能跑，但离"优雅"还差得远。

具体说，加号拼接有三处不顺手。

第一处，繁琐。只要涉及两个部分的拼接，中间就得补一个加号；四个变量拼一句话，就是三个加号，改一个字都要重新数清楚引号从哪儿断、从哪儿接。

第二处，破坏字符串的完整性。这是更要命的一点。一句话在代码里被拆成 `"大家好，我是" + name + "，我今年" + age + "岁"` 这样的碎片，你盯着屏幕看到的是一堆引号和变量名，得自己在脑子里把引号和加号一个个剔掉，才能还原出"大家好，我是涛哥，我今年18岁"这一整句话。字符串本来是一个完整的表达，这么一拼，它的全貌就在代码里消失了。

第三处，还要做类型转换。加号在字符串这儿是有脾气的：它只肯把字符串和字符串接起来，字符串碰上数字，直接翻脸。所以 `age` 是整数的时候，得先用 `str()` 转成字符串才能拼进去，多写一层转换，就多一处出错的机会。

| 问题 | 具体表现 |
| :--- | :--- |
| 拼接繁琐 | 每两个部分之间都要补一个 `+`，变量越多，加号越多 |
| 破坏字符串完整性 | 引号、加号、变量名混在一起，代码里读不出一整句话 |
| 需要类型转换 | `+` 只接字符串与字符串，遇到整数得先转成字符串 |

三处都指向同一个症结：拼句子这件事，被加号抢了活。那有没有更优雅、效率更高的做法？

有，这就是字符串格式化。

## 百分号占位：先把位置留出来

字符串格式化本质上也是拼接，只是不再用加号去"连接"，而是先在字符串里把位置留出来，再把变量"填"进去。

留位置用的符号叫占位符，写法是 `%s`。这里的 `%` 表示"这个位置我要占住"，后面的 `s` 是 string 的简写，意思是填进来的东西按字符串处理。`%` 和 `s` 必须挨着写，中间不能空格。

### 一个 %s 换一个变量

只有一个变量的时候，语法短得像一句话：

```python
name = "涛哥"

print("大家好，我是%s，欢迎大家进入到Python课程的学习" % name)
```

写法上有两个位置要盯住：字符串里，占位符 `%s` 写在原本要出现姓名的地方；字符串的后面，用一个 `%` 引出要填进去的变量。

运行时，`name` 的值会被自动转成字符串，然后替换掉 `%s`——不是接在后面，是顶替掉那个位置。所以最后打印出来是完整的一句话：

```text
大家好，我是涛哥，欢迎大家进入到Python课程的学习
```

### 多个 %s 要按顺序对齐

一个变量好办，四个变量才是常态。规则很简单：有几个位置要填，就写几个 `%s`；`%` 后面就给几个数据，多个数据用括号括起来、逗号隔开。

```python
name = "涛哥"
age = 18
pro = "软件工程"
hobby = "Python、Java"

print("大家好，我是%s，我今年%s岁，我学习的专业是%s，爱好是%s" % (name, age, pro, hobby))
```

这段代码里数得出四个 `%s`，所以末尾的括号里必须是四项：`name`、`age`、`pro`、`hobby`。

顺序不是随便排的，这是最容易踩坑的地方：第一个变量填第一个占位符，第二个填第二个，一路对下去。

```text
"..."%s"..."%s"..."%s"..."%s"..."  %  (name, age, pro, hobby)
     ^      ^      ^      ^
     |      |      |      +--- 4th value: hobby
     |      |      +---------- 3rd value: pro
     |      +----------------- 2nd value: age
     +------------------------1st value: name
```

这张图读起来就一句话：箭头从左到右排开，把括号里的值逐个送进占位符，谁也不能插队。

还有一条硬规矩：前面有几个占位符，后面就得给几个数据，一个不能多，一个不能少。

跑起来的结果：

```text
大家好，我是涛哥，我今年18岁，我学习的专业是软件工程，爱好是Python、Java
```

注意 `age` 是整数 18，这里没写任何转换代码，`%s` 自己把它当字符串处理了。回头看加号拼接的第三处不顺手——类型转换——到这儿就一并解决了。

> **提示**：`%s` 里的 `s` 只说明"按字符串填"，并不要求传进来的东西必须是字符串。整数、小数传进去都会先转成字符串再填，所以年龄这类数字变量不必手动 `str()`。

## 字符串前面加个 f

第二种格式化的写法更短：在字符串前面加一个 `f`，然后用大括号 `{}` 占位。

`f` 是个标识，告诉 Python"这个字符串待会儿要格式化，里面的 `{}` 不是普通字符"。占位符里不再写 `%s` 这种格式符，而是直接把变量名写进去。

### 大括号里能写什么

先看一个变量：

```python
name = "涛哥"

print(f"大家好，我是{name}")
```

`{name}` 里的 `name` 必须和上面定义的变量名对上。运行时，Python 把 `name` 的值取出来，填进这对大括号的位置。

同一个案例改成 f 的写法，四个变量照样填：

```python
name = "涛哥"
age = 18
pro = "软件工程"
hobby = "Python、Java"

print(f"大家好，我是{name}，我今年{age}岁，我学习的专业是{pro}，爱好是{hobby}")
```

对比一下就能看出省在哪儿：百分号写法要在字符串末尾再补一个 `%` 和一对括号，把四个变量按顺序重新列一遍；f 的写法把变量名直接嵌进了占位符里，写完字符串，这句代码就结束了。

更关键的是，对位这件事顺带消失了。谁的名字写在哪个大括号里，谁的值就填在哪个位置，不存在"第一个变量必须填第一个占位符"这种约束。

大括号里除了变量名，还能写表达式。这个能力很实用——要输出的不是某个变量的值，而是两个变量算出来的结果时，直接把算式写进大括号就行，不必先在旁边算好、再单独存一个变量。

### 少了这个 f，占位符就变成普通文字

这是 f 写法唯一的坑，也是必须记牢的一条：前面那个 `f` 不能漏。

漏了会怎样？大括号失去了"占位符"的身份，退化成字符串里的普通字符。`{name}` 不再被替换，而是原样打印出来——屏幕上出现的就是 `大家好，我是{name}` 这几个字。

> **易错点**：`f` 是这套写法的开关。没有 `f`，`{}` 只是一对普通符号；有了 `f`，`{}` 才是占位符。写完先看一眼字符串引号前面有没有那个 `f`。

两种写法摆在一起比一比：

| | 百分号占位 | 前面加 f、大括号占位 |
| :--- | :--- | :--- |
| 占位符写法 | `%s`，`%` 与 `s` 必须紧挨 | `{}` |
| 变量写在哪儿 | 字符串末尾 `%` 之后，按顺序排列 | 直接写进大括号里 |
| 顺序要求 | 严格按占位符先后对位 | 写谁的名字就填谁的值 |
| 变量多时的观感 | 末尾一长串括号，来回对位 | 变量嵌在句子里，一眼看清 |

第二种更简洁，也是现在企业开发里的推荐方式。后面写代码，我会尽量都用它。

## 数据全写死在代码里，练着不灵活

前面写的代码里，姓名、年龄、专业、爱好，这些数据全是在代码里写死的。写死的意思是：想换个人名，得改代码；想多试几组数据，就得改一次、跑一次。

练习的时候这就很难受了。判断一段代码写得对不对，本来应该换几组数据反复试，可数据在代码里焊死了，试一次改一次，一点都不灵活。

那能不能反过来——让程序在运行时直接从键盘上拿数据？我在键盘上敲一个 9，程序就把这个 9 接住，赋给我指定的变量。能这样的话，同一份代码就能应对任意输入，程序立刻灵活起来。

答案当然是可以的。

输入和输出是一对：输入是"从键盘把数据拿进程序"，输出是"把程序里的数据送到控制台"。输出我们早就在用了，`print()` 干的就是这个活；这一节的重点在输入。

Python 把输入做成了一个内置的语句，叫 `input`，用起来就是一句：

```python
s = input("提示信息")
```

拆开看三件事：

- 括号里的提示信息，会在代码执行到这一行时打印到控制台，告诉用户该输入什么；
- 打印完，程序就停在这一行等键盘，光标在提示信息后面闪，不会往下走；
- 你敲完内容按下回车，敲进去的内容会被赋值给等号左边的变量——上面这行就是赋给 `s`，之后在代码里用 `s` 就能拿到刚才输入的东西。

`input` 是 Python 自带的内置功能，不用自己实现。它本质上也是一个函数——函数这个概念后面会专门讲，包括怎么自己定义函数；现在只要会用它的调用格式就够了。`print` 同理，一个负责把数据拿进来，一个负责把数据送出去。

## input 取回来的一律是字符串

### 一句 input 卡住整个程序

拿姓名和年龄试一下：

```python
name = input("请输入您的姓名：")
age = input("请输入您的年龄：")

print(f"您的姓名是{name}，年龄为{age}")
```

执行的过程是这样的：

```text
[执行 input("请输入您的姓名：")]
        |
        v
[控制台打印提示，光标在提示后面闪，程序停在这一行等键盘]
        |
        v
[键入 涛哥，按回车]
        |
        v
[字符串 "涛哥" 赋给变量 name，第一行才算执行完]
        |
        v
[执行下一行 input("请输入您的年龄：")，再停一次等输入]
        |
        v
[键入 18，按回车，"18" 赋给变量 age]
        |
        v
[执行 print，输出：您的姓名是涛哥，年龄为18]
```

这张图要盯的是两个"停"：每遇到一个 `input`，程序都不会自己往下走，必须等你按下回车。所以两个 `input` 是两步，不是一步——姓名输完回车，才轮到问年龄。

运行效果：

```text
请输入您的姓名：涛哥
请输入您的年龄：18
您的姓名是涛哥，年龄为18
```

前两行是你敲进去的，第三行才是程序打印出来的。这也是为什么提示信息末尾习惯加一个冒号：光标紧跟在冒号后面，输入的位置一目了然。

### 输入 18 拿到的也是 "18"

这里有一条必须钉死的规矩：**键盘录入的数据，取回来永远都是字符串**。

你在提示后面敲 18，`age` 里存的不是整数 18，是字符串 `"18"`。敲 `3.14`，拿到的是字符串 `"3.14"`；敲一个字母，拿到的还是字符串。`input` 不猜你想要什么类型，它只负责把键盘上的字符原样搬进程序。

> **易错点**：`"18"` 和 `18` 在 Python 里是两种东西。前者是字符串，后者是整数；前者不能参与算术运算，后者可以。凡是用 `input` 拿到的数据，只要后面要算，就得先转换类型。

这条规矩现在看着只是一句提醒，等下一节做案例，它就是那道必须迈过去的坎。

## 案例：模拟 ATM 机取款

把输入用起来，做一个像样的案例：模拟银行卡在 ATM 机上取款。

需求是这样的：小智的银行卡里有 1 万块钱，现在到 ATM 机取钱，程序要根据输入的金额完成取款，取完之后把卡上的余额展示出来。

到银行取钱的流程你们都熟：卡插进去，先输密码，再输取款金额，机器吐钱、显示余额。插卡这个动作程序模拟不了，那就从输密码开始。

所以分三步：第一步，输入密码；第二步，输入取款金额；第三步，计算余额并输出。

### 把需求拆成三步

余额怎么算？卡上原有的总金额，减去这一次取走的金额。所以先得有一个变量记住总金额。

```python
# 案例：模拟银行卡 ATM 取款
total = 10000  # 总金额

# 第一步：输入密码
password = input("请输入您的银行卡密码：")
print(f"密码正确，密码是{password}")

# 第二步：输入取款金额
number = input("请输入您的取款金额：")

# 第三步：计算余额并输出
print(f"取款后银行卡的余额为{total - number}元")
```

第一步里那句 `print` 值得说一句：真实 ATM 会校验密码对不对，这里不校验，因为校验要靠逻辑判断，还没学到。所以密码输进来之后，直接原样打印一句"密码正确"，把流程走通就行。

第二步和第一步写法一样，只是变量换成 `number`，提示信息换成取款金额。

第三步是重点：余额等于 `total - number`，这个算式直接写进 f 的大括号里。大括号能吃表达式，这里正好用上——不用先算好存进一个变量，直接算、直接打印。

### 字符串减不了整数

代码敲完，编辑器会在 `total - number` 这处标黄。鼠标往上一悬浮，提示很清楚：这里要的是 `int` 类型，实际拿到的却是 `string` 类型。

病根就是上一节那条规矩：`number` 是 `input` 拿回来的，它是字符串 `"1000"`，不是整数 1000；而 `total` 是整数 10000。一个整数减一个字符串，减法在字符串上根本没有定义，程序跑不下去。

`number` 现在缺的是一次类型转换——把字符串变成整数。Python 内置的 `int()` 干的就是这个活：

```python
print(f"取款后银行卡的余额为{total - int(number)}元")
```

`int(number)` 的意思是：把 `number` 这个字符串按整数解析出来。`"1000"` 进去，`1000` 出来。两个整数相减，减法这才成立。

运行一遍，密码敲 `666888`，取款金额敲 `1000`：

```text
请输入您的银行卡密码：666888
密码正确，密码是666888
请输入您的取款金额：1000
取款后银行卡的余额为9000元
```

1 万减 1000 等于 9000，算对了。这个案例从头到尾只用了三样东西：`input` 拿数据、`int` 转类型、f 字符串拼输出。

> **提示**：`int()` 只认整数写法。`int("1000")` 没问题，`int("10.5")` 会直接报错，因为 `10.5` 不是合法的整数字面量。要处理小数，得换 `float()`。

## 四个转换工具，一道求和练习

类型转换这块，Python 内置了四个工具，前两个刚刚已经用上了：

| 工具 | 作用 | 用在了哪儿 |
| :--- | :--- | :--- |
| `int()` | 把数据转成整数类型 | ATM 案例里把字符串金额转成整数 |
| `float()` | 把数据转成浮点数（小数）类型 | 输入两个数的案例里会用到 |
| `str()` | 把数据转成字符串类型 | 加号拼接时把数字转成字符串 |
| `bool()` | 把数据转成布尔类型 | 目前还没用到，先知道有这么一个工具 |

`int` 管整数，`float` 管小数，`str` 管字符串。方向也能反过来用：数字要拼进字符串、又不想用格式化，就 `str()` 一下。

顺手留一道练习：根据用户输入的两个数字，计算两数之和，输出到控制台。

需求跟 ATM 案例很像，思路可以照搬：两次 `input` 拿数据，转成数字，相加，打印。自己先写，写完再和讲义里的参考答案对照——这道题的参考答案已经放在讲义里了。

## 数据存好了，接下来是算

字面量、变量、常见数据类型学完，我们已经知道数据在 Python 里怎么写、怎么存。可数据存起来不是目的，存完了要拿它做运算。

数据要运算，就离不开运算符。

运算符这东西一点都不陌生，小学课本里就学过：加减乘除是最常见的一批；再往后有大于、小于、大于等于、小于等于、等于、不等于；还有处理逻辑关系的"并且""或者"。数一数，种类不少。

种类多，就得归类，一类一类地学。按作用分，Python 的运算符一共四类：

| 类别 | 管什么 | 典型成员 |
| :--- | :--- | :--- |
| 算术运算符 | 数学运算 | 加、减、乘、除、整除、取余、幂指数 |
| 赋值运算符 | 给变量赋值 | 等号 `=`，定义变量时用的就是它 |
| 比较运算符 | 比较两个数 | 大于、小于、大于等于、小于等于、等于、不等于 |
| 逻辑运算符 | 逻辑处理 | 并且、或者 |

先看第一类：算术运算符。要弄清两件事——Python 里有哪些算术运算符，以及每一个的写法、执行之后是什么效果。

## 算术运算符：七个符号

算术运算符是数学运算的基本符号，作用在一个或多个数字上，产生一个结果。

先看全貌，拿 10 和 4 试：

| 运算符 | 名称 | 写法 | 结果 |
| :---: | :--- | :--- | :--- |
| `+` | 加 | `10 + 4` | `14` |
| `-` | 减 | `10 - 4` | `6` |
| `*` | 乘 | `10 * 4` | `40` |
| `/` | 除 | `10 / 4` | `2.5` |
| `//` | 整除 | `10 // 4` | `2` |
| `%` | 取余（求模） | `10 % 4` | `2` |
| `**` | 幂指数 | `10 ** 4` | `10000` |

### 加减不变，乘除换了模样

加号和减号跟小学课本上写的一模一样，`10 + 4` 是 14，`10 - 4` 是 6，没什么需要适应的。

乘法和除法则要改改习惯，这两个符号在程序里跟课本上长得不一样：

- 乘法用星号 `*`。`3 × 8` 在代码里写作 `3 * 8`，中间那个星号就是乘号。
- 除法用斜杠 `/`。`10 ÷ 5` 在代码里写作 `10 / 5`。

除法还有一个特点必须记住：**结果一定是浮点数**。`10 / 5` 的结果不是 5，是 `2.0`；`10 / 4` 的结果是 `2.5`。哪怕除得尽、哪怕两个操作数都是整数，商也带小数点。

> **易错点**：`10 / 5` 得 `2.0` 而不是 `2`。除法不负责取整，它只把商算出来，而商的类型固定是浮点数。

### 整除与取余：一个留整数，一个留余数

要整数商，得换一个符号：两个斜杠 `//`，读作整除。

整除的规则一句话说完：只保留整数部分，结果一定是整数。比如 `10 // 3`，10 除以 3 除不尽，是 3.333…，整除取前面的整数部分，结果就是 3。那 `10 // 4` 是多少？先别急着往下看，自己算一下——答案是 2。

另一个是百分号 `%`，叫取余，也叫求模。它取的是除法之后的余数。

`10 % 3`：10 除以 3 商 3 余 1，结果就是 1。`10 % 4`：商 2 余 2，结果就是 2。

整除和取余是一对好搭档：一个扔掉余数、留下整数商，一个扔掉商、留下余数。

### 幂指数：两个星号

一个星号是乘法，两个星号 `**` 就是幂指数，求一个数的多少次方。

`10 ** 3` 是 10 的三次方，1000。`10 ** 2` 是 10 的二次方，100。`4 ** 2` 是 4 的二次方，也就是 4 的平方，16。

10 的连乘尤其好记：二次方 100，三次方 1000，四次方 10000——指数是几，后面就跟几个 0。

七行代码跑一遍，把这些结果一次看全：

```python
print(10 + 4)
print(10 - 4)
print(10 * 4)
print(10 / 4)
print(10 // 4)
print(10 % 4)
print(10 ** 4)
```

```text
14
6
40
2.5
2
2
10000
```

对着输出逐行看：加得 14，减得 6，乘得 40，除得 2.5（小数点要留意），整除得 2，取余得 2，幂指数得 10000。前四种跟心算对得上，后三种靠的正是新学的三个符号。`10 // 4` 和 `10 % 4` 都得 2，纯属巧合，别把这两个符号记混——一个给商，一个给余数。

### 这些符号在键盘的哪儿

这批符号里有一半不在明面上，得配合 Shift 才打得出来，所以单独说一下位置。

加号在等号键的上方，按住 Shift 再按等号键。减号是一个独立的键，直接按。星号在数字 8 那个键上，同样要按住 Shift。斜杠在问号键的下面，直接按就是除号。双斜杠没有专门的键，连按两下斜杠；两个星号也一样，连按两下星号。百分号在数字键那一排的符号区，配合 Shift 打出来。

这条不用背，敲几十遍自然就熟了。真正容易混的是两个斜杠和两个星号：单斜杠是除，双斜杠是整除；单星号是乘，双星号是幂。

## 优先级：先幂，再乘除整除，最后加减

一个式子里同时出现好几个运算符，先算谁？

拿这个式子做实验：

```python
print(0.1 + 10 / 4 ** 2)
```

里面有加法、除法、幂指数三种运算。优先级从高到低排下来是：

| 优先级 | 运算符 |
| :---: | :--- |
| 最高 | `**` 幂指数 |
| 次之 | `*` `/` `//` `%` 乘、除、整除、取余 |
| 最低 | `+` `-` 加、减 |

按这个顺序拆，式子分三步落地：

$$4^2 = 16$$

$$10 \div 16 = 0.625$$

$$0.1 + 0.625 = 0.725$$

所以打印出来是 `0.725`。

想改顺序，跟数学里一样加括号，括号的优先级最高。比如想让 `0.1 + 10` 先算，就把它们括起来——括号里的部分永远先执行。

## 案例：输入两个数，求和与求差

需求：从键盘录入两个数，分别是 x 和 y，然后输出 x 加 y 的结果，以及 x 减 y 的结果。

这题看着简单：两次输入，两个算式，两行输出。可它会把前面几节埋的坑一路踩过来，正好检验前面的东西有没有真吃透。

### 第一版：直接相加，得到 105

第一版按最直白的思路写：

```python
x = input("请输入X的值：")
y = input("请输入Y的值：")

print(f"X + Y 的结果为{x + y}")
print(f"X - Y 的结果为{x - y}")
```

输入 10 和 5 跑一遍，第一行输出 `X + Y 的结果为105`，第二行直接报错。

105 这个数字，是这道题最值得看的地方。10 加 5 怎么会是 105？因为 `x` 和 `y` 都是 `input` 拿回来的字符串，`"10" + "5"` 在 Python 里不是相加，是拼接——两个字符串首尾一接，得到 `"105"`。加号对字符串的含义是连接，不是求和。

第二行报错也在情理之中：减号在字符串上没有定义，`"10" - "5"` 无从下手，Python 只能抛出一个类型错误，告诉你这两个操作数做不了减法。

两个现象，一个病根：数据还是字符串，没转成数字。

### 第二版：int 挡住了小数

补上转换，把 `int()` 直接套在 `input` 外面——`input` 拿回字符串，`int` 当场把它转成整数，一行代码干完两件事：

```python
x = int(input("请输入X的值："))
y = int(input("请输入Y的值："))

print(f"X + Y 的结果为{x + y}")
print(f"X - Y 的结果为{x - y}")
```

再输 10 和 5：

```text
请输入X的值：10
请输入Y的值：5
X + Y 的结果为15
X - Y 的结果为5
```

这次对了，15 和 5 都是算出来的，不是拼出来的。

可换个输入就露馅：输 `0.5`，程序立刻报错。`int` 只认整数写法，`"0.5"` 不符合整数的样子，解析失败。而题目要的是"两个数"，并没说必须是整数——小数也应该能进。

那就统一按小数处理。

### 第三版：float 之后冒出的长尾巴

把 `int` 换成 `float`，输入的内容一律转成浮点数：

```python
x = float(input("请输入X的值："))
y = float(input("请输入Y的值："))

print(f"X + Y 的结果为{x + y}")
print(f"X - Y 的结果为{x - y}")
```

先输整数 10 和 5，能跑，只是结果带上了小数点——10 变成 `10.0`，5 变成 `5.0`，和是 `15.0`，差是 `5.0`。数值上没错，形式上变成了小数；这是 `float` 的代价，也是它换来通用性的原因。

再输 0.5 和 0.4：

```text
请输入X的值：0.5
请输入Y的值：0.4
X + Y 的结果为0.9
X - Y 的结果为0.09999999999999998
```

和是 0.9，没问题。差本该是 0.1，屏幕上却成了 `0.09999999999999998`。

这是算错了吗？

## 那条长尾巴从哪来

不是算错，是精度损失。

计算机底层靠二进制存储和处理数据，而二进制没法准确表示所有的小数。有些小数写进内存的那一刻就已经不是精确值了，只剩下一个非常接近的近似值。0.4 就是这样一个数：存进去的时候，末尾已经被截掉了一点点。

两个这样的近似值相减，误差就露到了明面上——`0.5 - 0.4` 得到的不是整齐的 0.1，而是 `0.09999999999999998`。差的这一点点，就是被丢掉的精度。

> **结论**：凡是涉及浮点数的运算，都可能出现精度损失。原因在计算机的二进制存储方式，不在 Python。这在计算机做算术运算时属于正常情况，不是异常。

以后遇到 `0.1 + 0.2` 不等于 `0.3` 这种事，不必怀疑代码写错了，它就是这么工作的。这一节先把现象记牢，把三个版本的求和求差各敲一遍，再去做课末那几道案例练习。

### 求两个数之和

题干：根据用户输入的两个数字，计算两个数之和，并把结果输出到控制台。

解析：

- 两个数字都要从键盘来，所以用两次 `input()`，分别赋给两个变量；
- `input()` 拿到手的一律是字符串，直接相加会变成拼接，必须先转成数字；
- 题目只说"两个数字"，没限定整数，用 `float()` 更稳妥，整数也能照收；若确定只输整数，用 `int()` 也行；
- 算完把结果打印出来，用 f 字符串把算式结果嵌进一句话最省事。

答案：用两次 `input` 分别读入两个数，各自套一层 `float()` 转成浮点数，再把两者相加的结果通过 `print` 输出。写法与正文"输入两个数，求和与求差"的第三版同源，只是输出从两行减成一行。讲义里另附了这道题的参考答案，写完可以对照一下。
