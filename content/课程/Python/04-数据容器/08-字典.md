# 字典

* **字典（dict）**

* > **定义**：以键值对形式存储数据的数据容器，一个键对应一个值，中间用冒号分隔，多个键值对之间用逗号分隔。

* `dict` 取自 dictionary；同样是键值对结构，有的语言叫映射 map，有的叫哈希 hash。

* 一项数据指的是一个键值对，所以存四组键值对的字典是四项数据，不是八项。

* 空字典写 `{}` 或 `dict()`；`type` 结果为 `<class 'dict'>`。

* 取值只能通过键：`dict1['李慕婉']`；字典没有索引下标，方括号里放的必须是键，不是序号。

* **键的约束**

* 值可以是任意类型，字符串、布尔、整数、浮点都行，而且随时能改。

* 键必须是不可变类型：字符串、整数、浮点、元组可以当键；列表、集合、字典是可变类型，不能当键。

* 用列表当键直接报错：`TypeError: unhashable type: 'list'`。

* 理由是键必须从头到尾钉死在一个值上：编号自己会变，书和号就对不上了。

* 键重复不报错，后写的值覆盖先写的值，一个键在字典里永远只有一份；值莫名其妙不对时，先回头查是不是同一个键写了两次。

* > **易错点**：字典没有 `add` 方法。添加和修改是同一行代码，只看 key 在不在：不存在就新增，存在就覆盖。

* **增删改查**

* 增与改同一行：`dict1["涛哥"] = 550`；key 不存在是新增，已存在是修改。

* 删除有两条路：`pop(key)` 删掉整对键值对并把 value 返回；`del dict1[key]` 只删不返回。

* 查单个值两种写法等价：`dict1[key]` 与 `dict1.get(key)`。

| 写法 | 拿到什么 | 返回类型 |
| :--- | :--- | :--- |
| `dict1[key]` / `dict1.get(key)` | 这个 key 对应的一个 value | 值本身的类型 |
| `dict1.keys()` | 字典里所有的 key | `dict_keys` |
| `dict1.values()` | 字典里所有的 value | `dict_values` |
| `dict1.items()` | 字典里所有的键值对 | `dict_items` |

* 三个批量方法返回的不是列表，而是字典独有的三种类型，但内容照样能遍历。

* **遍历**

* 走 `keys`：`for key in dict1.keys(): print(f"{key}: {dict1[key]}")`，先拿键再回头取值。

* 走 `items` 加下标：`for item in dict1.items(): print(f"{item[0]}: {item[1]}")`，每一项本身是元组。

* 走 `items` 加解包：`for key, value in dict1.items(): print(f"{key}: {value}")`，两个变量按位置接住键和值。

* > **提示**：这三种写法能成立，靠的是 for 循环、元组、解包几样东西的组合；同一需求往往有多种写法都通。

* **嵌套结构设计**

* 一个字典装一件商品（`name`、`price`、`number`）不够用：`name` 是 key，同一个字典里 key 只能出现一次，塞不进第二件商品。

* 列表套字典能装多件，但商品名称落在 value 里，而字典的增删改查全围着 key 转，靠名称找商品只能遍历整个列表逐个比对。

* 正确结构是外层字典、key 直接就是商品名，value 是装着 `price` 和 `number` 的小字典：

```text
shopping_cart
├── "mate80" → {"price": 6999, "number": 2}
└── "鼠标"    → {"price": ...,  "number": ...}
```

* > **结论**：谁被频繁拿来定位，谁就该当 key。商品名称坐在 key 的位置上，改和删都变成一行索引的事。

* 存的写法：`shopping_cart[goods_name] = {"price": goods_price, "number": goods_number}`；取的时候按同样的 `price`、`number` 去拿，名字差一个字母就是 `KeyError`。

* **菜单驱动**

* 骨架就三件事：打印菜单、读入编号、按编号分支，整段塞进 `while True`，出口只留一个 `break`。

* 菜单是多行字符串，用三引号定义后 `print`；欢迎语和菜单留在循环外，`input` 与分支必须进循环。

* 等值分支用 `match`：`match choice:` 配 `case "1":`，一行一个分支，不必重复写 `choice ==`。

* `input` 拿回来的永远是字符串，`case` 后面必须比 `"1"` 这样的字符串，写数字 `1` 一条也匹配不上。

* `case _:` 管 1~5 之外的所有输入，下划线是通配符，不能加引号；写成 `case "_":` 就变成匹配内容为一个下划线的字符串。

* 添加前用 `if goods_name in shopping_cart` 查重，`in` 在字典上判断的是 key 在不在；修改和删除用 `not in` 把住门，逻辑正好相反。

* 校验要提到收数据之前：名称一输完就判断存在性，不存在就提示并用 `continue` 中断本轮，价格数量一个都不用问。

* > **易错点**：`continue` 是"这一轮不干了，下一轮继续"，`break` 是"整个循环到此为止"；校验不过要的是前者。

* 判断前移之后，"能走到这儿的商品一定存在"，原来那个 `else` 就多余了，可以删掉直接改。

* 容器里的数据随进程生灭：程序一停，内存里那份数据就没了，重新运行是从空白开始；要留下来得写到文件里。
