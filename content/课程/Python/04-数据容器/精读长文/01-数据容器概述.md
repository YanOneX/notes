# 数据容器与列表：把一堆数据装进一个变量

## 一个变量只装一项，装多了怎么办

Python 核心语法的前两块已经走完了：一块是数据的存储与运算，讲数据怎么存、怎么算；一块是数据的逻辑处理，也就是流程控制语句，讲代码怎么按条件走、怎么循环。接下来进入第三块，数据的存储容器。

先把"容器"这两个字拆开。容器就是用来存东西的，数据容器顾名思义，就是用来存数据的。听到这儿很容易冒出一个疑问：前面讲数据的存储与运算时，我们已经能用变量存数据了，为什么还要再引入一种专门存数据的东西？

原因很朴素：一个普通的变量只能存一项数据。要存多项，就得定义多个变量；要存大量数据，就得定义大量变量。这件事既繁琐，又臃肿，写出来一大片赋值语句，看着就难受。

数据容器就是来解决这个问题的。定义一个变量，让这个变量的类型本身是一种容器，然后把大量数据塞进这个容器里。同样是存一批数据，用容器来存要简洁得多，也优雅得多。

> **定义**：数据容器是一种可以容纳多份数据的数据类型。它首先是一种数据类型；因为能容纳多份数据，所以被称为容器。容器里的每一份数据，都称为一个元素。

元素可以是任意类型。放在同一个容器里的这些元素，可以是字符串、可以是数字、也可以是布尔值，没有类型上的限制。

## 五种容器，按三个问题分家

Python 里的数据容器不止一种，常见的就有五类。它们凭什么分成五类？看三个问题：支不支持重复元素、能不能修改、有没有序。按这三条一划，五种容器就站成了五队。

| 中文名 | 类型名 |
| :--- | :--- |
| 列表 | list |
| 字符串 | string |
| 元组 | tuple |
| 集合 | set |
| 字典 | dict |

其中字符串要单独点一句：它就是前面已经讲过的那种字符串。别以为它只是"一段文本"，它其实也是一种数据容器，后面讲切片的时候就会看到它和列表共享同一套玩法。

这五种容器会一种一种地讲过去，五种都讲完，再一起做一个数据容器的综合案例，把几种容器放到同一个场景里用一遍。

## 列表：方括号里排开的一串元素

列表是数据容器里的第一种，也是这一块最先展开的一种。它要解决的问题很直接：一次性存储多个数据，里面每一项数据都是它的一个元素。

### 定义就是一句赋值

它的定义语法，本质上就是一次变量赋值，只是右边的值换了个长相：

```text
列表名称 = [元素一, 元素二, 元素三, ...]
```

左边是列表名称，其实就是一个变量名；右边为这个变量赋值，赋的是一对方括号括起来的东西。两侧必须是方括号，方括号里罗列要存的数据，元素与元素之间用逗号分隔。

```python
s = [54, 45, 75, 108, 23, 78, 75]
```

这个列表名叫 `s`，里面存了七个元素：54、45、75、108、23、78、75，每两个元素之间逗号隔开。注意最后那个 75——它和第三个元素 75 是重复的，列表允许这种重复存在。

### 两条特点，一条比一条实用

列表的特点，归纳起来大的方面就两条。

第一条，它可以存储不同类型的元素。上面这个例子存的都是 `int`，但那只是例子。一个列表里可以放整数、可以放浮点数、可以放字符串、可以放布尔值，语法层面没有任何限制。不过在实际项目里，列表里基本存的都是同一类型的数据——语法允许混着放，工程上通常不混着放，这两件事要分开看。

第二条，列表里的元素是有序的、可以重复的、可以修改的。

有序是指：定义时是什么顺序，存储就是什么顺序，最终操作元素时也可以按指定的顺序来操作。可以重复是指：列表里允许出现相同值的元素，那两个 75 就摆在那儿，完全合法。可以修改是指：可以指定要改列表里的哪一个元素，把 108 改成 208，直接改就行。

问题也就在这里冒出来了：一个列表里这么多元素，我怎么知道我要操作的是哪一个？改的时候改谁？取的时候取谁？

## 索引：正向从零，反向从负一

列表会给每一个元素都配一个索引，也叫下标。有了它，操作哪个元素就是一串数字的事。

正向索引从零开始：头部第一个元素下标是 0，第二个是 1，第三个是 2，依次类推。想取第一个元素就写 `s[0]`，第二个写 `s[1]`，第三个写 `s[2]`。

Python 还额外给了另一种编号方式，叫反向索引，从列表的末尾开始数：最后一个元素是 -1，倒数第二个是 -2，倒数第三个是 -3。

把上面那个七元素列表摊开，两种编号是这样对齐的：

```text
元素      54    45    75   108    23    78    75
正向索引   0     1     2     3     4     5     6
反向索引  -7    -6    -5    -4    -3    -2    -1
```

三行逐列对齐，一列就是同一个元素，从左往右都是"下一个"，只是一个从 0 递增，一个从 -1 递减。

所以取同一个元素，两种写法都行：取第一个元素，正向写 `s[0]`，反向写 `s[-7]`；取最后一个元素，正向写 `s[6]`，反向写 `s[-1]`。只要索引是负数，就代表这是反向索引。

> **易错点**：正向索引从 0 起，反向索引从 -1 起。这两个起点记反了，取出来的就是隔壁的元素，而且不会报错，属于最难查的那类错。

Python 把这种"元素有序、并且可以通过索引访问元素"的容器，统一称为序列类型。列表就是典型的序列：它里面元素有顺序，元素又能按索引访问。后面讲到切片时会发现，"序列"这个身份比"列表"这个身份管用得多。

## 在代码里把列表跑一遍

语法看一遍不算会，得到编辑器里敲一遍。下面这一串演示，覆盖列表的定义、查看类型、取值、改值、删值，还有那个一定会踩到的越界。

### 定义与类型

先在编辑器里直接写一个字面量：

```python
[56, 90, 88, 65, 90, "A", "hello", True]
```

前面四个是整数，接着一个重复的 90，然后是字符串 `"A"`、字符串 `"hello"`、布尔值 `True`。八项数据混着四种类型，写下去不报错——列表确实允许存储不同的数据类型。

但编辑器会在这行左边给个黄色背景，鼠标悬浮上去提示：这个语句似乎不起任何作用。为什么不起作用？因为列表定义在这儿，没有任何变量接收它，既没有名字也没有下文，等于白写。想操作这个列表，就得用变量接住它：

```python
s = [56, 90, 88, 65, 90, "A", "hello", True]
print(type(s))
```

`type()` 用来查看变量当前是什么类型。运行结果：

```text
<class 'list'>
```

列表的数据类型就是 `list`。

### 取值：两种索引各来一遍

取列表里的元素，直接拿索引去撞。取第一个元素有两种写法：

```python
print(s[0])     # 56
print(s[-8])    # 56
```

`s[0]` 也好 `s[-8]` 也好，两行打印出来的都是列表头部的那个 56。反向索引 `-8` 是数出来的：这个列表一共八项，最后一个（`True`）是 -1，往前一项一项倒推，第一个自然就是 -8。

再取第三个元素，也就是 88：

```python
print(s[2])     # 88
print(s[-6])    # 88
```

正向索引 2 对应第三个元素（因为从 0 开始数），反向索引 -6 从尾部数过来正好落到同一个位置。

### 改值：找到位置，重新赋值

列表的元素可以被修改，改法就是"按索引定位，再赋值"。现在想把字符串 `"A"` 改成 `"ABC"`：

```python
s[5] = "ABC"
print(s)
```

为什么是 5？因为 `"A"` 前面还有五个元素（56、90、88、65、90），它是第六个，而索引从 0 开始，第六个元素的索引就是 5。

运行结果：

```text
[56, 90, 88, 65, 90, 'ABC', 'hello', True]
```

第六个位置的 `"A"` 已经变成 `"ABC"`，其余元素一个没动。这就是"为指定索引位置的元素赋一个新值"。

### 删值：del 关键字

删掉列表里指定的元素，用的不是方法而是一个关键字 `del`，后面直接跟要删的那个位置：

```python
del s[6]
print(s)
```

`"hello"` 前面有六个元素，它是第七个，索引为 6。删完再整体输出：

```text
[56, 90, 88, 65, 90, 'ABC', True]
```

`"hello"` 没了，列表短了一项，剩下的元素仍然保持原来的先后顺序。

> **提示**：`del` 是 delete 的简写，删除那个单词的缩写。它删的是"这个位置上现在站着的元素"，位置本身不会留空，后面的元素会整体前移。

### 越界：索引不能随便写

列表一共八项，索引最大是 7。那如果写个 10 呢？

```python
s[10] = "DEF"
```

运行之后直接报错，红色的一片，其中最关键的是一行：

```text
IndexError: list assignment index out of range
```

`list index out of range`，意思就是列表的索引超出范围了。索引 10 在这个列表里根本不存在，既没有这个元素可改，赋值也就无从谈起。

> **易错点**：指定的索引超出列表的范围会直接报错。写索引之前先数一遍元素个数，正向上限是"长度减一"，反向下限是"负的长度"。

### 用 for 循环验证它有序

"列表是有序的"这句话，光看定义不算证明。把元素一个个取出来打印，顺序对不对一眼就知道：

```python
for item in s:
    print(item)
```

`in` 后面跟的 `s` 就是要遍历的数据集，也就是这个列表；`item` 是一个变量名，叫什么都行，它代表每一轮遍历出来的那个元素。

运行结果：

```text
56
90
88
65
90
ABC
True
```

和当初存进去的顺序完全一致。存的时候什么次序，取出来还是什么次序——这就是"有序"的实际含义，也是列表能按索引取值的底层原因：位置是固定的，第几个就是第几个。

顺带说一句，`for` 循环本来就是用来遍历数据集的，列表正是最标准的一种数据集，两者是天生一对。

## 切片：从一串里截一段

索引一次只能取一个元素，可现实中经常要的是"前三个""后面五个"这样的一段。截取数据中的一部分，这个操作就叫切片。

比如一个七元素列表，要把前面三个元素截出来，这一个动作就是切片。

切片不是列表的专利。字符串、元组这些容器也都支持切片——原因还是那个身份：Python 里的序列类型都支持切片。序列类型指的是元素有序、并且可以通过索引访问容器内元素的那类容器。既然切片的本质是"按位置截一段"，只要元素有位置可用，就能切。

### 三个参数，两个冒号

切片的语法是在序列后面跟一对方括号，方括号里写三个参数，三个参数之间用两个冒号隔开：

```text
序列[start:end:step]
```

三个参数各管一段：

| 参数 | 名称 | 含义 | 不写时的默认值 |
| :--- | :--- | :--- | :--- |
| `start` | 开始索引 | 从哪个位置开始截 | 0，即从第一个元素开始 |
| `end` | 结束索引 | 截到哪个位置为止 | 列表长度，即截到末尾、包含最后一个元素 |
| `step` | 步长 | 每隔几个元素取一个 | 1，即挨个取 |

三条规矩，一条都不能含糊。

第一，截取时包含开始索引，但不包含结束索引对应的元素。开始写 0、结束写 2，含义是"从 0 号位置开始，截到索引为 2 的位置为止"，覆盖的是 0、1、2 这三个位置，但因为不含结束索引，最终切出来的是两个元素。

第二，这两个索引既可以用正向索引，也可以用反向索引，两种都支持，混着用也成立。

第三，步长是选取的间隔，默认值为 1，不写就是挨个取。

### 含头不含尾，边界要自己算

拿七元素列表试两个写法。

`s[0:5:1]`：从索引 0 开始，截到索引 5，步长 1 表示挨个取。因为不含结束索引，索引 5 那个元素不会被切进来，切出来的是前面五个元素。想切前五个却写了 5 而不是 4，正是"含头不含尾"这半句话的作用——结束索引写的是"切到哪儿为止（不含）"，不是"切几个"。

`s[0:5:2]`：起点和终点不变，步长变成 2，含义是每两个元素取一个。取走第一个，跳过第二个，取走第三个，跳过第四个，再取走第五个，最终得到三个元素。

> **提示**：`[0:5]` 和 `[0:5:2]` 的边界完全一样，区别只在于取的时候跳不跳。判断切出来几个元素，先按 `end - start` 数出区间长度，再按步长折算，最后回到"含头不含尾"检查一遍首尾。

## 切片实操：一步步把写法简化

编辑器里先备好一个十元素列表 `s`，然后一条条试。

要前面五个元素，从头部开始截，写法是：

```python
print(s[0:5:1])
```

结束索引为什么是 5？因为 0、1、2、3、4 这五个位置正好是要的五项，而索引 5 是第六个元素，含头不含尾正好把它挡在外面。步长写 1，说明不需要跳着取。

运行结果：

```text
['A', 'X', 'H', 'K', 'L']
```

再把切出来的东西扔进 `type()` 看一眼：

```python
print(type(s[0:5:1]))
```

```text
<class 'list'>
```

切片的返回值仍然是 `list`。切片的实质就是"从一个大的列表里截出一个小列表"，不是截出五个互不相干的变量。

### 简化到只剩一个冒号

`[0:5:1]` 这三个参数，每一个都有默认值，所以每一个都能省。

开始索引是从头开始的 0，0 是默认值，可以省：`s[:5:1]`。

步长是 1，1 也是默认值，可以省：`s[:5:]`。

步长既然省了，它前面那个冒号也就没有存在的必要了，一起省：`s[:5]`。

四种写法打印出来的结果完全一样。

### 第一个冒号不能省

既然第二个冒号能省，第一个冒号是不是也能省？不能。省掉它，含义就变了：

```python
print(s[5])
```

这不再是切片，而是取索引为 5 的那个元素，也就是第六个元素，输出 `B`。方括号里只有一个数字时，Python 理解为"按索引取值"；只有出现冒号，才理解为"切一段"。冒号是切片和索引之间唯一的分界线，第一个冒号一旦拿掉，整条语句的性质就变了。

### 步长决定跳几个

现在换个目标：截取 `A`、`H`、`L` 这三个元素。它们在原列表里并不相邻，中间都隔着一个，所以步长不能是 1，得是 2：

```python
print(s[0:5:2])
```

```text
['A', 'H', 'L']
```

起点仍是 0，终点仍是 5（因为要截到 `L` 为止、不含 `B`），只是每取一个就跳过一个。步长换成 3，中间就跳过两个元素，取出来的更稀疏。

再看边界写小一点的情况：

```python
print(s[0:2:1])
```

```text
['A', 'X']
```

结束索引 2 不含，所以只拿到索引 0 和 1 两项。

至于反向索引，位置从尾部数就行，`-1` 是最后一个元素。同一个位置，正向写法是几、反向写法是负几，两种写法混在同一条切片里也照样成立，切出来的区间不变。

## 那串黄色提示不用管

切片写完，编辑器可能在方括号那一段标黄，提示里扯到"类型别名"之类的字眼。这条提示和语法对错无关，纯粹是开发工具自己的静态检查在说话，代码照跑不误，结果也完全正确。

如果有代码洁癖，看着那抹黄色不舒服，可以把它关掉。编辑器右上角有个带数字的小警告图标（比如显示 7），点开是个下拉列表，默认选的是"所有问题"，所以什么提示都往外冒。把它改成"语法"，就只看语法层面的问题；改成"无"，则一条提示都不显示。

> **提示**：不建议直接选"无"。提示全关掉，语法错误也一起看不见了，等于把报警器拆了。最多收到"语法"这一档。

想调回来也简单，鼠标再悬浮到那个位置，重新选一次就行。
