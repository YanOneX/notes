# 从选课名单吃透集合，再认识键值对字典

集合的基本操作刚过完一遍，方法名是记住了，但真拿到一堆数据要动手时，未必想得起来该用哪一个。所以这里不再添新语法，就发一组真实的选课数据，用四个需求把交集、并集、差集、解包这些操作挨个用一遍。案例做通了，集合这一块才算真的拿下；再往后翻，就是数据容器里的最后一位——字典。

## 一组选课数据，四个需求

数据的形态很朴素：一个班的学生选课情况，拆成四份名单——选修足球的、选修篮球的、选修法语的、选修艺术的。四份名单各自都是一个 set 集合，分别装进 `football_set`、`basketball_set`、`french_set`、`art_set` 四个变量里。

这份基础数据在课程讲义的最后一栏「课程案例数据」里能直接复制，也可以自己随手编几个名字构造一份，不影响练习效果。

要完成的需求一共四条：

- 找出同时选修了法语和艺术的学生；
- 找出四门课程全都选修了的学生；
- 找出选修了足球、但没有选修篮球的学生；
- 统计每一个学生选修了多少门课程，并把结果输出出来。

前三条都是"从四份名单里挑人"，最后一条是"给每个人数数"。看着都是筛选，其实落到的集合运算并不相同，下面一条一条来。

## 同时选修了法语和艺术的学生

"同时选修了法语和艺术"，翻译成集合的语言，就是既在法语名单里、又在艺术名单里的那部分数据——交集。相关的两个集合是 `french_set` 和 `art_set`。

求交集，最直接的办法是调用集合自己的方法 `intersection`，把第二个集合当参数传进去：

```python
# 方式一：调用 intersection 方法求交集
f_a_set = french_set.intersection(art_set)
print(f"同时选修了法语和艺术的学生是：{f_a_set}")
```

`f_a_set` 这个名字没什么讲究，就是 french 和 art 两个单词的首字母拼一下，表示"法语和艺术的交集"。变量接住返回值之后再格式化输出，`print` 前面记得带上那个 `f`，否则花括号会被原样打印出来。

运行的结果是四个人：姜老道、韩立、天运子、虎袍。要验证也简单，在编辑器里双击其中某个名字，看它在法语名单和艺术名单里是不是同时被高亮——两个都亮，就说明这个人两份名单都在；其余没被选中的名字，一查就能看出只出现在其中一份里。

同一个需求还有第二种写法：不用方法，直接上运算符。

```python
# 方式二：用 & 运算符求交集
f_a_set2 = french_set & art_set
print(f"同时选修了法语和艺术的学生是：{f_a_set2}")
```

这个 `&` 就是键盘上数字 7 上面那个符号，有的字体把它显示得像一个尖角朝上的 `∧`，认符号位置比认字形可靠。在 Python 里它读作"与"，用在集合上就是求交集。两个变量之间夹一个 `&`，不用写括号、不用记方法名，输出结果和方式一一模一样。

> **提示**：`intersection` 与 `&` 是同一件事的两种写法，前者要传参、名字长；后者短，一眼能看出是"两个集合在做运算"。求交集的时候，第二种更简洁，也更好读。

## 四门课全选的学生

需求升级成"四门课程全都选修了"，就是四个集合的公共部分——四个集合的交集。

交集可以连着写。既然 `&` 是二元运算符，那就两个两个地串下去，`football_set & basketball_set & french_set & art_set`，中间结果本身仍然是集合，所以能一路接到底：

```python
# 四个集合连续求交集
all_set = football_set & basketball_set & french_set & art_set
print(f"同时选修了四门课程的学生是：{all_set}")
```

用 `intersection` 也完全可以，只不过它是要传参的方法，串四个集合就得写成链式调用，读起来没有运算符顺眼。

结果只剩两个人：天运子、韩立。同样的验证手法——双击名字，四个集合里全部高亮，说明四门课一门没落；其他学生要么只亮三处、要么只亮两处，自然就被交集筛掉了。

> **易错点**：交集越求越小，是把条件一层层收紧。四个人、两个人这样的结果看着少，恰恰说明筛选生效了，不要怀疑数据出了问题。

## 选修了足球、但没选篮球的学生

这一条的条件里带了个"但没"：在足球名单里存在，在篮球名单里不存在。这正是差集要解决的问题——`A - B` 取的是"在 A 里出现、在 B 里没出现"的那部分元素，方向由谁减谁决定。

### 调用 difference 方法

求差集的方法是 `difference`，谁在前面、谁当参数，语义就是"从前者里扣掉后者中出现的元素"：

```python
# 方式一：调用 difference 方法求差集
fb_set = football_set.difference(basketball_set)
print(f"选修了足球但没有选修篮球的学生是：{fb_set}")
```

这里足球在前、篮球在后，拿到的就是"足球名单里有、篮球名单里没有"的学生：紫菱、遁天、许立国、乌丑，四个人。挨个核对一遍就放心了——紫菱在足球名单的最后一位，篮球名单里翻不到；遁天、许立国、乌丑同样只在足球那边；反过来看李飞宇、天运子这些人，两份名单都有，说明他们既踢球也打球，自然被扣掉了。

### 用减号

差集也有运算符，就是减号：

```python
# 方式二：用减号运算符求差集
fb_set2 = football_set - basketball_set
print(f"选修了足球但没有选修篮球的学生是：{fb_set2}")
```

`football_set - basketball_set` 和上面那次方法调用的结果一字不差。

> **易错点**：减号是有方向的。`football_set - basketball_set` 问的是"踢球但不打球的人"，`basketball_set - football_set` 问的却是"打球但不踢球的人"，换一下顺序，答案就换了一批人。写的时候先在心里把这句话念一遍，再决定谁减谁。

### 用集合推导式

同一个需求还有第三种写法，叫集合推导式。这名字听着耳熟，因为讲列表的时候见过列表推导式——两者本来就是一套东西，作用都是"按规则快速构建一个新容器"。

语法先摆出来：外层一对大括号（因为要造的是集合），里面先写 `for 变量 in 容器`，再在前面写"要往新集合里放什么"，末尾还可以补一个 `if 条件`，条件成立才把这个元素收进去。

拿这个需求套进去，思路是：从足球名单里一个一个取出学生，凡是"不在篮球名单里"的，收进新集合。

```python
# 方式三：用集合推导式
fb_set3 = {s for s in football_set if s not in basketball_set}
print(f"选修了足球但没有选修篮球的学生是：{fb_set3}")
```

拆开看这三段：

- `for s in football_set`：`s` 是从足球名单里遍历出来的学生名，所以它一定在足球集合里，这一半条件不用再判断；
- `if s not in basketball_set`：`in` 是判断元素在不在容器里的操作符，讲列表时用过，集合上照样能用。`s in basketball_set` 表示"这人篮球也选了"，我们要的是反面，所以在前面加 `not`；
- 最前面的 `s`：条件通过之后，真正被放进新集合的元素就是这个学生名。

三种写法跑出来的结果完全一致。真要说哪种最省事，还是第二种——一个减号，语义直白，不用记方法名，也不用写循环。集合推导式的价值不在这一条需求上，而在于它把"筛选 + 构建"压缩成了一行，条件再复杂也不怕。

> **提示**：集合推导式和列表推导式的语法结构完全一样，唯一的区别是最外层那对括号——`[]` 造列表，`{}` 造集合。记住这一点，两种推导式就只需要记一套。

## 统计每个学生选修了几门课程

这条需求性质变了：前面三条都是"筛出某些人"，这一条要给名单上的每个人配一个数字。它得拆成两步走。

第一步，得先有一份完整的学生名单——谁在这个班里上过课，一个都不能漏。四份名单各自只覆盖一部分人，所以要把它们合起来，也就是求并集：

```python
# 第一步：四份名单求并集，拿到去重后的全班名单
all_set = football_set.union(basketball_set).union(french_set).union(art_set)
print(all_set)
```

求并集照样有两条路：调方法，或者用运算符。上面是方法写法，`union` 一次只合两个集合，四份名单就得连着往后接三次，能算出来，但链条有点长。换成运算符就清爽了——一根竖线：

```python
all_set = football_set | basketball_set | french_set | art_set
```

这根竖线是键盘上回车键上面那个 `|`，不是斜杠。编辑器里注释默认是倾斜字体，斜杠 `/` 和竖线 `|` 挨得近，写的时候看清楚，别用错。

并集一算完，名单就到手了，而且天然是去重的：并集的结果仍然是 set，集合本身不允许重复元素，同一个人出现在四份名单里也只留一份。

第二步才是数数。可问题来了——`all_set` 里每个人只留了一次，那个"出现了几次"的信息已经被去重抹掉了。名字在这四份名单里一共出现了多少次，才等于他选了几门课。而集合装不下重复元素，这个活儿得换个容器，也就是列表。

于是把四份名单摊平成一个列表，用的是一颗星号，也就是解包：

```python
# 第二步：把四份名单解包摊平进一个列表，列表里允许重复
all_list = [*football_set, *basketball_set, *french_set, *art_set]
```

`*` 加在集合名前面，意思是"把这个集合里的元素一个一个拆出来，摆在这里"，四段拆完，再用列表的方括号一裹，四份名单就汇成了一个允许重复的大列表。

有了名单、又有了带重复的流水账，剩下的事就顺理成章：遍历去重后的名单，对每个人数一数他在 `all_list` 里出现过几次。

```python
for s in all_set:
    print(f"{s}选修了{all_list.count(s)}门课程")
```

`s` 从 `all_set` 里取，拿到的就是每个学生的名字（并集里没有重复，所以每个人只处理一次）。`count` 是列表自带的方法，统计某个元素在列表里出现了几次，把 `s` 传进去就行。

输出的结果形如：红蝶选修了 1 门课程，天运子选修了 4 门课程，紫菱选修了 2 门课程。随手核对几个：红蝶在四份名单里只被双击亮起过一处，天运子四处全亮，紫菱亮两处——名字出现几次，就是选了几门课，逻辑对得上。

> **提示**：这里之所以要绕一个列表，是因为 set 会去重、记录不了"出现次数"。想统计频次，就得先换到一个允许重复的容器里，再用 `count` 去数。集合负责"去重拿名单"，列表负责"保留重复做计数"，两个容器各干各的活。

## 三个运算符，一套推导式

四个需求做完，顺手把这一节新添的东西归拢一下。核心是集合运算的运算符，一共三个：

| 运算 | 方法 | 运算符 | 结果含义 |
| :--- | :--- | :--- | :--- |
| 交集 | `intersection` | `&` | 两个集合共有的元素 |
| 并集 | `union` | `\|` | 两个集合合起来、自动去重的元素 |
| 差集 | `difference` | `-` | 在前者中、但不在后者中的元素 |

这三种运算，方法和运算符完全等价，随便挑一种都能出结果。运算符短、读起来像数学式子，多数时候更顺手；方法名则把话说得更明白，尤其在链式调用或者需要传多个参数的时候。

另一件新东西是集合推导式。它和列表推导式的语法结构一模一样，只是外层括号从 `[]` 换成了 `{}`。写熟了列表推导式，这一条几乎是白送的。

到这里，集合这一块的内容就算过完了。四份选课名单、四条需求，交集、并集、差集、解包、推导式全都在里面跑了一遍。要是能不看讲义、自己把这段代码敲出来跑通，集合就算真的掌握了。

## 字典：从书架上的那本字典说起

集合之后，数据容器还剩最后一种——字典 dict。

字典这东西一点都不陌生。上学那些年，谁桌上没压过一本汉语字典、英语字典、成语字典。翻开它的样子也都记得：前面是字或者词，后面跟着这个字对应的解释。用它的动作就一个——根据字去查解释。

这种工具能成立，靠的是一条隐含的规矩：前面那个字不能重复。同一本字典里出现两个"行"字、各给一套解释，你翻到哪个算数？所以字典天然就是"字不重复、一字一解"的结构。

Python 里的字典，把这个结构原样搬了过来。它就是一种数据类型，名字叫 `dict`，里面存的是键值对：键对应传统字典里的"字"，值对应"字后面的解释"。写的时候中间用冒号隔开，`键: 值`，表示这两者是一对。取数据的时候，也只认一个动作——拿着键去找值。

`dict` 这个词来自英文 `dictionary`，就是字典的意思，取前四个字母简写。同样是键值对数据，不同语言叫法不一样：Python 叫 dict（字典），有的语言叫映射 map，有的叫哈希 hash，指的都是这同一种结构。

## 没有字典，成绩该怎么存

光说结构还是虚的，看一个具体场景。

现在要存班级学员的高考成绩：王林 670 分、韩立 556 分、李慕婉 582 分、子玲 435 分、许立国 608 分。

不用字典，这组数据怎么存？批量存数据，必然要用数据容器，能选的无非列表、元组、集合。集合先排除——它没有顺序，姓名和分数对不上号。那就只能用列表或者元组，而且得定义两个：一个装姓名，一个装分数。

```text
names  = ['王林', '韩立', '李慕婉', '子玲', '许立国']
scores = [ 670,    556,    582,      435,    608   ]
           ↑ 两个列表靠"同一下标"隐式绑定，顺序必须严格对齐
```

这么存，就必须守住一条死规矩：姓名列表的第一个是王林，分数列表的第一个就必须是 670；第二个是韩立，第二个就必须是 556。上下两个列表一个位置都不能错位。

麻烦还不止定义的时候。假设要查许立国的分数，得分两步走：先在姓名列表里找到"许立国"的下标，再拿这个下标去分数列表里取对应的值。一次查询要跑两个列表、做两次定位，写起来啰嗦，效率也低。

可要是换个角度看看这组数据呢——王林对着 670，韩立对着 556。王林不就是键，670 不就是值吗？这本来就是一组天生的键值对。既然数据长这样，就该用为它量身定做的容器来存：

```python
scores = {'王林': 670, '韩立': 556, '李慕婉': 582, '子玲': 435, '许立国': 608}
```

要查许立国的分数，`scores['许立国']` 一步到位。不用维护两个列表的对应关系，不用先找下标再取值，写出来简洁，跑起来高效，看着也优雅。

> **结论**：字典的主要应用场景，就是存储键值对类型的数据。数据本身成对出现、且要靠"名字"去查"内容"的时候，它比列表、元组都合适。

## 字典的三个特点

存储形式定了，字典的特点也就跟着清楚了，三条：

- 以键值对的形式存储数据，一个键配一个值，两者用冒号分隔；
- 一个字典里，键（key）不能重复——还是那本实体字典的道理，字要是重了，就查不出唯一的解释了；
- 字典里存的数据可以修改。要注意，改的是键对应的值，键本身动不了，因为它必须是不可变类型。

## 定义字典与取值

定义字典的语法，外层是一对大括号——和集合一样用大括号，但里面的内容不一样。集合里是一个个散着的元素，字典里必须是一组组 `键: 值`，多个键值对之间用逗号隔开。

```python
dict1 = {'王林': 670, '李慕婉': 608, '许立国': 580, '韩立': 688}
print(dict1)
print(type(dict1))
```

键是字符串，正常用引号引起来，单引号双引号都行；后面跟冒号，再跟具体的值。这一份里放了四组键值对，注意计量单位——一个键值对算一项数据，所以这个字典存的是四项数据，不是八项。

运行结果第一行会把四个键值对原样打印出来，第二行 `type` 会告诉你它是 `dict`。

取值也简单：字典名后面跟方括号，方括号里写键。

```python
print(dict1['李慕婉'])
```

这行会打印 608，因为 `'李慕婉'` 就是这个字典里的一个键，方括号里的内容是在问"这个键对应的值是多少"。

要定义空字典，两种写法：一对什么都不装的大括号 `{}`，或者直接调用 `dict()`。

> **易错点**：`{}` 造出来的是空字典，不是空集合。集合的定义虽然也用大括号，但空集合没法用 `{}` 表示——那对空括号被字典占用了，想要空集合只能写 `set()`。这个坑在两种容器之间来回切换时特别容易踩。

> **提示**：字典没有索引下标。列表能写 `list1[0]`，那是在按位置取；字典的方括号里放的必须是键，不是序号。想拿值，只能通过键。

## 键为什么必须不可变

字典里对键和值的要求是两套标准：值可以是任意类型的数据——字符串、布尔、整数、浮点，随便什么都可以；键不行，键必须是不可变类型。

先说清楚哪些是不可变类型。字符串 `str`、整数 `int`、浮点 `float`、元组 `tuple`，这些都是不可变的，拿来当键没问题。反过来说，列表 `list`、集合 `set`、字典 `dict` 都是可变类型，它们不能当键。

```python
# 整数、浮点、元组作键，都可以
dict2 = {0: 'a', 1: 'b', 2: 'c', 3: 'd'}
dict3 = {1.5: 'x'}
dict4 = {(1, 2): 'y'}
```

元组那一条看着有点怪——`(1, 2)` 当键，现实里没什么业务意义，这里纯粹是验证"不可变类型就能当键"这条规则。整数、浮点、字符串、元组挨个试下来，都能正常打印出来。

换成列表当键，就报错了：

```python
dict5 = {['a', 'b']: 'x'}   # TypeError: unhashable type: 'list'
```

报错信息说得很直接：list 是不能作为字典的键的，理由也简单——列表是可变的，而字典不允许它的键发生变化。

这个限制不难理解，想想图书馆的书。每本书的书脊上都有一个编号，你按编号去找书。可要是这个编号自己会变，今天写着 A-102，明天变成 B-305，那还找得着吗？编号一乱，书和号就对不上了。字典的键就是那个编号，它必须从头到尾钉死在一个值上，所以才要求不可变。

## 重复的键与可改的值

键不能重复这条规矩，实际表现值得单独看一眼。往刚才那个字典里再塞一个同样的键：

```python
dict1 = {'王林': 670, '李慕婉': 608, '许立国': 580, '韩立': 688, '王林': 700}
```

编辑器会先给个提示，鼠标悬上去能看到"字典中包含重复的键"之类的警告。这个提示可以忽略，重点看运行会怎样——程序不报错，正常跑完。

但结果变了：王林那个键对应的值不是 670 了，而是 700。

> **易错点**：键重复不会报错，而是后面的值覆盖前面的值。一个键在字典里永远只有一份，后写进来的那份把先写的顶掉。所以写字典时如果发现某个键的值莫名其妙不对，先回头找找是不是同一个键写了两次。

改值走的是另一条路——按现有的键重新赋值：

```python
dict1['李慕婉'] = 688
print(dict1)
```

`dict1['李慕婉']` 定位到这个键对应的位置，等号右边赋一个新值 688，再打印整个字典，李慕婉对应的 608 已经变成了 688。这就是"字典里的数据可以修改"的具体样子：键不动，值可以换。

把这几条串起来看，字典其实就三句话：用键值对存数据；键必须唯一、且必须是不可变类型；值随便什么类型都行，而且随时能改，改的时候靠键定位。

字典这一块还没走完。眼下弄清楚的是它长什么样、怎么定义、怎么取值、怎么改值；往后还有两块——一块是字典自己提供的那组常用操作，另一块是一组案例，用案例把前面这些内容再压一遍。等这三块都过一遍，数据容器这一章也就收尾了。
