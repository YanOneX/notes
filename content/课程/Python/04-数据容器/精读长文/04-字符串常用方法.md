# 字符串校验与元组解包

字符串的基本操作和常用方法讲完之后，该拿一个案例把它们串一遍了。光知道 `count`、`index`、切片各自能干什么不够，得放进一个真实的需求里跑一次，才算真的会用。这个案例就是邮箱格式的校验。

## 一个邮箱校验的案例

需求是：用户输入一个邮箱，我们验证它的格式对不对，正确就输出邮箱格式正确，否则输出邮箱格式错误。

邮箱地址不能随便写，不是任意一个字符串都能当邮箱，它有一定的格式要求。这里先抓最核心的两条：

- 整个地址里必须有 `@`，而且只能有一个；
- 地址里至少要有一个点 `.`。

看两个例子就清楚了：`itcast@163.com` 里有一个 `@`、一个点；`itcast@mail.itcast.cn` 里有一个 `@`、两个点。两个都是合法邮箱，所以点只需要"至少一个"，而 `@` 是"有且只有一个"——这两条要求不一样，写法也就不一样。

整个需求就两步：第一步接收用户输入的邮箱，第二步判断它的格式。

第一步用一个变量接住输入，变量名取 `mail`：

```python
mail = input("请输入邮箱：")
```

第二步要判断，自然用 `if`。这里的关键是选对判断工具。前面讲字符串常用方法时有两个做查找、做统计的方法，一个是 `find`，一个是 `count`。这个场景用 `count` 最直接——它统计某个子串在字符串里出现的次数，正好对上"有几个 `@`""有几个点"这两句话。

```python
mail = input("请输入邮箱：")

if mail.count("@") == 1 and mail.count(".") >= 1:
    print(f"{mail}是合法的邮箱")
else:
    print(f"{mail}是非法的邮箱")
```

两个条件之间是"并且"的关系：`@` 出现一次、点出现至少一次，两个条件都成立才算合法邮箱，所以中间用 `and` 连接。`@` 那一条写成 `== 1`，因为两个 `@` 同样不合法；点那一条写成 `>= 1`，因为点的个数上不封顶。

跑几组输入试试。输入 `taoge@163.com`，输出"是合法的邮箱"；输入 `dong@163.com`（`@` 前面换成一个字），一样合法；输入 `dong.taoge@163.com`，两个点一个 `@`，也合法——这也是合法的邮箱格式，很多人自己的邮箱就是这种形状。反过来，输入 `taoge163.com`，一个 `@` 都没有，输出"是非法的邮箱"；输入 `taoge@163com`，点被漏掉了，同样非法。

> **提示**：这种判断并不严谨，只是在我们目前学过的知识范围内做的一个简单判断。真正校验邮箱格式要用正则表达式，后面会专门讲到。

## 换 in 来判断"有没有"

同一个需求还有第二种写法。判断一个子串在不在字符串里，可以用 `in` 运算符。这个运算符在讲列表的时候已经见过，用来判断指定元素是否在列表之中；放到字符串上，它判断的就是指定的子串是否在这个字符串之中。

> **定义**：`子串 in 字符串` —— 子串存在则返回 `True`，不存在则返回 `False`。

但 `in` 只回答"有没有"，不回答"有几个"。所以 `@` 那一条仍然必须用 `count`：`in` 无法区分一个 `@` 和两个 `@`，在它眼里两者都是 `True`，而邮箱里出现两个 `@` 就是非法的。点那一条只关心存在不存在，用 `in` 正合适。

```python
mail = input("请输入邮箱：")

if mail.count("@") == 1 and "." in mail:
    print(f"{mail}是合法的邮箱")
else:
    print(f"{mail}是非法的邮箱")
```

改完之后再测一遍：`dong@163.com` 合法；`dong.taoge@163.com` 合法，`mail` 里点再多，`"." in mail` 也只返回一个 `True`；`taoge@163com` 非法，因为里面根本没有点。结果和第一种写法完全一致。

| 要判断的事 | 可用的写法 | 说明 |
| :--- | :--- | :--- |
| `@` 出现了几次 | `mail.count("@") == 1` | 必须计数，`in` 判断不了个数 |
| 点有没有出现 | `"." in mail` 或 `mail.count(".") >= 1` | 只关心存在与否，两种写法等价 |

同一个需求能有不同写法，这只是其中一种思路，选顺手的那个就行。

## 已经有了列表，为什么还要元组

接下来是数据容器里的第三种：元组 tuple。它同样能存多项数据，把多项数据存进一个元组里。

那马上就会有一个疑问：前面讲列表的时候，我们不就已经能把多项数据存进列表了吗，为什么还要学元组、还要用元组？

要搞清楚这个问题，先回想列表的特点。列表有三条：可以存多项元素，元素可以重复；元素有序；元素可以修改。三条里前两条元组也有，差别全在第三条。

再看一个开发中的场景：我们需要存一组数据，但这组数据是固定不变的，只能用来查询，不能修改。这时候还能用列表吗？不能——列表的每一个元素都是可以修改的，用它来存一组"不该被改动"的数据，等于把门留在了那里，谁都能推开。这种场景就该换元组。

> **定义**：元组是一种不可变的序列，类似于列表，但一旦创建完成，里面的元素不允许修改，只能查询。

元组和列表最大的不同点就一句话：一个可以修改，一个不可以修改。这也正是元组存在的意义——业务里只要遇到"这组数据只能查、不能改"，就该用元组来存。

## 元组长什么样：定义与特点

元组的特点可以从两个层面记。

它也能存不同类型的元素，元素可以重复，元素有序，这几点和列表一模一样。唯一的不同是元素不可以修改。

又因为它也是一种序列类型，所以它支持索引访问，也支持切片操作，而索引访问的方式和切片的语法，跟列表完全一致。

定义元组用一对小括号把元素括起来，元素之间用逗号分隔：

```python
t1 = (80, 95, 78, 50, 76, 88, 85, 80, 20)
print(t1)
print(type(t1))
```

输出里能看到一个带小括号的序列，类型是 `<class 'tuple'>`，`tuple` 就是元组类型。

如果要定义一个空元组，直接写一对小括号就行：

```python
t2 = ()
```

也可以调用 `tuple()` 来得到空元组。`tuple` 本身是一个函数，后面讲函数时会详细说，这里先知道它能造出一个空元组即可。不过既然只是要一个空的，写一对小括号既简洁又高效，没必要绕一趟函数调用。

| 对比项 | 列表 list | 元组 tuple |
| :--- | :--- | :--- |
| 定义符号 | 方括号 `[]` | 小括号 `()` |
| 元素可重复 | 是 | 是 |
| 有序（可索引、可切片） | 是 | 是 |
| 元素可否修改 | 可以 | 不可以，只读 |
| 常用方法 | 增、删、改、查一大批 | 只有 `count` 和 `index` |

元组的方法少得可怜，常用的就两个，原因还是那句话：它不支持任何修改操作，只能查询，所以留下的两个方法都是跟查询、统计相关的。`count` 统计某个元素在元组中出现的次数；`index` 查找某个元素在元组中的索引位置。

`index` 有一个地方要留意：元组里允许存在重复元素，所以它返回的是第一次匹配到的那个元素的位置。比如用 `index` 找 5，拿到的是第一个 5 的索引。

## 索引、切片与仅有的两个方法

元组是有序的，属于序列的一种，所以能通过索引访问元素，正向索引和反向索引都行：

```python
t1 = (80, 95, 78, 50, 76, 88, 85, 80, 20)

print(t1[0])    # 80，第一个元素
print(t1[-1])   # 20，最后一个元素
```

既然是不可变的，那就试试改它会发生什么：

```python
t1[0] = 100
```

执行就报错：`TypeError: 'tuple' object does not support item assignment`——元组对象不支持元素的重新赋值。开发工具在写的时候就会先给出提示，因为它在语法层面就知道这个位置不能改。

切片也一样支持，语法和列表的切片完全一致：

```python
print(t1[0:5])   # (80, 95, 78, 50, 76)
```

想截取前五个元素就写 `0:5`，索引从 0 开始，索引 5 是第六个元素，切片不包含结束位置，所以结束位置写 5 正好取到前五个。

两个方法各试一次：

```python
print(t1.count(80))   # 2
print(t1.index(80))   # 0
```

`t1` 里有两个 80，所以 `count` 得到 2；`index` 找 80 得到 0，也就是第一个 80 所在的位置，第二个 80 的索引它不管。

> **注意**：`index` 查找的元素不存在时会直接报错，这一点可以自己试一下，不要以为它会返回一个 -1 之类的值。

## 单元素元组的那一个逗号

这里有个容易踩的点，专门说一下：怎么定义一个只有一个元素的元组。

直觉上会写成这样：

```python
t3 = (100)
print(type(t3))   # <class 'int'>
```

用小括号括起来了，看起来是元组，但结果出来是 `int`。原因在于小括号在 Python 里不只是用来定义元组的，它还能把表达式括起来——前面讲运算符优先级时用它提升优先级，讲多条件时用它把一个条件括成一个整体，都是这个用法。当括号里只有一个元素时，解释器会认为这就是一对普通的括号，而不是元组的定义语法。开发工具也会在这行下面画波浪线，提示"移除冗余的圆括号"，因为它等价于直接写 `t3 = 100`。

想要真正的单元素元组，元素后面必须补一个逗号：

```python
t3 = (100,)
print(t3)         # (100,)
print(type(t3))   # <class 'tuple'>
```

> **易错点**：单元素元组的那个逗号不能省，决定它是不是元组的不是括号，而是逗号。

## 组包：定义元组本身就是在组包

组包和解包是一对对立方向的操作。

> **定义**：组包指把多个值合并到一个容器中的过程；解包指把容器拆解成一个个独立的值、再分别赋值给多个变量的过程。

组包这个概念一点都不新。写下 `t1 = (5, 7, 9, 1)` 这一行，把四个值合并进元组这一个容器里，这个过程就是组包。

```python
t1 = (5, 7, 9, 1)
print(t1)      # (5, 7, 9, 1)

t2 = 5, 7, 9, 1
print(t2)      # (5, 7, 9, 1)
```

定义元组时括号其实可以不写，直接一列逗号分隔的值，解释器执行时同样认为它是一个元组，也会自动把括号补上，两行输出完全一样。不过还是建议把括号加上——不加括号虽然能跑，但一眼看过去不容易看出这是个元组，加上括号语义就明摆在那里了。

```text
组包：      5    7    9    1
              \   |   |   /
               \  |   |  /
                (5, 7, 9, 1)

解包：      (5, 7, 9, 1)
               /  |   |  \
              5   7   9   1
              ↓   ↓   ↓   ↓
              a   b   c   d
```

图里上半部分是把散着的值收拢进一个容器，下半部分是把容器拆开分给四个变量，两个方向互为逆操作。

## 解包：拆成独立的值，再分给变量

解包就是把容器解开成一个个独立的元素，再赋值给不同的变量。元组里有几个元素，就可以一次拆给几个变量：

```python
t1 = (5, 7, 9, 1, 11, 12)
a, b, c, d, e, f = t1

print(a, b, c, d, e, f)   # 5 7 9 1 11 12
```

赋值按位置来：`a` 拿第一个元素 5，`b` 拿第二个 7，`c` 拿第三个 9，依此类推，`f` 拿最后一个 12。这就是最基础的解包。

> **易错点**：基础解包必须保证数量一致——不用星号时，容器里有几个元素，等号左边就得有几个变量。

数量对不上会直接报错。同样是这个六元素的元组，只写五个变量接收，工具里那一行立刻变红，提示"值太多无法解包"；真跑起来就是：

```python
a, b, c, d, e = t1
```

```text
ValueError: too many values to unpack (expected 5, got 6)
```

报错信息说的就是这件事：期望 5 个值，实际拿到 6 个，`unpack` 就是解包这个动作。变量补齐之后，六个值一次全部拿到。

## 星号：把剩下的都收进一个列表

基础解包要求数量一一对应，可实际需求往往没这么整齐。还是那个六元素的元组，如果只要第一个、第二个和最后一个，中间那一段根本不想一个个写出来。

这时就该用扩展解包，靠一个星号：

```python
t1 = (5, 7, 9, 1, 11, 12)

first, second, *other, last = t1

print(first, second)   # 5 7
print(other)           # [9, 1, 11]
print(last)            # 12
```

规则是：星号最后处理。先给不带星号、位置最确定的变量分配——`first` 拿第一个，`second` 拿第二个，`last` 拿最后一个；剩下的元素全部归带星号的变量。

> **定义**：`*变量名` 表示收集剩余的所有元素，用来处理数量不确定的那一段。

注意 `other` 打印出来是方括号包着的 `[9, 1, 11]`，不是小括号——星号收集到的剩余元素会封装成一个列表，而不是元组。原因很好理解：元组里的数据不可变，收进来的东西就没法再处理了；列表是可变的，收集完还能继续增删改，方便后续操作。

星号也可以往前挪：

```python
*other, last2, last1 = t1

print(other)    # [5, 7, 9, 1]
print(last2)    # 11
print(last1)    # 12
```

这种写法下，`last2` 收的是倒数第二个元素，`last1` 收的是倒数第一个元素，两个固定位置先定下来，最前面剩下的四个就都进了 `other` 这个列表。所以看这种代码时，先找不带星号的变量，再让星号去兜底。

## 一行代码完成变量交换

元组的组包与解包最实用的一个副产品，是把以前那个"借第三个杯子"的交换案例直接简化掉。

先回到老问题：`a = 10`，`b = 20`，想让两个变量的值换过来。之前是用一杯雪碧、一杯可乐来解释的——想把两杯饮料对调，手里必须多一个空杯子，先倒进去一杯，腾出位置，倒完再倒回来。落到代码上就是再定义一个临时变量，靠它中转。

现在不用了：

```python
a = 10
b = 20

a, b = b, a

print(a)   # 20
print(b)   # 10
```

一行代码，两个值就换过来了。拆开看就明白这一行里其实做了两步操作：

```python
t = b, a      # 第一步：组包，把 b 和 a 的值合并成一个元组 t
a, b = t      # 第二步：解包，把 t 里的值按位置分给 a 和 b
```

`b, a` 就是一个没写括号的元组，赋值给 `t` 是组包；`a, b = t` 是把容器拆开分给两个变量，是解包。把 `t` 换成右边的原式，两行就合并成了一行 `a, b = b, a`——右边先组包，左边再解包，中间不需要任何临时变量。

三个变量的轮换是同样的思路。`a = 100`，`b = 200`，`c = 300`，希望把三个值按"`a` 的值给 `c`、`b` 的值给 `a`、`c` 的值给 `b`"转一圈：

```python
a, b, c = 100, 200, 300

c, a, b = a, b, c

print(a, b, c)   # 200 300 100
```

等号右边 `a, b, c` 组包成 `(100, 200, 300)`，左边 `c, a, b` 按位置解包：`c` 拿到 100，`a` 拿到 200，`b` 拿到 300。验证一遍，`a` 是 200、`b` 是 300、`c` 是 100，正好转了一圈。

随着储备的知识越来越多，很多需求实现起来会越来越简单，原来要三四行加一个临时变量的活，现在一行就写完了。

## 本讲提到的题目

邮箱校验的案例做完，留了两道练习题。

### 判断回文串

接收用户输入的一个字符串，判断它是不是回文串。

解析：回文串指两边对称的字符串，从前往后读和从后往前读完全一样，比如"黄山落叶松叶落山黄""上海自来水来自海上"。判定方式就是把这个条件和字符串本身对应起来——把字符串反过来，再看它和原串是否相等：相等就是回文串，不相等就不是。答案即"原串与反转后的串相同则为回文串"。

### 十个字符串的反转与转存

让用户输入十个字符串，把这些字符串统一反转，反转之后转成大写，再存进列表，最后把列表里的字符串逐个输出。

解析：需求里已经把步骤排好了——先循环接收十次输入，每收到一个就先反转、再转成大写，然后把结果追加进列表；十个都处理完，再遍历这个列表，把每个字符串输出一遍。这里存结果用的是列表而不是元组，因为列表要一个个往里追加，正好是它的可变特性派上用场的地方。
