# 从成绩单到集合：元组嵌套、解包与 set 的基本操作

## 先看需求：一张十个人的成绩单

我们手上有一张成绩单，长得跟班主任用的那种表格一样：第一列学号，第二列姓名，往后三列是语文、数学、英语三科成绩。十行，十个学生。

要拿程序把这张表过一遍，需求有三条：

1. **算出每个学生的总分和三科平均分**，并且跟这个学生的学号、姓名、三科成绩一起输出——一行一个学生。
2. **统计每一科的最低分、最高分、平均分**，语文一行、数学一行、英语一行。
3. **把平均分大于 90 的学生找出来**，当作优秀学生输出。

三条需求本身都不复杂，真正要先想清楚的是另一件事：这张表在 Python 里到底怎么放。数据没地方安顿，后面全是空谈。

## 数据怎么存：元组里面再套元组

最朴素的想法是给每个值开一个变量。可字符串、`int`、`float` 这些类型，一个变量只装一个值；这张表有十个学生、每人五项，五十个值，开五十个变量显然不现实。所以必须上容器。

那用列表还是元组？判断标准只有一条：这批数据以后还要不要改。

> **结论**：成绩录入、核对完之后就不该再被程序改动，所以这里用元组，不用列表。

接下来是结构。表有十行，一行就是一个学生，那外层元组就该有十个元素；而一个学生身上挂着五项信息，这五项本身也是一个整体，于是每个元素再拿一个元组装起来——学号、姓名、语文、数学、英语。

```text
students（元组，10 个元素）
├── ("S001", "王林",   85, 92, 78)      ← 一个学生，又是一个元组
├── ("S002", "李慕婉", 92, 88, 95)
└── ...（共 10 条）

内层元组的五个位置：学号  姓名  语文  数学  英语
```

一层对一行，一层对一列，表的结构就搬进代码里了。

```python
students = (
    ("S001", "王林", 85, 92, 78),
    ("S002", "李慕婉", 92, 88, 95),
    # 其余 8 名学生的信息同理，此处省略
)
```

写成这样，取数据就靠下标：`s[0]` 学号、`s[1]` 姓名、`s[2]` 语文、`s[3]` 数学、`s[4]` 英语。后面三个需求，全是在这几个下标上做文章。

这十行是体力活。等以后做项目，这种规整的结构化数据完全可以丢给 AI 去生成；但现在还在打基础，建议老老实实手敲一遍，把嵌套的括号和逗号敲熟——手上有感觉了，再看别人的代码才不费劲。

> **提示**：从别处粘代码进来常带着一串缩进，选中之后按 `Tab` 往右缩，按 `Shift + Tab` 往左顶格。

## 每个学生一行：总分、平均分与对齐的输出

### 先把总分和平均分算出来

要算每个学生的总分，就得把每个学生挨个取出来处理一遍——一个一个来，这就是循环的场合。

```python
for s in students:
    total = s[2] + s[3] + s[4]
    avg = total / 3
    print(f"{s[0]}\t{s[1]}\t{s[2]}\t{s[3]}\t{s[4]}\t{total}\t{avg}")
```

`for s in students` 每次取出一个元素，而这个 `s` 本身又是一个元组：外层装的是学生，内层装的是字段，所以循环一轮正好处理一个学生。

总分把三科成绩加起来。下标是 2、3、4，不是 0、1、2——前两位已经被学号和姓名占掉了。

> **易错点**：平均分除的是 3，也就是科目数，不是 `len(students)`。`len(students)` 是 10，学生人数；拿总分除以人数，算出来的东西没有任何意义。

### 让平均分只留一位小数

第一次运行，前面几列还算整齐，最后一列却拖出一条长尾巴。原因出在除法上：`255 / 3` 除得尽，另外一些总分除不尽，Python 就把浮点数的精度全打出来了。

要它只留一位小数，就在 f-string 的变量后面加一个冒号，冒号后面写格式：

```python
print(f"{avg:.1f}")
```

三段各有分工：冒号是分隔符，告诉 Python 后面是格式说明；`.1` 表示保留一位小数；`f` 表示按浮点数（float）来处理这个值。写成 `{avg:.1f}`，除不尽的那种一长串数字就收成一位小数，除得尽的 `85.0` 也照样保留一位。

### 用制表符把输出排成一张表

小数收住了，还有两个毛病：内容挤成一团；`85`、`92`、`78` 摆在那儿，根本不知道哪个是语文、哪个是英语——因为没有表头。

先加表头。在循环之前打一行列名，列与列之间用 `\t`：

```python
print("学号\t\t姓名\t\t语文\t\t数学\t\t英语\t\t总分\t\t平均分")
```

`\t` 是转义字符，输出的是一个制表符（Tab）。它比敲空格好用，因为制表符负责对齐，列宽由它撑开。

表头先用两个 `\t` 把列拉开，跑出来发现太宽，列与列之间空出一大截；改成一个 `\t`，数据行也用同样的一个 `\t`，上下就对上了。对齐这件事没什么原理，就是试：宽了减一个，窄了加一个。

数据行照同样的办法加上制表符，最后的输出是这样：

```text
学号	姓名	语文	数学	英语	总分	平均分
S001	王林	85	92	78	255	85.0
S002	李慕婉	92	88	95	275	91.7
```

第一列学号，第二列姓名，中间三列是三科成绩，后面跟着总分和平均分，一眼扫过去就知道每一列是什么。

## 把每一科的成绩抽成一列

第二个需求要的是"每一科"的最值，可数据偏偏是按"每个学生"存的。所以得先做一次转换：把每一科的成绩，从每个学生的元组里抽出来，凑成三个列表。

这活儿列表推导式最拿手：

```python
chinese_scores = [s[2] for s in students]
math_scores = [s[3] for s in students]
english_scores = [s[4] for s in students]
```

列表推导式就两段：前面的 `s[2]` 决定往新列表里放什么，后面的 `for s in students` 决定从哪里取。这里最容易写错的是前面——如果写成 `[s for s in students]`，拿到的是十个完整的元组，不是十个语文成绩，一定要把下标带上。

抽出来之后，三个统计量都是现成的函数：`min()` 求最小、`max()` 求最大，平均分用 `sum()` 求和再除以 `len()` 求长度。

```python
print(f"语文最低分：{min(chinese_scores)}，最高分：{max(chinese_scores)}，平均分：{sum(chinese_scores) / len(chinese_scores)}")
```

不想调 `min`、`max` 也有土办法：把列表排个序，第一个元素就是最小值，最后一个就是最大值。效果一样，只是多了一步排序。

数学和英语是同一段代码换一个列表，复制两份、把变量名和下标换掉就行（`Ctrl + D` 可以快速复制当前行）。

> **提示**：这里的 `len(chinese_scores)` 是列表长度，也就是学生人数。上一个需求里除的 3 是科目数——同样是求平均，除的东西完全不是一回事，别顺手混用。

跑出来核对一下：语文最低分 66，最高分 95，去表里翻，最低的那一条确实是 66，95 是周易的语文。数对得上，说明没有抽错列。

## 挑出平均分大于 90 的学生

第三个需求最轻：再遍历一次，算出平均分，判断一下。

```python
for s in students:
    avg = (s[2] + s[3] + s[4]) / 3
    if avg > 90:
        print(f"{s[0]}\t{s[1]}\t{avg:.1f}")
```

需求说的是"大于 90"，代码里就写 `>`，不要顺手写成 `>=`。边界值算不算优秀，是需求定的，不是写代码的人定的。

跑出来是四个学生，平均分都在 90 以上，学号、姓名、平均分一并输出。小数同样用 `:.1f` 收一下。

三段输出原本是首尾相连的，读起来分不清哪段属于哪个需求。在每两段之间补一个空的 `print()`，打一行空行，层次立刻清楚。

## 换一种写法：元组解包

三个需求都实现了，代码能跑，输出也对。但回头看一眼，有一处别扭：`s[2]`、`s[3]`、`s[4]`。

问一句：`s[2]` 是学生的什么信息？`s[4]` 又是什么？结构记得牢的人能脱口而出，记不牢的人得回头翻定义才知道。三科还好，要是七八个科目，满屏都是 `s[5]`、`s[6]`、`s[7]`，可读性就没了。

元组解包就是冲着这个问题来的。既然 `s` 里有五个元素，左边就摆五个变量，Python 按位置一个一个对上：

```python
for id, name, chinese, math, english in students:
```

> **定义**：元组解包，就是把元组里的元素按位置依次赋给一组变量。变量个数必须和元素个数一致，多一个少一个都会报错。

`id` 这个词在开发里指唯一标识，学号正好是唯一的，所以第一个变量叫 `id`；后面依次是姓名、语文、数学、英语。

解开之后，循环体里全部改用变量名：

```python
for id, name, chinese, math, english in students:
    total = chinese + math + english
    avg = total / 3
    print(f"{id}\t{name}\t{chinese}\t{math}\t{english}\t{total}\t{avg:.1f}")
```

总分从 `s[2] + s[3] + s[4]` 变成 `chinese + math + english`，输出里的每一项也都有了自己的名字。跑一遍，结果和方式一完全相同。

但解包不是哪里都合适。第二个需求就不值得改：它只需要每一科的那一列，用解包就得在循环里白摊五个变量、只用其中一个，反而累赘，所以那一节保持原样。第三个需求可以换成解包，改完输出一样。

> **结论**：两种写法都对，输出一模一样。解包的价值不在少敲几个字符，而在把"第几个位置是什么"写进变量名里，让人一眼看懂。

| 写法 | 取数据的样子 | 什么时候合适 |
| :--- | :--- | :--- |
| 索引 | `s[2]`、`s[3]`、`s[4]` | 只要其中一两个字段，比如只抽一列成绩 |
| 解包 | `chinese`、`math`、`english` | 五个字段全都要用，比如算总分、拼输出 |

## 为什么还要第四种容器

列表、元组、字符串，三种容器都能装多条数据了，为什么还要再学一个 `set` 集合？

设想一个业务系统里的场景：要定义一个变量，存一批用户的手机号。手机号、身份证号、银行卡号这类东西，一个人只有一个，天然不会重复。

那能不能用列表或者元组来存？不能。列表和元组允许重复元素，你往里放两次同一个手机号，它就老老实实存两份，数据就脏了。`set` 不一样，它会自动去重：即使你存了重复的，也只留一份。

> **结论**：要存一批不重复、唯一的数据，就用 `set`。

后面还会配一个案例专门练它，这一节先把特点和基本操作弄清楚。

## set 的三个特点

一句话就能说完：`set` 是一种无序的、不可重复的、可修改的数据容器。三个词，对应三个特点。

**无序**。列表、元组、字符串都是有顺序的，有顺序就能按下标取：`s[0]` 拿第一个。`set` 没有顺序，这条路直接断掉——它不支持索引访问，`s[0]` 这种写法在集合上用不了。

**不可重复**。存进去的重复元素会被自动去掉，集合里不会同时存在两个相同的值。这一点是它存在的理由。

**可修改**。可以往里加元素，也可以从里面删元素。元组是定义好就动不了的，这一点上两者正好相反。

| 容器 | 是否有序 | 能否存重复元素 |
| :--- | :---: | :---: |
| 列表 | 有序 | 可以重复 |
| 元组 | 有序 | 可以重复 |
| 集合 | 无序 | 自动去重 |

> **提示**：无序的直接后果，是不要依赖控制台打印出来的顺序。同一批元素，打印的先后可能和你写的顺序对不上；拿顺序去做判断、去写断言，迟早出事。

## 定义集合，以及空集合的坑

列表用方括号 `[]`，元组用小括号 `()`，集合用大括号 `{}`：

```python
s1 = {5, 3209, 12, 5, 0, 0}
print(s1)
print(type(s1))
```

元素之间用逗号分隔。这里故意把 `5` 和 `0` 各写了两遍，跑出来只剩一个 `5`、一个 `0`——去重是自动完成的。同时打印的先后顺序也和定义时写的顺序对不上，这就是无序。`type()` 打出来是 `<class 'set'>`。

空集合有个坑，而且是反复强调的那个坑：

```python
s2 = {}       # 这不是空集合
s3 = set()    # 这才是空集合

print(type(s2))   # <class 'dict'>
print(s3)         # set()
```

> **易错点**：`{}` 定义出来的是字典（dict），不是集合。空集合只能用 `set()`，一对小括号，一个元素都不给。空集合打印出来是 `set()`，不是 `{}`。

字典是后面要讲的最后一种容器，这里先把这个坑记住就行。

## 七个常用方法

常用方法一共七个，按用途分两拨：四个管增删，三个管两个集合之间的运算。

| 方法 | 作用 |
| :--- | :--- |
| `add` | 往集合里添加一个元素 |
| `remove` | 删除指定元素，元素不存在会报错 |
| `pop` | 随机删除一个元素，并把删掉的元素返回 |
| `clear` | 清空集合 |
| `difference` | 求两个集合的差集 |
| `union` | 求两个集合的并集 |
| `intersection` | 求两个集合的交集 |

### 增与删

`add` 负责加。原来集合里有八个元素，`s1.add(1200)` 之后变成九个。用调试器一步一步走，会看到 `1200` 落在了 `400` 和 `500` 之间——不是接在末尾，因为集合根本没有"末尾"这个概念。这是无序最直观的一次现场演示。

`remove` 删指定元素，`s1.remove(200)`，`200` 就从集合里消失了。要注意：删的元素如果不存在，会直接报错，不是静默跳过。

`pop` 随机删一个，并且把删掉的那个元素返回回来。它没法指定删谁——无序的集合没有"第几个"可言。想知道删的是谁，就拿一个变量接住返回值；某一次接住的是 `800`。

`clear` 清空，集合里一个元素都不剩，剩下的是 `set()`，不是 `{}`。

### 差集、并集与交集

这三个是初中数学里的集合运算，作用在两个集合之间。把 S2 和 S3 摊成三段来看最清楚：

```text
        S2 = {A, B, C, D, E, X, Y}    S3 = {C, E, Y, Z}

        ┌───────────────┬───────────────┬──────────┐
        │  A  B  D  X   │   C  E  Y     │    Z     │
        └───────────────┴───────────────┴──────────┘
          S2 - S3           S2 ∩ S3        S3 - S2
```

左段只在 S2 里，右段只在 S3 里，中段两边都有；三段合起来，就是并集。

```python
s2 = {"A", "B", "C", "D", "E", "X", "Y"}
s3 = {"C", "E", "Y", "Z"}

print(s2.difference(s3))     # {'A', 'B', 'D', 'X'}
print(s3.difference(s2))     # {'Z'}
print(s2.union(s3))          # 两个集合的全部元素
print(s2.intersection(s3))   # {'C', 'E', 'Y'}
```

`difference` 求差集：包含在第一个集合里、但不包含在第二个集合里的元素。`s2.difference(s3)` 得到 `{A, B, D, X}`；把两个集合调个个儿，`s3.difference(s2)` 只剩 `{Z}`。差集是有方向的，谁写在前面，谁就是被减的那一个。

`intersection` 求交集：两个集合共有的元素，`{C, E, Y}`。`union` 求并集：两边的元素合并到一起，重复的只留一份。交集和并集都不挑顺序，`s2.union(s3)` 和 `s3.union(s2)` 结果一样。

> **提示**：三个方法里只有 `difference` 有方向。记这一条，比死背三个英文单词有用。

这一整套演示跑下来，集合"可修改"这个特点也就验证完了：能加、能删、能清空，跟元组的纹丝不动正好相反。
