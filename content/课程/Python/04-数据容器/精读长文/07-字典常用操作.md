# 字典的增删改查与购物车案例

字典这种东西，知道它长什么样是一回事，能随手往里塞、往外拿是另一回事。前面把它的特点和定义捋清楚了：键值对，一个 key 对应一个 value。这一节要做的，就是让这些键值对真正动起来——增、删、改、查，一样一样过一遍。

这些操作本身不难，难的是把边界记牢：同样一行代码，什么时候是新增，什么时候是修改。等这四类操作过完，再拿一个购物车的小案例把它们串起来用一次，字典这块才算真的拿下。

## 增和改，是同一行代码

往字典里加数据，语法简单得有点不像话：字典名后面跟方括号，方括号里写 key，等号后面写 value。

```python
dict1["涛哥"] = 550
```

这一行到底是"增"还是"改"，不看你写了什么，只看 `涛哥` 这个 key 在字典里有没有。没有，就是往字典里新塞进一对键值对；已经有了，就是把原来那个 value 换成新的。

> **结论**：添加和修改的语法完全一样，只看 key 在不在。key 不存在就执行添加，key 存在就执行修改。

拿一个现成的字典试一下。假设 `dict1` 里已经存了四个人的成绩，唯独没有"涛哥"：

```python
dict1 = {"王林": 670, "李慕婉": 608, "许立国": 580, "韩立": 588}
print(dict1)

dict1["涛哥"] = 550          # 涛哥不存在，走新增
print(dict1)                 # 涛哥 550 进去了

dict1["涛哥"] = 620          # 涛哥已经存在，走修改
print(dict1)                 # 涛哥从 550 变成 620
```

先输出一遍，确认里面确实只有四组键值对、没有涛哥；打下断点走一步，涛哥 550 就进来了；再为同一个 key 赋一次值，550 就被改成 620。一个学渣，代码跑两行，一跃成为学霸。

> **易错点**：别把"新增"和"修改"当成两套 API 去找。字典没有 `add` 方法，赋值就是全部。它靠 key 是否存在自己判断该干什么，你要做的是想清楚这个 key 此刻在不在。

## 删除：pop 和 del 的差别

删掉一对键值对，有两条路。

第一条是调字典自带的 `pop` 方法，把要删的 key 传进去：

```python
score = dict1.pop("许立国")
print(score)    # 580，被删掉的那个值被返回来了
print(dict1)    # 许立国 这一对已经不在了
```

`pop` 会把这个 key 连同它对应的 value 一起从字典里摘掉，同时把刚摘下来的那个 value 作为返回值交还给你。删的是什么，你当场就知道。

第二条是用 `del` 这个关键字，前面学列表时已经用过它：

```python
del dict1["韩立"]
print(dict1)    # 韩立 这一对没了，但 del 不给返回值
```

> **结论**：`pop` 和 `del` 都能按 key 删掉整对键值对，区别只有一处——`pop` 能拿到被删掉的值，`del` 拿不到。

要删完还想拿这个值去做别的事，就用 `pop`；纯粹想把它从字典里抹掉，`del` 更直接。这个区别后面写案例时用得上：删商品只需要删，不需要那个价格，用哪个都行。

## 查询：一个 key 换一个 value

按 key 取 value，有两种写法，效果一模一样。

```python
print(dict1["涛哥"])         # 620
print(dict1.get("涛哥"))     # 620
```

方括号是直接用 key 去索引，`get` 是调字典对象的方法、把 key 传进去。日常取单个值，这两种随便挑一个顺手的。

除此之外，字典还提供了三个"一次拿走一批"的方法：

| 写法 | 拿到什么 | 返回的类型 |
| :--- | :--- | :--- |
| `dict1[key]` | 这个 key 对应的一个 value | 值本身的类型 |
| `dict1.get(key)` | 同上 | 值本身的类型 |
| `dict1.keys()` | 字典里所有的 key | `dict_keys` |
| `dict1.values()` | 字典里所有的 value | `dict_values` |
| `dict1.items()` | 字典里所有的键值对 | `dict_items` |

```python
print(dict1.keys())     # dict_keys(['王林', '李慕婉', '涛哥'])
print(dict1.values())   # dict_values([670, 608, 620])
print(dict1.items())    # dict_items([('王林', 670), ('李慕婉', 608), ('涛哥', 620)])
```

`items` 这个词翻译过来就是"项"，一项就是一对键值对。所以 `keys` 拿全部的键，`values` 拿全部的值，`items` 拿全部的键值对，三个名字和它们干的事对得上，不用死记。

注意它们返回的东西：不是列表，是 `dict_keys`、`dict_values`、`dict_items` 这三种字典独有的类型。但你把里面的内容摊开看，就是一个一个的元素排在那儿，跟列表长得几乎一样，所以后面拿它去遍历毫无障碍。

## 遍历字典的几种走法

假设现在要把字典里所有的键值对一条一条打印出来，那就得遍历。遍历的入口不止一个，因为上面那三个方法各自都能交出一批数据。

最直觉的一种是走 `keys`：先拿到所有的 key，再拿着 key 回头去取 value。

```python
for key in dict1.keys():
    print(f"{key}: {dict1[key]}")
```

`dict1.keys()` 交出全部的 key，for 循环一次取一个，取到的 `key` 拿去索引字典，对应的 value 就出来了。

第二种是走 `items`：`items` 交出的每一项本身就是一个键值对，而这一项在 Python 里是个元组，所以可以用下标去拆。

```python
for item in dict1.items():
    print(f"{item[0]}: {item[1]}")
```

小括号括起来的就是元组，`item[0]` 是键，`item[1]` 是值。

第三种还是走 `items`，但不拆下标，直接在 for 循环的变量位置上写两个名字——这就是解包：

```python
for key, value in dict1.items():
    print(f"{key}: {value}")
```

`items` 的每一项里装着两个元素，循环时这两个变量按位置接住它们：第一个元素给 `key`，第二个元素给 `value`。三种写法跑出来的结果都是：

```text
王林: 670
李慕婉: 608
涛哥: 620
```

> **提示**：这段遍历之所以能成立，靠的是前面学的 for 循环、元组、解包这几样东西的组合。学过的知识别供在架子上，活学活用，同一个需求往往有好几种写法都通。

## 案例：一个购物车系统

字典的特点、定义、常用操作都过了一遍，接下来拿一个案例把它们粘起来——购物车系统，也就是商品信息的增、删、改、查。

需求是这样的：用字典结构存商品数据，通过控制台菜单和用户交互。程序跑起来，控制台先出现这么一块菜单：

```text
############################
#       购物车系统         #
#  1 添加购物车            #
#  2 修改购物车            #
#  3 删除购物车            #
#  4 查询购物车            #
#  5 退出购物车            #
############################
```

用户敲一个编号，程序就去执行对应的操作。五个功能各自的流程：

- **添加购物车**：录入商品名称、商品价格、商品数量，然后把这件商品存进购物车。你在电商网站上加购物车，要填的也是这几项。
- **修改购物车**：先输入要改的是哪件商品（按名称），再输入这件商品最新的价格和最新的数量。
- **删除购物车**：输入商品名称，按名称把这件商品从购物车里删掉。
- **查询购物车**：把购物车里的数据展示出来——商品名称是什么、价格多少、数量多少。
- **退出购物车**：结束程序。

> **提示**：留意修改和删除这两项的共同点——它们都要先拿到商品名称，靠名称找到那件商品，然后才动手。这个共同点会直接决定下面数据结构怎么设计。

## 数据结构：三种存法，只有一种顺手

写代码之前先想清楚一件事：购物车到底怎么存。这一步没想明白，后面每一行代码都在补窟窿。

**第一种，一个字典装一件商品：**

```python
{"name": "mate80", "price": 6999, "number": 2}
```

`name` 是商品名称，`price` 是价格，`number` 是数量。看着挺齐全，但满足不了需求。原因很直接：一个购物车不会只装一件商品，而这里的 `name` 是一个 key，同一个字典里 key 只能出现一次。你把 `name` 定成 mate80，就再也塞不进第二件商品了。这种结构只能存"单件商品的购物车"，不是购物车。

**第二种，列表套字典：**

```python
[
    {"name": "mate80", "price": 6999, "number": 2},
    # 再来一件商品就再往列表里加一个字典
]
```

外层是列表，列表里每个元素是一个字典，字典里装着这件商品的名称、价格、数量。乍一看是能满足需求的——购物车里有几件商品，列表里就有几个元素，多件商品的问题解决了。

但再往下想一步就露馅了：修改和删除的时候，我们要先输入商品名称，靠名称找到这件商品。而在这个结构里，商品名称是字典的 value，不是 key。字典的增、删、改、查全是围着 key 转的，删除尤其如此，`pop` 和 `del` 都只认 key。名称蹲在 value 里，你就只能把整个列表遍历一遍、逐个比对，才能找到那件商品。

**第三种，外层字典，key 直接就是商品名：**

```text
shopping_cart（外层字典）
├── key: "mate80"  →  value: {"price": 6999, "number": 2}
└── key: "鼠标"    →  value: {"price": ...,  "number": ...}
```

整个购物车就是一个字典，每一个键值对是一件商品：key 是商品名称，value 又是一个字典，里面装这件商品的 `price` 和 `number`。读这张图只要看两层：外层一层，一个键值对就是一件商品；进到 value 里那一层，才看到这件商品的价格和数量。

这下修改和删除都变成同一个动作：用户输入的商品名称，恰好就是这个字典的 key，拿它去索引，一件商品立刻被定位到，改也好删也好，一行代码的事。

> **结论**：商品名称必须坐在 key 的位置上。字典的所有操作都是围绕 key 展开的，谁被频繁拿来定位，谁就该当 key。

## 菜单和分支：这次用 match

先立容器。程序刚跑起来时购物车里什么都没有，所以它就是一个空字典，随用户的操作再往里长东西：

```python
shopping_cart = {}
```

菜单本身没什么神秘的，就是 print 打出来的一段字符串。它有好几行，所以用三引号定义成一个多行字符串，赋给变量 `menu`，再打印：

```python
menu = """
############################
#       购物车系统         #
#  1 添加购物车            #
#  2 修改购物车            #
#  3 删除购物车            #
#  4 查询购物车            #
#  5 退出购物车            #
############################
"""

print("欢迎使用购物车管理系统")
print(menu)
```

五行选项要居中、两边要各留一段井号边框，逐行手敲井号太笨。按住 `Alt` 再按住 `Shift`，用鼠标从第一行往下拖，五行行首同时出现光标——这叫列编辑，然后一敲，五行的前缀就一起加上了；同样的方法再拖一次，把后边框也补齐。

> **提示**：列编辑的快捷键是 `Alt + Shift`，按住不松、鼠标纵向拖选，改的就是同一列的位置。边框能对齐，靠的是补齐空格，井号个数不必数，敲完跑一遍看输出对不对齐最省事。

菜单出来之后，让用户输入要执行的操作：

```python
choice = input("请选择要执行的操作（1~5）：")
```

这个分支有一串等值判断——`choice` 是不是 1、是不是 2、是不是 3……如果写成 `if / elif`，每一条都得重复写一遍 `choice ==`，读起来又长又重复。这正是 `match` 的用武之地：

```python
match choice:
    case "1":
        pass    # 添加购物车
    case "2":
        pass    # 修改购物车
    case "3":
        pass    # 删除购物车
    case "4":
        pass    # 查询购物车
    case "5":
        pass    # 退出购物车
    case _:
        print("非法操作，不支持")
```

`match` 后面跟要匹配的值，`case` 后面跟候选，命中哪个就执行哪个分支，一行一个，`choice ==` 一次都不用写。先把架子搭起来，五个分支里先放 `pass` 占位，等会儿一个一个填肉。

> **提示**：`input` 拿回来的永远是字符串，不管用户敲的是不是数字。所以 `case` 后面要比的是 `"1"`、`"2"` 这样的字符串，写成数字 `1` 一条也匹配不上。

最后那个 `case _` 管的是"1~5 之外的其他所有情况"，用户手滑敲个 6 或者敲个字母，都落到这里，输出一句非法操作。

> **易错点**：`case _:` 里的下划线是通配符，**不能加引号**。写成 `case "_":` 就变成"匹配内容为一个下划线的字符串"了，1~5 之外的输入会全部漏过去，程序一声不吭。

## 添加购物车：先查重，再落库

添加购物车要收三样东西：商品名称、商品价格、商品数量。三次 `input`，三个变量分别接住：

```python
goods_name = input("请输入商品的名称：")
goods_price = float(input("请输入商品的价格："))
goods_number = int(input("请输入商品的数量："))
```

三行的区别在后面那两个转换上。名称收进来就是字符串，原样用；价格不行，商品价格不一定是整数，6999 也好 69.9 也好都得接得住，所以用 `float` 把输入的字符串转成小数；数量更不行，数量是整数，用 `int` 转。

拿到三样东西之后，先别急着往字典里写。购物车里已经有这件商品了呢？添加的前提是它还没有，所以先查一遍：

```python
if goods_name in shopping_cart:
    print("该商品已存在，请重新选择要执行的操作")
else:
    shopping_cart[goods_name] = {"price": goods_price, "number": goods_number}
    print("商品添加完毕")
```

`in` 这个运算符前面在列表、集合上都用过，搁在字典身上，它判断的是 **key 在不在**。商品名称存在，说明这件商品已经在购物车里了，那就不能添加——提示一句，让用户重新选操作。不存在，才走进 `else`。

`else` 里这一行是整段的核心：方括号里写 key，也就是 `goods_name`；等号右边不是单个值，而是一个新造出来的字典 `{"price": ..., "number": ...}`。外层字典的 key 是商品名，value 是这件商品的价格和数量，前面设计好的结构就落在这里。

> **提示**：小字典里的 `price` 和 `number` 这两个名字，是后面查询时的取货凭证。存的时候叫什么，查的时候就得叫什么，两边对不上就是 `KeyError`。

## 改与删：用 not in 把住门

修改购物车的录入环节和添加几乎一样，也是三行 `input`，只是提示语换了说法——问的是"要修改的商品名称"，价格和数量前面都要带上"最新的"，因为用户是来改的，得让他把新值报清楚：

```python
goods_name = input("请输入要修改的商品名称：")
goods_price = float(input("请输入商品最新的价格："))
goods_number = int(input("请输入商品最新的数量："))
```

判断的门槛反过来了。修改的前提是这件商品得先存在，用户要是敲了个购物车里根本没有的名称，那没什么可改的：

```python
if goods_name not in shopping_cart:
    print("该商品不存在，请重新选择要执行的操作")
else:
    shopping_cart[goods_name] = {"price": goods_price, "number": goods_number}
    print("商品修改完毕")
```

添加是"存在就不干"，所以用 `in`；修改是"不存在就不干"，所以用 `not in`。两处就差这一个运算符，逻辑正好相反。

再看 `else` 里这一行——它和添加时的那一行一模一样。这不是巧合，前面讲增改同源时就说过：同一行赋值，key 不存在就是新增，key 存在就是修改。走到这里的 key 一定存在，所以它执行的是修改，旧的价格和数量被整个换掉。

删除购物车连价格和数量都不用问，只需要用户报一个名称：

```python
goods_name = input("请输入要删除的商品名称：")

if goods_name not in shopping_cart:
    print("该商品不存在，请重新选择要执行的操作")
else:
    del shopping_cart[goods_name]
    print("商品删除完毕")
```

门槛和修改一样，也是 `not in`：你有，我才删；你随便输一个购物车里没有的名称，提示一句就完了，不进删除逻辑。门里那一步，`del shopping_cart[goods_name]` 是把这对键值对整对摘掉，换成 `shopping_cart.pop(goods_name)` 也一样能删——这里不需要那个被删掉的价格，所以哪个顺手用哪个。

## 查询购物车：怎么存进去，就怎么取出来

查询要把购物车里每件商品都摆出来。外层字典的 key 就是全部商品名称，所以拿 `keys()` 起步：

```python
for goods_name in shopping_cart.keys():
    goods_info = shopping_cart[goods_name]
    print(f"商品名称：{goods_name}，商品价格：{goods_info['price']}，商品数量：{goods_info['number']}")
```

`keys()` 交出所有商品名称，for 循环一次取一个；拿着这个名称回到外层字典索引一下，取出来的就是那件商品的小字典，交给 `goods_info`；再从 `goods_info` 里按 `price`、`number` 把两个值取出来，塞进格式化字符串里打印。

> **提示**：写查询这一段的诀窍只有一句——刚才怎么存的，现在就怎么取。存的时候 value 是 `{"price": ..., "number": ...}`，取的时候就得按 `price`、`number` 去拿，一个字母都不能差。

## 让系统一直转：while True 加一个 break

四个功能写完，跑一把试试。菜单正常出来，输入 `1`，敲进 mate80、6999、2，控制台打出"商品添加完毕"——然后程序就结束了。

这就不像一个系统了。既然是个购物车系统，添加完一件商品，用户多半还想接着改、接着查、接着加，怎么可能一次就收摊。真正该结束的时机只有一个：用户选了 5。

所以要把"读输入 + 分支处理"这一整段塞进循环里。循环次数事先根本不知道，用户想操作几次就几次，所以用 `while`；条件直接写 `True`，让它一直转，出口靠 `break`：

```python
print("欢迎使用购物车管理系统")
print(menu)

while True:
    choice = input("请选择要执行的操作（1~5）：")

    match choice:
        case "1":
            pass
        # 其余分支略
        case "5":
            print("拜拜")
            break
        case _:
            print("非法操作，不支持")
```

哪几行该留在循环外面，得想清楚：欢迎语和菜单只该在程序启动时露一次面，留在外面；`input` 和 `match` 必须进去，每一轮都要重新问一次、重新判一次。

退出分支里，先打印一句"拜拜"，再 `break`。`break` 的作用就是立刻跳出当前循环，循环一结束，程序也就走完了。

到这里，添加、修改、删除、查询四个功能齐活，加上退出的收尾，购物车系统算是立起来了。这套代码的完整测试，留到下一小节跑一遍。

## 拼起来看

把前面各段按顺序合到一个文件里，就是完整的一套：

```python
shopping_cart = {}

menu = """
############################
#       购物车系统         #
#  1 添加购物车            #
#  2 修改购物车            #
#  3 删除购物车            #
#  4 查询购物车            #
#  5 退出购物车            #
############################
"""

print("欢迎使用购物车管理系统")
print(menu)

while True:
    choice = input("请选择要执行的操作（1~5）：")

    match choice:
        case "1":
            goods_name = input("请输入商品的名称：")
            goods_price = float(input("请输入商品的价格："))
            goods_number = int(input("请输入商品的数量："))

            if goods_name in shopping_cart:
                print("该商品已存在，请重新选择要执行的操作")
            else:
                shopping_cart[goods_name] = {"price": goods_price, "number": goods_number}
                print("商品添加完毕")

        case "2":
            goods_name = input("请输入要修改的商品名称：")
            goods_price = float(input("请输入商品最新的价格："))
            goods_number = int(input("请输入商品最新的数量："))

            if goods_name not in shopping_cart:
                print("该商品不存在，请重新选择要执行的操作")
            else:
                shopping_cart[goods_name] = {"price": goods_price, "number": goods_number}
                print("商品修改完毕")

        case "3":
            goods_name = input("请输入要删除的商品名称：")

            if goods_name not in shopping_cart:
                print("该商品不存在，请重新选择要执行的操作")
            else:
                del shopping_cart[goods_name]
                print("商品删除完毕")

        case "4":
            for goods_name in shopping_cart.keys():
                goods_info = shopping_cart[goods_name]
                print(f"商品名称：{goods_name}，商品价格：{goods_info['price']}，商品数量：{goods_info['number']}")

        case "5":
            print("拜拜")
            break

        case _:
            print("非法操作，不支持")
```

从头到尾只用了两样东西：一个是字典，装着整个购物车；一个是 `match`，把用户敲的数字分派到五个分支上。增删改查这四类操作，在这里全部落地了一次。
