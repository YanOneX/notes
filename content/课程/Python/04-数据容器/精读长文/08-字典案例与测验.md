# 购物车跑通之后，字典才算真的学会

购物车系统的代码敲完，不等于这个案例做完了。架子搭起来之后，接下来第一件事是右键运行，一项一项去试，看它到底有没有问题；有问题，再回来修。

## 菜单转起来：先拿一个非法输入试探

运行之后，光标停在那儿等输入，提示只要 1~5 之间的数字。我第一个输的不是 1，也不是 2，而是 0。为什么先拿 0 开刀？菜单上的五个分支分别对应添加、修改、删除、查询、退出，0 一个也匹配不上，正好用它验一验最后那条“兜底”分支写没写对。

回车，屏幕上跳出“非法操作不支持”，紧接着整个菜单又打印了一遍，重新问我要执行哪个操作。这个反应是对的：打印菜单、读入编号、多分支判断这一整段都写在循环里，一轮走完不是结束，而是回到循环开头再走一遍，菜单自然又冒出来。

> **提示**：菜单类程序的骨架就三件事——打印菜单、读编号、按编号分支；想退出去只有一条路，让 `break` 把循环打断。

接着输 1，走“添加购物车”。商品名称填 `mate80`，价格 6999，数量 2，三次回车之后提示“商品添加完毕”，菜单第三次出现。既然刚加完，顺势输 4 查一下：商品名称 mate80、价格 6999、数量 2，一条不少。

再添一件：名称“茶叶”，价格 599，数量 1，添加完毕后再输 4，两条记录都在。到这里，添加和查询这两条路是通的。

轮到修改。输 2，程序问要修改哪个商品，我故意填了一个购物车里根本没有的名字——“矿泉水”。这时它的表现值得盯一下：它没有当场拦我，而是接着问价格，我填 2；再问数量，我填 5；等三样都收齐了，才回过头告诉我“该商品不存在，请重新选择”。

结论没错，过程别扭。一个人明明没有这件商品，却先被要求填一遍价格和数量，填完才被告知白填了。

## 把校验提到收数据之前

问题出在校验的位置太靠后。名称一输完就该判断：购物车里有没有这件商品？没有，提示一句，直接回到“请输入要修改的商品名称”，价格和数量一个都不用问。

改法很直接：找到修改购物车那一段，把原来压在后面的存在性判断整段剪切（`Ctrl + X`），挪到输入名称之后；提示信息照旧输出，然后补一句 `continue`。

`continue` 的作用是中断本次循环、直接进入下一次循环——当前这一轮剩下的代码一律跳过，于是又回到循环开头，重新问要改哪个商品。

```python
if name not in cart:
    print("该商品不存在，请重新选择")
    continue
```

判断前移之后，下面那段代码就有了一个新的前提：能走到这儿的，商品一定存在。既然一定存在，原来那个 `else` 就是多余的，删掉，价格、数量收完直接改。

> **易错点**：`continue` 和 `break` 只差一个词，效果正相反。`continue` 是“这一轮不干了，下一轮继续”，`break` 是“整个循环到此为止”。校验不过要的是前者。

## 重启之后，购物车为什么空了

改完代码，重新运行。第一件事照例输 4 查购物车——屏幕上什么也没有。

不是查询坏了。刚才添加的 `mate80` 和茶叶，是存在内存里的：字典、列表这些容器都活在当前这个进程里，程序一停，内存里那份数据就没了，重新运行是从一张白纸开始。

> **结论**：容器里的数据随进程生灭。想让它留下来，得写到文件里——这是后面讲文件操作要解决的事，眼下知道“重启即清空”就够了。

## 增删改查逐项过一遍

清空就清空，正好从头再验一遍，这次把改和删都走完。

先添两条：`mate80`，6999，2 件；茶叶，599，1 件。输 4 查，两条都在。

输 2 修改，商品名填“鼠标”——不存在，这回它立刻回“该商品不存在，请重新选择”，没有再问价格数量，说明 `continue` 生效了。再输 2，这次填对，茶叶；程序问最新价格，填 699（涨价了），数量从 1 改成 3，回车，“商品修改完毕”。再输 4 查，茶叶的价格和数量都变了。

删也一样。输 3，填“矿泉水”，不存在，删不了，提示后重新选；再输 3，填 `mate80`，“商品删除完毕”；输 4 复查，购物车里只剩茶叶。

最后输 5 退出。屏幕打一句“拜拜”，接着 `break` 打断循环，循环一结束程序就收尾了。

增、删、改、查、退出，五条路全通。这个案例能自己独立写出来，字典这种数据容器基本就没什么问题了——它考的从来不是某一个方法的名字，而是“用 key 找 value”这件事能不能落到一套完整的增删改查里。

## 五种数据容器摆在一张表里

到这里，Python 里常见的五种数据容器——字符串、列表、元组、集合、字典——就全部过完了。它们各自能装什么、有什么脾气，散在各节里看不出来，摆到一张表上才清楚。

| 容器 | 有序性 | 元素可否重复 | 可变性 | 索引访问 | 切片 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 字符串 `str` | 有序 | 允许 | 不可变 | 支持 | 支持 | 文本处理 |
| 列表 `list` | 有序 | 允许 | 可变 | 支持 | 支持 | 一批允许重复、需要增删改的数据 |
| 元组 `tuple` | 有序 | 允许 | 不可变 | 支持 | 支持 | 一批不允许修改、允许重复的数据 |
| 集合 `set` | 无序 | 不允许 | 可变 | 不支持 | 不支持 | 去重：身份证号、手机号、银行卡号 |
| 字典 `dict` | key 有序（3.7 起） | key 不可重复，value 可重复 | 可变 | 不支持 | 不支持 | 键值对形式的数据 |

六个维度：有序性、能否重复、可变性、是否支持索引、是否支持切片、典型场景。下面一列一列说。

## 六个维度逐个看

### 有序性

五种里只有集合是无序的，其余都占“有序”这一格。字符串、列表、元组好理解——存进去什么顺序，取出来还是什么顺序。

字典要单独说一句：Python 3.7 之后，字典里存进去的 key 也是有序的，想验证的话自己敲两行试试就知道。

但这件事对我们几乎没影响。访问字典靠的是 key，不是下标；有序也好无序也罢，取 value 的写法一个字都不用改。知道它有这个性质就行，不必围着它去设计代码。

### 能不能有重复元素

字符串、列表、元组都允许重复，同一个值出现几次都行。集合不允许，这是它区别于其他四种最大的特点，也是它存在的理由。

字典要拆成两半看：value 可以重复，key 不行。key 一旦重复，后面的会把前面的覆盖掉，字典里最后只留下一条。

> **提示**：字典的 key 相当于这组数据的“身份证号”，一个号只能对应一个人，重复登记的结果就是覆盖前一条。

### 可变与不可变

字符串和元组不可变：一旦定义好，里面的元素就不允许再动。列表、集合、字典可变，增、删、改都支持。

判断一个容器可变不可变，有个很实用的角度：如果你需要“改其中某一个元素”，那就只能在列表、集合、字典里挑；字符串和元组一旦落笔，就是定稿。

### 索引访问与切片

字符串、列表、元组支持索引访问，也就是下标，正向从 0 开始，反向从 -1 开始。既然能按下标取到元素，切片自然也就成立——能截出字符串、列表、元组里的一段。

集合和字典不支持索引访问。集合是无序的，压根没有“第几个”这种说法；字典按 key 取值，也没有下标可给。这两个既然不能按下标取元素，切片也就无从谈起。

## 什么场景选什么容器

特点分清楚了，选型就不用死记，是推出来的。

处理文本，用字符串。

要存一批数据，就在列表、元组、集合之间挑，挑的标准只有两问：这批数据允许重复吗？需要改动吗？

- 允许重复、而且要改 → 列表。日常用得最多，就因为它同时满足这两个条件。
- 允许重复、但不许改 → 元组。定稿的数据交给它，谁也动不了。
- 不允许重复、要去重 → 集合。存用户的身份证号、手机号、银行卡号这类东西，天然不该重复，交给 `set` 最省心。

要存的是“一个对一个”的对应关系，用字典——它本来就是为键值对准备的。

> **结论**：选容器不靠背，靠两句自问——会不会重复？要不要改？答案一出来，容器就定了。

## 函数是什么：手机里已经装好的功能

数据存储与运算、数据的逻辑处理、数据存储容器，核心语法的前三个部分学完，第四个部分是函数。

“函数”这个词前面出现过很多次，只是一直没展开。它的定义是一句话：组织好的、可以重复使用的、用来实现特定功能的代码片段。拆开就是三层意思——它是一段代码；这段代码有明确的功能；这段代码能被反复使用。

拿手机打比方。手机出厂就集成了打电话、发短信、拍照这些功能，都已经提前装好。要打电话，打开手机、输入号码、通话；下一次再打，还是输入号码、通话。功能本身不用你重新造一遍，你只是“用”它。

函数就是这个角色：功能提前组织好，谁要用谁调用，调一次用一次。

前面其实一直在用函数。要接收键盘录入，调 `input`；要往控制台输出，调 `print`。`max` 求最大值、`min` 求最小值、`len` 取元素个数、`sum` 求和，也全是函数。这些叫内置函数——Python 底层提前定义好、写在源代码里的，实现细节不用我们操心，直接调用就能拿到结果。

内置的再好用，也总有它没覆盖的需求。想把自己写的一段功能也变成“随叫随到”的东西，就得自己定义函数。所以函数这一章分两块：基础讲怎么定义、怎么调用；进阶讲更高级的用法。基础这一块先解决两件事——怎么把一段代码封装成函数，封装好之后怎么用。

## 定义一个函数

语法长这样：

```python
def 函数名(参数列表):
    函数体
    return 返回值
```

一处一处看：

- `def` 是定义函数的关键字，一个都不能少。
- 紧跟其后的是函数名。命名规则和变量名完全一致——它们同属标识符，只能由数字、字母、下划线组成，且不能以数字开头。
- 括号里是参数列表，指的是将来调用这个函数时可以传进来的数据。
- 括号后面跟一个冒号，冒号之后换行、缩进，缩进的部分叫函数体，这个函数要干的活全写在这儿。
- `return` 用来指定返回值：函数执行完需要交出结果时，就靠它。

> **提示**：参数列表和 `return` 都是可有可无的，由具体需求决定。没有参数就写一对空括号，不需要返回结果就不写 `return`。

看个例子，一个只负责输出分隔线的函数：

```python
def outline():
    print("----------------------------------------")
    print("----------------------------------------")
```

`outline` 就是“画一条外框线”的意思。括号里空着，参数留到后面再讲，这里先看最基础的结构；函数体两行 `print`，每行输出一串横杠，合起来就是一条分隔线。注意函数体里照样可以调用别的函数——`print` 自己就是一个函数。

缩进在这里不是排版，是语法。两行都缩进，才都算这个函数的函数体；要是第二行顶格写，它就跟这个函数没关系了，是函数外面独立的一句。

> **注意**：函数体有几行，前面就得有几行缩进。少一个缩进，代码的归属就变了。

定义敲完，右键运行——控制台一片空白。文件确实跑了，但一个字也没输出。

## 先定义，后调用

因为定义只是把这段代码“登记”到一个名字上，并不会执行它。函数体里的代码什么时候跑？被调用的时候。

调用语法也就一句话：函数名后面跟一对括号，有参数就把参数塞进括号里。

```python
outline()
```

再运行，两道横线出来了。调一次，函数体执行一次；写下三行 `outline()`，出来六道横杠——每次调用输出两行，三次正好六行。一段重复的逻辑就这么被收进函数里，往后要用，写个名字加一对括号就够了。

调用还有一条铁律：先定义，后调用。把 `outline()` 挪到 `def` 上面试试，编辑器立刻标出问题，运行报 `NameError: name 'outline' is not defined`。原因不复杂：解释器从上往下一行行执行，走到调用那一行时，它还没见过 `outline` 这个名字，自然找不到。挪回定义下面，一切正常。

> **结论**：定义在前、调用在后，是解释器的执行顺序决定的，不是风格偏好。

三件事记牢：

1. 先定义，再调用；
2. 定义时不执行，调用时才执行；
3. 函数体有多行代码时，靠缩进表明归属。

参数怎么指定、返回值怎么给，是接下来要解决的问题。

## 本讲提到的题目

**题干**：开发一个教务管理系统，用来维护和管理学员的成绩信息。系统提供七项功能，用一个七项菜单让用户输入编号来选择要执行的操作：

1. 添加学生信息
2. 修改学生信息
3. 删除学生信息
4. 查询学生信息
5. 列出所有学生
6. 统计班级成绩
7. 退出系统

**解析**：这题和购物车案例是同一个骨架——外层一个循环反复打印菜单，内层一串分支按编号分流，选中退出项就用 `break` 跳出。数据组织也照搬：一条记录用一个字典描述，所有记录装进一个列表，增、删、改、查全都落在这个列表上。前五项与购物车一一对应，多出来的“统计班级成绩”，无非是对一批成绩再做一次汇总，求最大、求最小、求和、求个数这些内置函数前面都练过。
