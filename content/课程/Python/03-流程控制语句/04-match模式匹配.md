# match 模式匹配

### 语法与流程

* **match...case（结构模式匹配）**
* > **定义**：用一个清晰的模板去匹配数据的结构与内容，匹配成功后才执行对应分支。
* 语法 `match 表达式:`，冒号下挂一串 `case 值:`；所有 `case` 彼此平齐，每个 `case` 底下的语句再缩进一层。
* 比 `if` 省掉重复的 `变量 ==`：`case "1":` 直接写要匹配的内容。
* 「结构」指它不仅比对内容，也能比对数据的形状，这一点在匹配列表、字典这类复合数据时显现。

* **匹配流程**
* 先算出 `match` 后面表达式的值，再从上往下与各 `case` 后的值逐一比较。
* 命中一个 `case` 就执行它下面的语句，执行完整个 `match` 结构立即结束，后面的 `case` 一概不再看。
* 全都不命中时落到 `case _` 兜底；没有兜底则什么都不做。
* 星期日程例：输入 1 命中 `case "1"` 打印周一工作会议，输入 6 或 7 命中 `case "6" | "7"` 打印周末休息，输入 9 落到 `case _` 打印输入有误。
* > **易错点**：`input()` 取回的是字符串，`case` 后面也要写带引号的字符串；写成 `case 1:` 与 `"1"` 类型不同，永远匹配不中。

* **四则运算计算器**
* 三次录入：`number1 = float(input(...))`、`number2 = float(input(...))`、`oper = input(...)`。
* `match oper:` 下挂 `+`、`-`、`*`、`/` 四个分支，末尾 `case _` 提示「操作不支持」。
* 骨架阶段各 `case` 里先写 `pass` 占位，逻辑想清楚再填。
* 格式化串 `f"{number1} + {number2} = {number1 + number2}"` 里，大括号外的 `+` 是原样输出的字符，大括号内的 `+` 才是算术运算符。
* 输入 10、5、`*` 得 `10.0 * 5.0 = 50.0`；输入 10、2、`/` 得 `5.0`。

### 特殊写法

* **竖线 `|` 匹配多个值**
* `case "6" | "7":` 表示值等于 6 或 7 都命中同一支，执行同一段操作。
* 要匹配的项再多，继续用竖线往下串。

* **下划线 `_` 兜底**
* `case _` 匹配前面都没对上的所有情况，作用等同 `if` 里的 `else`。
* 兜底分支可有可无，写不写看需求；存在「其他情况」时写上更稳妥。
* > **易错点**：下划线不带引号，写成 `case "_"` 就变成匹配一个下划线字符，语义完全变了。

### 条件守卫

* **case 后的 if 守卫**
* 写法 `case "/" if number2 != 0:`：值相等且 `if` 条件成立，这一支才算匹配上。
* `if` 条件不成立就当作没匹配上，继续往下比，最终可落到 `case _`。

* **除数为零**
* `10 / 0` 会抛 `ZeroDivisionError: division by zero`；10 是被除数、0 是除数，报错只与除数为 0 有关。
* 需求上这属于「操作不支持」，应当由守卫拦下并落进 `case _` 给出提示，而不是让程序崩掉。

### 与 if 的分工

* **版本限制**
* `match` / `case` 是 Python 3.10 才加入的语法，放到早期版本上运行会直接报语法错误。

* **适用边界**
* 变量去匹配若干固定值（等值匹配）用 `match` / `case`。
* 范围比较（如分数在 60 到 70 之间）、用 `and` / `or` 组合的条件，`match` 无能为力，仍要用 `if` / `elif`。

| 要判断的事情 | 更合适的写法 |
| :--- | :--- |
| 变量匹配若干固定值（等值匹配） | `match` / `case` |
| 范围的比较 | `if` / `elif` |
| 多个条件组合起来判断 | `if` / `elif` |
