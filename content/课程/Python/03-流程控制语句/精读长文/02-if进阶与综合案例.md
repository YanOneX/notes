# 多分支与嵌套：elif 与 if 套 if

## 从一个"不考虑零"的练习说起

四个练习里，第三个最先被拎出来讲。需求很短：判断用户输入的数字是正数还是负数，题目后面还专门缀了一句——不考虑零。

不考虑零，一个数字就只剩两种可能：要么正，要么负。这种"非此即彼"的场面，上一节的 `if...else` 正好够用：条件成立输出正数，不成立输出负数，两条路，没有第三条。

可偏偏有人要多问一句：如果零也得管呢？

这一问，问题就变味了。数字变成三种身份——正数、负数、零。判断的时候，第一个条件问"大于零吗"，成立就是正数；不成立还得接着问"小于零吗"，成立是负数；两条都不成立，才轮到零。

数一数，这里出现了两个条件判断。

## if...else 为什么接不住三个分支

`if...else` 的结构是什么样，上一节已经拆过：`if` 后面写一个条件，条件成立走操作一，不成立就进 `else` 走操作二。

问题就出在这"一个条件"上。`if` 后面只能挂一个条件，`else` 又没有资格带条件——它只是个"否则"，是兜底的那条路。你想在"否则"之后再问一句"那如果是小于零呢"，没地方问。

所以要判断正、负、零三件事，`if...else` 已经不够用了。不是写法上别扭，是这套结构本身就只有两条出口。

> **结论**：`if...else` 只处理"成立 / 不成立"两种情况。一旦分支超过两条，就得换一种能挂多个条件的结构。

## elif：多出来的那条分支

Python 给的结构叫 `if...elif...else`。那个 `elif`，其实是 `else if` 的简写，读的时候读成"else if"就行。

> **定义**：`if...elif...else` 专门用来做多条件判断——`if` 挂第一个条件，`elif` 接着往上挂更多的条件，分支数量不再受"两条"的限制。

结构长这样：

```text
if 条件一:
    操作一
elif 条件二:
    操作二
elif 条件三:
    操作三
...
else:
    操作N
```

`if` 先起头，写第一个条件；后面用 `elif` 一个一个往上挂条件；最后可以跟一个 `else`，兜住"前面所有条件都不成立"的情况。

两个地方要注意：

- `elif` 可以出现很多次。业务里有几个分支，就挂几个 `elif`，写十个八个都行；
- `else` 可有可无。所有分支都能被 `elif` 的条件覆盖干净，`else` 就可以不写；但只要写了，它必须放在最后。

## 执行流程：一条路走到黑

多个条件挂在同一个结构上，执行时并不是每个条件都算一遍。它从上往下问，问到第一个"成立"的就停下来，把那条分支的代码执行完，整个结构就结束了。

```text
判断条件一
   │
   ├── 成立 ──→ 执行操作一 ──→ 结束
   │
   └── 不成立
          │
          └── 判断条件二
                 │
                 ├── 成立 ──→ 执行操作二 ──→ 结束
                 │
                 └── 不成立 ──→ 执行 else 里的操作三 ──→ 结束
```

读这张图只要记一句话：条件一成立，操作一执行完就直接出门，后面的 `elif` 和 `else` 一个都不会碰；只有条件一不成立，才有资格去问条件二；条件一、条件二都不成立，才落进 `else`。

这就是"多分支"和"多判断"的区别。三个条件摆在那里，但每次运行只会走其中一条路。

## 在 PyCharm 里写正数、负数、零

需求清楚了，代码就好写。先接收输入，`input()` 拿回来的是字符串，既然要比较大小，就得先转成整数：

```python
number = int(input("输入数字："))

if number > 0:
    print(f"{number} 是一个正数")
elif number < 0:
    print(f"{number} 是一个负数")
else:
    print(f"{number} 是零")
```

三段的职责很分明：

- `number > 0` 是第一个条件，成立就打印正数；
- `number < 0` 挂在 `elif` 上，只有第一个条件不成立时才会被问到；
- `else` 不写条件，它是"前面都不成立"的出口，剩下的可能只有零。

> **易错点**：`else` 后面不要再写条件。它的语义就是"剩下的全归我"，一旦给它加了条件，它就不再是 `else` 了。

跑一遍。输入 `5`，第一个条件成立，打印"5 是一个正数"，`elif` 和 `else` 连看都不看。输入 `-1`，第一个条件不成立，往下问第二个条件，`-1 < 0` 成立，打印"-1 是一个负数"，`else` 不执行。输入 `0`，两个条件都不成立，落进 `else`，打印"0 是零"。

三条路，各走一次，都对上了。

## 顶格对齐：elif 不是 if 的下一层

写这段代码时有个地方特别容易歪。

在 `if` 的代码块里敲完 `print`，回车，光标会自动缩进到下一层。这时候如果顺手就在缩进的位置写下 `elif`，那这个 `elif` 就变成了 `if` 内部的语句——它不再是"另一个条件"，而是"条件成立之后才轮得到的下一句"。

```python
# 错的写法：elif 被缩进到了 if 里面
if number > 0:
    print(f"{number} 是一个正数")
    elif number < 0:
        print(f"{number} 是一个负数")
```

`if`、`elif`、`else` 这三者必须顶格对齐，处在同一列上，它们才是一套结构里的三个分支。缩进一旦不同，层级就变了，`elif` 会被当成 `if` 里面的东西，语法直接报错。

> **提示**：判断 `elif` 归谁管，看它和哪个 `if` 左对齐。左对齐的那个 `if` 就是它的上级；缩进进去的，就成了别人的下级。

## 登录案例：三套账号

语法演示完，换一个更像真实业务的需求：根据输入的用户名和密码做系统登录。

规则里给了三组合法的账号——用户名 `admin`、密码 `666888`；用户名 `root`、密码 `547527`；用户名 `张三`、密码 `123456`。命中其中任意一组就是登录成功，其余的统统提示用户名或密码错误。

为什么要有三组？因为真实的系统里，合法的用户名和密码本来就可能有多套。这不是一道"猜密码"的题，而是"多套凭证里任意一套匹配即可"的判断。

先接收两个输入：

```python
username = input("请输入用户名：")
password = input("请输入密码：")
```

然后判断。一组账号是"用户名对"并且"密码也对"，两个条件同时成立才算数，所以用 `and` 连起来：

```python
if username == "admin" and password == "666888":
    print("登录成功 1")
elif username == "root" and password == "547527":
    print("登录成功 2")
elif username == "张三" and password == "123456":
    print("登录成功 3")
else:
    print("登录失败，用户名或密码错误")
```

第一组判断不成立，才有机会问第二组；第二组也不成立，才问第三组；三组全不成立，才进 `else`。`elif` 在这里连着挂了两次，正是它"可以出现多次"的用法。

> **易错点**：一组账号内部的两个条件是"并且"的关系，必须用 `and`。写成 `or`，就变成"用户名对就行，或者密码对就行"，只输对一半也能登录，逻辑就漏了。

测试的时候可以给三句"登录成功"分别加上不同的编号，方便看清到底是哪一条分支在跑。输入 `admin` / `666888`，打印"登录成功 1"；输入 `张三` / `123456`，前两组都不成立，第三组命中，打印"登录成功 3"；输入 `aa` / `111`，三组全落空，落进 `else`，打印"登录失败，用户名或密码错误"。

## elif 的三条注意事项

这段语法收尾时，值得记住的就三条：

| 注意点 | 具体说法 |
| :--- | :--- |
| `elif` 的数量 | 可以写多个，业务里有几个分支就挂几个 |
| `else` 的位置 | 可有可无；写了就必须放在最后，后面不能再接 `elif` |
| 判断的顺序 | 从上往下依次判断；前面某条成立了，后面的条件不再判断、代码也不再执行 |

第三条最容易被忽略。它不是"所有条件都算一遍再挑一个"，而是"问到第一个成立的就走人"。所以 `elif` 的排列顺序本身带着优先级：越靠前的条件越先被问，也越容易把后面的情况"吃掉"。写多分支时，顺序不是随便摆的。

## 三角形案例：先判能不能构成，再判是什么形状

`if` 的核心语法到这里就算学完了，接下来用一个案例把它们串起来。

需求：输入三角形的三条边长，判断它是等边三角形、等腰三角形、普通三角形，还是这三条边根本构不成三角形。

要写代码，先得把两件事想清楚。

第一件，什么样的三条边能构成三角形？回到小学数学：任意两边之和要大于第三边。注意"任意"两个字——不是随便挑两条边加起来比一比就行。

第二件，能构成三角形之后，怎么分类型？三条边都相等是等边三角形；其中两条边相等是等腰三角形；三条边都不相等是普通三角形。

这两条规则一摆，判断的层次也就出来了：先用"能不能构成"卡一道，能构成的再进去分形状，构不成的直接给个提示。这正是 `if` 嵌套的用武之地。

## 注释：从井号到三引号

写这个案例之前，先补一个顺手的小知识：注释。

单行注释用 `#`，注释的是这一行的内容。要多行注释，最朴素的办法是每一行前面都加一个 `#`，一行一行加。在 PyCharm 里也可以用 `Ctrl + /` 批量加上或取消。

但大段文字这么加，屏幕上全是井号，看着乱。Python 里还有一种更清爽的写法——三引号：

```python
"""
这里是一大段说明文字
可以跨很多行
不用每行都加井号
"""
```

三引号本来是定义字符串的第三种方式。前面没有变量去接它，它就只是一段没人用的字符串，效果等同于注释；前面要是有个变量接住，那它就是货真价实的字符串。

> **提示**：三引号注释的本质是"一个没有被赋值的字符串"。所以它通常整段放在语句的位置上，而 `#` 可以缀在任意一行代码的末尾。

以后遇到整段的说明、需求描述、判定规则，用三引号包起来，结构比一行行加井号清楚得多。

## 先把"不能构成"挡在门外

按需求，第一步接收三条边的边长。题目说了输入的都是正整数，那就直接转成整数，三条边分别叫 `a`、`b`、`c`：

```python
a = int(input("请输入第一个边的边长："))
b = int(input("请输入第二个边的边长："))
c = int(input("请输入第三个边的边长："))
```

第二步判断。判断形状之前，必须先确认这三条边能不能组成三角形——组不成的，后面那些等边、等腰的判断根本没有意义。

构成三角形的条件是"任意两边之和大于第三边"，翻成代码就是三个式子同时成立：

```python
if a + b > c and a + c > b and b + c > a:
    pass
else:
    print(f"三条边长 {a}、{b}、{c} 不能构成三角形")
```

这里有个特别值得停一下的地方：为什么三个式子一个都不能少？

只写 `a + b > c`，只能保证 a 和 b 加起来比 c 长，可 a 和 c 加起来未必比 b 长——那种情况依然构不成三角形。三条边两两组合，一共三组，三组都得满足。少了任何一组，"任意"两个字就落空了。

> **易错点**：判断构成三角形时，三个不等式必须用 `and` 全部连上。漏掉一组是最典型的错误写法，而且它不会报错，只会在某些输入下悄悄给出错误答案。

`if` 里面现在写的是 `pass`。这是个空语句，什么都不做，纯粹占个位置。因为 `if` 的条件成立之后必须跟代码块，而形状判断的逻辑要等会儿才写，先用 `pass` 把结构撑住，语法才不会报错。

> **定义**：`pass` 是空语句，起语法占位的作用。它不执行任何操作，只是告诉解释器"这里有一块代码，暂时是空的"。

## 嵌套 if：形状判断放进内层

`pass` 的位置，就是判断形状的位置。能构成三角形，才轮到分类型。

判断形状又是条件判断，所以里面继续写 `if`——`if` 套 `if`，这就是嵌套。

先判等边。三条边都相等，得同时满足 `a == b` 和 `b == c`：

```python
if a == b and b == c:
    print(f"三条边长 {a}、{b}、{c} 构成等边三角形")
```

不成立，再判等腰。等腰只要"有两条边相等"，三种组合里命中任意一种就行，所以用 `or`：

```python
elif a == b or b == c or a == c:
    print(f"三条边长 {a}、{b}、{c} 构成等腰三角形")
```

这里 `and` 和 `or` 的选择正是关键：等边要求"三条都相等"，是并且；等腰要求"任意两条相等"，是或者。开发工具可能会顺手提示补成 `and`，但那会把等腰判成"三条都相等"，等于把等腰三角形全判丢了。

最后一个分支不用再写条件。前面两个都不成立，说明三条边互不相等，那必然是普通三角形，直接 `else`：

```python
else:
    print(f"三条边长 {a}、{b}、{c} 构成普通三角形")
```

合起来，完整的代码如下：

```python
a = int(input("请输入第一个边的边长："))
b = int(input("请输入第二个边的边长："))
c = int(input("请输入第三个边的边长："))

if a + b > c and a + c > b and b + c > a:
    if a == b and b == c:
        print(f"三条边长 {a}、{b}、{c} 构成等边三角形")
    elif a == b or b == c or a == c:
        print(f"三条边长 {a}、{b}、{c} 构成等腰三角形")
    else:
        print(f"三条边长 {a}、{b}、{c} 构成普通三角形")
else:
    print(f"三条边长 {a}、{b}、{c} 不能构成三角形")
```

外层的 `if...else` 管"能不能构成"，内层的 `if...elif...else` 管"是什么形状"。两层各管一件事，互不干扰。

需要的话，内层还能继续往下嵌。业务里有更细的分支，再套一层 `if` 一样可以，嵌套的层数本身没有限制——限制你的是可读性。

## 缩进就是层级

这段代码比前面几段长，也就更容易在缩进上翻车。

```text
if 能构成三角形:
    if 三边都相等:
        等边三角形
    elif 任意两边相等:
        等腰三角形
    else:
        普通三角形
else:
    不能构成三角形
```

往里缩一层的那组 `if`、`elif`、`else` 是一套，退回到最外层的那组 `if`、`else` 是另一套。同一套里的三个关键字缩进必须完全一致，不同套之间靠缩进拉开层次——外层的 `if` 和 `else` 左对齐，内层的 `if`、`elif`、`else` 也左对齐，只是整体往里多缩了一层。

缩进错了，`else` 就会认错主人——本来该配外层的 `else`，缩进退一格，就变成了内层 `if` 的兜底，逻辑瞬间改味。

> **提示**：`else` 永远属于"和它左对齐的那个 `if`"。读别人代码时，顺着这一列往上看，就能确定它兜的是哪一段。

## 用调试模式跟一遍执行过程

代码写完，直接点运行也能看到结果，但这段逻辑分支多，光看输出不容易确认"它到底走了哪条路"。这时候用调试模式，让程序一步一步走给你看。

调试模式（debug）跟普通运行的区别在于：代码跑到断点就停下来，等你下指令。

在关键行——也就是第一次做条件判断的那一行——打个断点。把鼠标移到行号左边，点一下会出现一个小圆点，这就是断点；再点一下取消。然后选择调试模式运行，而不是平时那个直接运行。PyCharm 工具栏上第一个按钮是正常运行，旁边那个带小虫子的就是调试运行。

第一次测试，输入 `10`、`5`、`3`。回车之后，打断点的那一行被蓝色背景盖住，意思是程序停在这里了，还没往下走。下面的调试面板里能看到 `a`、`b`、`c` 三个变量的值：10、5、3，都是 `int` 类型。

按一下调试面板里的单步按钮（那个拐角的箭头），或者直接按 `F8`，程序往下走一步。`5 + 3 = 8`，比 10 小，`a + b > c` 不成立，整个条件为假，于是直接跳进 `else`。再按一次，打印"三条边长 10、5、3 不能构成三角形"。蓝色高亮停在哪个行号，程序就走到哪一行，路径一目了然。

第二次测试，输入 `18`、`15`、`13`。三条边任意两边之和都大于第三边，条件成立，单步之后蓝色高亮进入内层 `if`——它没有进 `else`，说明"能构成"这一关过了。

进去之后第一个条件问三边是否都相等，18、15、13 三个数两两都不相等，条件不成立，往下走到 `elif`；`elif` 判断任意两边是否相等，也不成立，再往下走一步，落进内层的 `else`，打印"构成普通三角形"。

第三次测试，输入 `18`、`18`、`19`。外层条件成立，进入内层；第一个条件不成立，走到 `elif`；`a == b` 成立，`elif` 命中，直接打印"构成等腰三角形"，后面的 `else` 不再执行。

三次测试走过的路径，用一张表记下来最清楚：

| 输入（a, b, c） | 外层判断 | 内层走向 | 输出 |
| :--- | :--- | :--- | :--- |
| 10, 5, 3 | 不成立 | 不进入 | 不能构成三角形 |
| 18, 15, 13 | 成立 | 内层 `else` | 普通三角形 |
| 18, 18, 19 | 成立 | 内层 `elif` | 等腰三角形 |

三条路径各走了一遍，输出都对得上，说明逻辑没问题。测试完记得把断点再点一下取消——不取消的话，下次调试还会停在那儿；普通运行则不受断点影响。

调试模式在后面还会反复用到，现在先记住两件事就够：断点让程序停在你想看的地方，`F8` 让它往下走一步。

- **判断正数还是负数**（四个练习中的第三个）：输入一个数字，判断它是正数还是负数，题目注明不考虑零。课上没有给出这一题的代码，正文里那段判断正、负、零的三分支，是把它扩展成"要考虑零"之后写出来的。
- **课后的两个需求**：具体要求写在幻灯片里，课上没有逐条展开，这里也不替它补题；按资料里的描述完成，做完对照在线讲义提供的参考答案。
- **北京市居民年度用电电费计算**：根据输入的用电度数算出对应电费，计价规则同样在幻灯片里给出，课上没有念出来。做完可以对照资料里的参考答案。
