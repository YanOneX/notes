# 让代码学会拐弯：if 与 if...else

我们前面写过的所有 Python 代码，其实都没有什么逻辑。代码是从上往下写的，运行的时候也是从上往下一行一行执行，第一行做完做第二行，中间不打一个弯。练语法的时候这样写没问题，可真到了做项目，情况完全不是这样。

拿 B 站登录来说。你在登录框里把账号和密码敲进去，点一下"登录"按钮，程序就要去执行登录操作了。那么问题来了：是点一下就直接登录成功、直接进首页吗？不是。它得先判断你输入的账号和密码对不对。对了，登录成功，进首页；不对，登录失败，还得弹一句"用户名或密码错了"给你看。这时候你再想，进首页那段代码和提示错误那段代码，能是从上往下挨着执行的吗？先恭喜你进首页，再骂你密码错了？显然不是——程序只会走其中一条路。

再看一个场景。进了 B 站首页，顶上有一组图片一直在循环播放，我们叫它轮播图。这组图大概八九张，播完一遍，从头再来一遍；第二遍播完，再播第三遍；第三遍播完，接着播第四遍，就这么一直循环着走。还有大家天天用的音乐播放器、视频播放器，上面那个按钮点一下是单曲循环，再点一下是列表循环。单曲循环是什么样？就这一首歌，放完了倒回来再放，放完了再放，一直循环。那你想想，写播放歌曲那段代码，底层是不是一直在循环着跑？

> **结论**：程序里的逻辑处理，说到底就两件事——**该不该做**（条件判断）和**做多少遍**（循环）。

在 Python 里，承担这两件事的东西叫流程控制语句，主要分三类：条件判断、模式匹配、循环。模式匹配先放一放，先把条件判断拿下。条件判断在 Python 里是靠一个语句实现的，就是 `if`，所以也叫 if 条件判断。

## if 的样子：条件、冒号、缩进

if 条件判断的应用场景说起来只有一句话：**只有在满足指定条件时，才执行对应的代码逻辑**。刚才 B 站登录不就是这样——只有在用户名和密码都正确的情况下，才执行"进入 B 站首页"那一段。

它的语法格式长这样：

```python
if 要判断的条件:
    条件成立时要执行的代码
```

`if` 是一个关键字，写完 `if` 加一个空格，空格后面写要判断的条件；条件写完，后面跟一个冒号；冒号下面另起一行，缩进着写条件成立时要做的事。

格式就这么三行，但有三处地方特别容易出问题，一个一个说。

第一处，**条件的判断结果必须是布尔值**，要么 `True`，要么 `False`，没有别的可能。结果是 `True`，就代表条件成立，下面那行代码执行；结果是 `False`，就代表条件不成立，下面那块代码一行都不会执行。

> **易错点**：条件写出来的是个表达式，但这个表达式算完必须能落到 `True` 或 `False` 上。`score > 680` 这种比较运算的结果天然就是布尔值，所以可以直接往里塞。

第二处，**条件后面的冒号**。这个冒号是语法的一部分，漏了直接报错。而且是英文符号——中文输入法下打出来的那个"："不算。

第三处，**下面那行代码前面的缩进**。缩进几个空格不重要，一个、两个、三个、四个都行，但**必须得有**。有缩进，Python 才知道这行代码是归 `if` 管的；没缩进顶格写，那就是另一回事了。

不过"几个都行"只是语法层面成立。Python 的官方规范里，描述代码归属靠的就是缩进，所以建议统一用四个空格。四个空格一个一个敲太麻烦，直接按一下 Tab 键，PyCharm 会自动把它转成空格，默认转出来正好是四个。

> **定义**：`if` 加上它下面缩进的那几行代码，整体算一个**代码块**——一个独立的执行单元。往后我们还会碰到别的代码块，判断归属的办法都一样：看缩进。

## 缩进划出的地盘

光看格式还是虚的，举个具体的需求：**如果高考分数超过 680，我就去读清华**。

这句话里，条件是"高考分数超过 680"，条件成立后要执行的操作是"去读清华"。翻成代码：

```python
score = 700
if score > 680:
    print("欢迎你来清华读书")
```

`score > 680` 算出来是 `True`，条件成立，下面那句就执行了。幻灯片上举例时用的是 695 分，敲代码的时候我随手改成了 700，反正都过 680，效果一样。

条件成立之后只干一件事，当然不够劲，可以干两件：

```python
score = 700
if score > 680:
    print("欢迎你来清华读书")
    print("恭喜你即将踏入精彩的大学生活")
print("----------------")
```

两句 `print` 前面都有缩进，所以这两句都属于 if 的代码块，条件成立时一起执行。

关键在后面这一句 `print("----------------")`。它顶格写，前面没有缩进。那么问题来了：这个 `print` 属不属于 if 的代码块？

先别急着往下看，自己判一下。

答案是**不属于**。这个判断的标准特别硬：if 代码块里的代码，前面必须有缩进；这一行顶格，它就是独立的一句，跟 if 没有关系。

程序执行的时候是这样走的：从上往下，执行到 `if` 那一行，先去算条件成不成立；成立，就把 if 代码块里那两句执行掉，然后继续往下走，执行这道横线；不成立，if 代码块整个跳过，直接去执行那道横线。

把 `score` 改成 600 再跑一遍就看得清清楚楚：条件不成立，两句欢迎词一句都不输出，横线照样输出。因为横线压根不在 if 的地盘里。

> **易错点**：判断一行代码归谁管，只看缩进，不看它离得近不近。

缩进这件事还有一层坑。上面两句 `print` 都缩进了四个空格，没问题。可要是第二句手一抖，多缩进了一个空格呢？

```python
score = 700
if score > 680:
    print("欢迎你来清华读书")
     print("恭喜你即将踏入精彩的大学生活")
```

PyCharm 立刻标红，一运行就报缩进错误。为什么？因为多缩进一格，Python 会认为这句是"上面那个 `print` 下面的语句"，而 `print` 后面跟一个冒号再挂子语句这种写法根本不存在，语法上就不成立。

> **结论**：同一个代码块里的代码，缩进量必须完全一致。Python 靠缩进表示代码的层级关系和归属，这一条没有商量的余地。

## 案例：把 B 站登录写出来

语法演示完，拿一个真活儿练手——**模拟 B 站登录**。输入账号和密码，登录 B 站。这个案例正好把前面学的输入输出和刚学的 if 拼在一起用。

题目里已经给了正确的账号和密码：账号 `18888888888`，密码 `666888`。

先别急着敲代码，把过程捋一遍。输入完账号密码，点登录，程序要做判断：用户输入的账号跟正确的账号是不是一致，用户输入的密码跟正确的密码是不是一致。两个都一致，登录成功，进 B 站首页；只要有任何一个不一致——账号错、密码错、或者两个都错——就是登录失败，提示"账号或密码错误"。

拆成三步：

1. 通过键盘录入，接收用户输入的账号和密码；
2. 判断账号和密码是否全部正确，都正确则登录成功，进入 B 站首页；
3. 判断账号和密码是否有错误，有任何一个错误则登录失败，提示错误信息。

代码写出来是这样：

```python
# 正确的账号和密码
ok_account = "18888888888"
ok_password = "666888"

# 第一步：接收用户输入的账号和密码
account = input("请输入您的B站账号：")
password = input("请输入您的B站密码：")

# 第二步：判断账号和密码是否全部正确，如果都正确则登录成功
if account == ok_account and password == ok_password:
    print("登录成功")
    print("进入B站首页")

# 第三步：判断账号和密码是否有错误，如果有任何一个错误则登录失败
if account != ok_account or password != ok_password:
    print("登录失败")
    print("账号或密码错误")
```

第一步之前先定义两个变量，把正确的账号和密码存起来，一个叫 `ok_account`，一个叫 `ok_password`。变量名两个单词之间用下划线分隔，这是命名的习惯写法。存好之后，后面判断的时候直接拿用户输入的值跟它们比就行。

第二步的条件是这道题的核心：

```python
account == ok_account and password == ok_password
```

`account == ok_account` 判断账号对不对，`password == ok_password` 判断密码对不对。这两个表达式之间用什么连？用 `and`。因为"登录成功"要求两个条件同时成立：账号得对，**并且**密码也得对。`and` 两侧都是 `True`，整个表达式才是 `True`；只要有一侧是 `False`，结果就是 `False`。

第三步反过来，判断的是"错"：

```python
account != ok_account or password != ok_password
```

`!=` 是不等于，`account != ok_account` 意思是账号不对。两个条件之间用 `or` 连，因为登录失败的判定是"有任何一个错"——账号错也行，密码错也行，两个都错更行。`or` 只要有一侧是 `True`，整个表达式就是 `True`。

跑起来验证。第一次输入一个随便编的账号，密码老老实实敲 `666888`：

- `account` 和 `password` 拿到值之后，先走第二步。账号不对，`account == ok_account` 是 `False`；密码是对的，`password == ok_password` 是 `True`。可是中间是 `and`，两侧都得真才行，一侧假，整个就是 `False`。条件不成立，if 代码块跳过。
- 接着走第三步。账号不对，`account != ok_account` 是 `True`；密码是对的，`password != ok_password` 是 `False`。中间是 `or`，只要有一个真，整个就是 `True`。条件成立，输出"登录失败""账号或密码错误"。

第二次输入正确的账号 `18888888888` 和正确的密码 `666888`：第二步两个条件都真，`and` 的结果是 `True`，输出登录成功、进入首页；第三步两个条件都假，`or` 的结果是 `False`，底下那两句不执行。

功能是对的，该失败的时候失败，该成功的时候成功。

不过再盯一眼这段代码，两个 `if` 排在那儿，第二个是不是可以省掉？

## 两个 if 其实是多余的

为了实现一次登录，我们写了两个 if：第一个判断账号和密码是否都正确，第二个判断账号和密码是否有错。

从功能实现的角度说，这么写没问题，跑起来结果也对。但反过来想一个问题：登录这件事，结果是不是除了成功就是失败？账号密码都对，登录成功；否则，登录失败。要么成功，要么失败，没有第三个选项。

既然只有两种可能，那第一个 if 条件成立就是登录成功；条件不成立，剩下的唯一出路就是登录失败——这个"否则"根本不需要再判断一次。第二个 if 整个是白写的。

所以刚才那种写法略微繁琐，效率也不高：一次判断能定下来的事，非要算两遍。

## if...else：把"否则"写出来

针对这种"两条路二选一"的场景，Python 提供的是 `if...else`：

```python
if 条件:
    条件成立时执行的代码
else:
    条件不成立时执行的代码
```

if 后面的条件和刚才一模一样，该怎么写怎么写。区别在后面：条件成立，执行 if 下面的代码；条件不成立，程序自动转到 `else`，执行 else 下面的代码。

`else` 就是"否则"。而 else 后面**不用写任何条件**，直接跟一个冒号就完事——它压根不需要判断，它就是"if 不成立"时唯一的去处。

执行路径是这样分岔又合流的：

```text
              条件成立?
             /         \
          True         False
           |             |
      if 代码块      else 代码块
           \             /
            \           /
           继续往下执行
```

条件只有两个出口，走完任意一个出口，两条路又并回一条，接着往下执行。

> **易错点**：else 后面不要写条件，但冒号不能漏。

还有一处和 if 一样：else 下面那块代码同样要缩进。有缩进，才表示这几句归 else 管。

## 用 else 把登录重写一遍

把刚才的登录代码拿过来，前面定义变量、接收输入的部分一个字都不用动，只改下面那一截：

```python
# 正确的账号和密码
ok_account = "18888888888"
ok_password = "666888"

# 第一步：接收用户输入的账号和密码
account = input("请输入您的B站账号：")
password = input("请输入您的B站密码：")

# 第二步：判断账号和密码是否全部正确
if account == ok_account and password == ok_password:
    print("登录成功")
    print("进入B站首页")
else:
    print("登录失败")
    print("账号或密码错误")
```

原来的第三个步骤——再判断一次账号和密码有没有错——整段删掉，换成 `else`。逻辑立刻清楚了：账号密码都对，走 if；不对，走 else。不对的情况只有一种，没必要再问一遍"是不是错了"。

跑两遍验证。

第一遍，账号随便敲个 `99999`，密码老老实实给 `666888`。回车之后，账号明显不对，if 的条件算出来是 `False`，程序不进 if 代码块，直接落到 else 里，输出"登录失败""账号或密码错误"。

第二遍，账号 `18888888888`，密码 `666888`。两个条件都真，if 成立，输出"登录成功""进入B站首页"，else 那一块跳过。

跟上一版比，这一版少了一次条件判断，代码也短了一截。同样是二选一的场景，能用 else 承接的，就别再多写一个 if 去问反面的问题。

## 案例：闰年还是平年

换个跟登录没关系的场景练手：**根据用户输入的年份，判断这一年是闰年还是平年**。

闰年的判定规则有两条，得说清楚。

第一条针对非整百年份。像 2025、2026、2027 这种不是整百的年份，只要能被 4 整除就是闰年。所谓整百年份，是 1900、2000 这种末尾两个零的。

第二条针对整百年份。整百年份光能被 4 整除还不够，必须能被 400 整除才算闰年。这条规则不是多余的——1900 能被 4 整除，可它不是闰年。

列成表更清楚：

| 年份类型 | 判定条件 | 结论 |
| :--- | :--- | :--- |
| 非整百年份 | 能被 4 整除 | 闰年 |
| 非整百年份 | 不能被 4 整除 | 平年 |
| 整百年份 | 能被 400 整除 | 闰年 |
| 整百年份 | 不能被 400 整除 | 平年 |

代码：

```python
year = int(input("请输入需要判定的年份："))

if (year % 100 != 0 and year % 4 == 0) or (year % 400 == 0):
    print(f"{year}是闰年")
else:
    print(f"{year}是平年")
```

这个案例里麻烦的不是 if...else 的结构，而是那一长串条件。一段一段拆开看。

先看"非整百年份"。判断一个数是不是整百，用取余：`year % 100 != 0`，除以 100 有余数，就说明它不是整百。再看"能被 4 整除"，也是取余：`year % 4 == 0`，余数为零就是整除了。这两件事必须同时成立，中间用 `and` 连起来，这就是第一段条件。

再看第二段：`year % 400 == 0`。有同学会问，是不是还得补一句 `year % 100 == 0` 才算"整百年份"？不用。一个数都能被 400 整除了，它必然也能被 100 整除，必然是个整百年份，这个条件已经被"能被 400 整除"包含在里面了，再写一遍是废话。

最后把两段接起来。满足第一段是闰年，满足第二段也是闰年，两个之间是"或者"的关系，用 `or`。

前面这一段本身是一个整体——"非整百 **并且** 能被 4 整除"，用一对括号把它圈起来，"这是一个整体"的意思就一目了然了。后面那一段括不括都行，我当时也顺手括上了。`and` 的优先级本来就比 `or` 高，加不加括号算出来结果一样，但括起来读代码的人一眼就能看出层次。

还有一处不能忘：`input` 拿回来的是字符串，而这里要做取余，是算术运算，所以得先用 `int()` 把年份转成整数。少了这一步，`%` 直接报类型错误。

> **易错点**：`input()` 的返回值永远是字符串。要做算术，先转换。

真正跑之前还出了个小岔子：上面 B 站登录那段代码没注释，一点运行，程序就停在那儿等输入 B 站账号。先把运行停掉，把上面那段整体注释掉，再重新运行。

四个年份，一个一个测。

**2025 年**。非整百年份，2025 除以 4 余 1，不能被 4 整除，第一段是假；2025 除以 400 也有余数，第二段也是假。两个假，走 else，输出平年。

**1900 年**。这是整百年份，`1900 % 100 != 0` 不成立，所以第一段直接是假——注意，整百年份根本进不了第一条规则。再看第二段，1900 除以 400 余 300，不等于零，也是假。结果是平年。这就是"整百年份必须被 400 整除"这条规则存在的意义：要是不加这条，1900 会被 4 整除，就被误判成闰年了。

**2004 年**。非整百年份，`2004 % 4 == 0` 成立，第一段为真，`or` 一真即真，输出闰年。

**2400 年**。整百年份，第一段因为 `2400 % 100 != 0` 是假而落空；但第二段 `2400 % 400 == 0` 成立，`or` 一真即真，输出闰年。

四个测试全过。一个年份要么是闰年，要么是平年，就这两个选项，二选一——所以这里用 if...else 正合适，条件成立给闰年，否则给平年，不需要第三个分支。

到这里，if 的两种写法就齐了：只有"条件成立才做"的时候，一个 if 就够；"要么这样要么那样"的时候，用 if...else 把另一条路接住。剩下的功夫全在两件事上——把条件写对，把缩进对齐。

课后还留了四道 if...else 的练习题，题目内容没有在这段里展开，做之前先把闰年这个案例自己动手敲一遍，再去做那四道，手感会顺很多。
