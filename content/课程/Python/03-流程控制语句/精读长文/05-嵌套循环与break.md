# 从一张九九乘法表到猜数字：嵌套循环与控制关键字的实战

## 一张九九乘法表，先当成表格来看

嵌套循环的语法结构和执行流程讲清楚之后，得找个地方把它用起来。第一个要动手的东西，是小学就开始背的九九乘法表。

要打印成什么样子，是有明确样例的：第一行只有一句「一一得一」；第二行是「一二得二、二二得四」；第三行是「一三得三、二三得六、三三得九」；第四行是「一四得四、二四得八、三四十二、四四十六」。一直往下推，推到第九行就是「一九得九、二九十八……九九八十一」。看到这个形状，脑子里的第一反应通常是「不就是俩循环套一块儿吗」，可真正动手写，十有八九会卡在同一个地方：到底哪个数该跟谁走。

所以先别急着敲键盘。这张表本质上就是一张表格，用框把它一行一行圈出来，结构立刻就清楚了——一行一行往下排。而要写代码，要弄清楚的只有两件事：这张表有几行几列，以及乘号两边的数字各自听谁的。

### 乘数管行，被乘数管列

顺着每种表达式看一遍，规律就出来了。

先看每个表达式里的第二个数，也就是乘数。第一行里它是 1，第二行里它是 2，第三行里它是 3，第四行里是 4，第五行里是 5。所以这个乘数标的就是「当前处于第几行」。

再看第一个数，也就是被乘数。竖着扫一遍：第一列表达式的被乘数全是 1，第二列全是 2，第三列全是 3，第四列全是 4。所以被乘数标的是「当前处于第几列」。

> **结论**：九九乘法表的每个单元格里，第一个数是列号，第二个数是行号。写代码时这两个数的来历完全不同，混了就会写出错位的表。

### 九行九列，一行一行地输出

接着数清规模：九行、九列，最长那一行排到「九九八十一」。九行九列一共八十一个格子，但真正打印出来的只有四十五个——右上那半边是空的，第 3 行只有 3 个格子，第 4 行只有 4 个。

这里有个容易被跳过、却决定代码骨架的细节：输出这张表的时候，到底是一列一列地输出，还是一行一行地输出？

先自己回答一遍再往下看。答案是一行一行。打印的时候先打第一行，第一行打完再去打第二行，第二行打完再打第三行……屏幕上光标本来也只能往下走，你想一列一列地竖着填，反倒是跟输出设备的脾气对着干。

### 外层管行，内层管列

既然是一行一行输出，嵌套的两层循环就各有分工了。

外层循环负责「现在输出第几行」，它一次推进一行；内层循环负责「这一行里输出第几个单元格」，它在每一行内部一个接一个地把单元格铺满。而前面刚确认过：行号就是表达式里的第二个数（乘数），列号就是第一个数（被乘数）。所以外层循环控制的其实是第二个数，内层循环控制的其实是第一个数。

把这张表按行铺开看，两层循环的对应关系一目了然：

```text
           第1列    第2列    第3列    第4列   ...
第1行      1x1
第2行      1x2      2x2
第3行      1x3      2x3      3x3
第4行      1x4      2x4      3x4      4x4
...
第9行      1x9      2x9      3x9      4x9   ...   9x9

横向一排  = 内层循环走完一圈（列号 1 → 行号）
纵向一列  = 外层循环往前走一步（行号 1 → 9）
```

图上每一横排是内层循环跑完一遍的产物，从上往下一排排堆出来，就是外层循环一次次的推进。看出来了吧：内层循环的终点不是固定的 9，而是「当前是第几行」——第 3 行只铺 3 个格子，第 4 行只铺 4 个格子。这条规律是下一步写循环边界时唯一的依据。

## 把分析写成代码

分析完了就落地。因为行数、列数都是提前就知道的确定值，这一块直接用 `for` 循环，不必上 `while`。

```python
# 打印九九乘法表
for i in range(1, 10):          # 外层循环：控制行
    for j in range(1, i + 1):   # 内层循环：控制列
        print(f"{j}x{i}={j * i}", end="\t")
    print()
```

四行代码，每一处边界都是前面分析推出来的，没有一处可以随手改。

### range 的边界：为什么是 1 到 10

外层写 `for i in range(1, 10)`。开发工具很热情，刚敲下 `range` 就提示 `range(10)`，这个提示不能照收。

`range(10)` 生成的是 0 到 9，默认从 0 开始。而这张表的行号是从 1 起的，没有第 0 行。所以要把起点写成 1：`range(1, 10)` 表示从 1 开始、到 10 结束，而 `range` 是左闭右开、不含右端点的，于是真正取到的就是 1、2、3、4、5、6、7、8、9，正好九行。想写 1 到 9 又要写 10，看着别扭，但这正是 `range` 的规则，习惯就好。

内层变量名用 `j`，别跟外层的 `i` 重名——两个循环变量一旦撞名，内层会把外层的值覆盖掉，表就会打成一条竖线。

### 内层的终点为什么跟着 i 走

内层如果也写 `range(1, 10)`（开发工具给的提示也是这个），那每一行都会老老实实输出九列：第一行也九个、第二行也九个，表格右上角那片本该空着的地方会被填满，打出来是个九行九列的方阵，跟样例完全不是一回事。

实际要的列数由行号决定：`i` 是 1 就输出 1 列，`i` 是 2 就输出 2 列，`i` 是 3 就输出 3 列。所以内层的终点应当是 `i`。

> **易错点**：终点直接写 `i` 还是不行。`range` 不含右端点，第一行 `i` 等于 1 时 `range(1, 1)` 里一个数都没有，第一行会整个消失。必须写成 `range(1, i + 1)`，让右端点往后挪一格，第一行才取得到 1。

### 用 \t 把一行里的单元格隔开

单元格内容用格式化字符串拼：第一个数取内层变量 `j`，第二个数取外层变量 `i`，等号后面是两者相乘的结果，也就是 `f"{j}x{i}={j * i}"`。

乘号这一块用的是小写字母 `x`。想要真正漂亮的乘号 `×` 也不难：在输入法状态栏上点右键，打开符号大全，里面有各种各样的符号可以挑。这里就先用 `x` 顶着，不影响结果。

真正需要琢磨的是结尾那个 `end="\t"`。`print` 默认自带换行，每调用一次就换一行。可内层循环管的是列——同一行的几个单元格必须待在同一行上，一旦换行，一行就只剩一个表达式，表会被打成竖条。所以要给 `end` 换个值，把「换行」改成「制表符」：`end="\t"`，`\t` 就是转义字符里那个制表符，代表一个制表位宽度的间距。于是每输出一个表达式，后面跟一个制表位，同一行的相邻单元格之间就有了固定的空白，右端还能自动对齐。

若把 `\t` 去掉、只留 `end=""`，两个单元格之间一点空隙都没有，数字和字母挤成一坨，非常难看。这个对比可以自己改一次、跑一次，看一眼就记住了。

内层循环整圈跑完，这一行的单元格才算铺满，此时该换行了。所以在内层循环的下面、与外层循环体同级的那个缩进位置上，单独写一句 `print()`——利用它自带的换行，把光标送到下一行行首，外层循环接着打印下一行。

最终输出与样例逐行对照：一一得一；接着一二得二、二二得四；再一三得三、二三得六、三三得九；一四得四、二四得八、三四十二、四四十六……九行依次排下来，形状一致。

这一块的内容到这里就写完了。它是嵌套循环最典型的一道案例，值得先不看代码、自己把需求分析一遍，再动手实现——需求没理清楚就抄代码，抄完也不知道每行在干什么。写完之后还有几道图形题等着练手，放在文末说。

## 登录案例：不知道要循环几次的时候

`while`、`for`、嵌套循环都过完了，接下来用一组案例把语法真正用起来。第一个案例是登录：根据输入的用户名和密码执行登录操作。这个场景你们熟，每天都在各种网站上做同一件事。

### 五个要求摆在一起看

题目的要求一共五点，摆在一起读才能看出它的用意：

1. 系统里正确的用户名和密码有三组，见下表；
2. 用户输入用户名和密码登录，直到登录成功程序才结束运行；登录失败就继续输入，再次登录；
3. 输入的用户名和密码不能为空，为空就继续提示他输入正确的用户名和密码；
4. 登录成功要输出「登录成功，进入到B站首页」；
5. 登录失败要提示「用户名或密码错误，请重新输入」。

| 用户名 | 密码 |
| :--- | :--- |
| `admin` | `666888` |
| `张三` | `123456` |
| `涛哥` | `888666` |

表格右边那列就是正确密码；三组之间是「任一套都对」的关系。

第 2 条是整道题的分水岭。以前做过的版本是：输一次，对了提示成功，错了提示失败，程序结束。而这个要求里，登录失败要一直提示重输、直到成功为止。反复做同一件事——这就撞上循环了。

### while 还是 for

一旦决定用循环，下一个问题立刻摆在面前：用 `while` 还是 `for`？

回到两者的适用场景。`while` 关注的是循环开始与结束的条件：如果你不清楚要循环多少次，但清楚循环结束（或开始）的条件，就该用 `while`。`for` 适合另外两种情况：次数明确可知，或者要遍历某个数据集里的每一个元素、再对元素做进一步处理。

照着这条标准看这道题：我们根本不知道用户会登录失败多少次，可能一次就对，也可能连着错十次，循环次数无从预估；但循环结束的条件非常明确——登录成功，程序结束运行。次数未知、条件已知，这就是 `while` 的地盘。

> **结论**：这道题用 `while`。判断标准不是「哪个顺手」，而是「你到底知不知道要转几圈」。

于是循环条件这一块不用 `i = 0` 加 `i < 10` 那一套写法——那种写法成立的前提是「我清楚要循环十次」，而这里不成立。这里直接写 `while True`：布尔值为真就一直循环，直到登录成功再退出。

### 三步走：接收、校验、判断

循环体里要做的事，按顺序拆成三步。

第一步，接收键盘录入的用户名和密码，分别用 `username` 和 `password` 两个变量接住。这里有一个必须当心的坑：这两行代码要缩进，不能顶格写。

> **易错点**：顶格写就和 `while` 平级了，一个在循环外、一个在循环里，这两行根本不属于循环体，`while True` 会变成一个疯狂空转、什么都不做的死循环。缩进在 Python 里不是排版，是语法。

第二步，校验：判断输入的用户名和密码是不是空的，为空就要求重新输入。

```python
if username == "" or password == "":
    print("输入的用户名和密码不能为空，请重新输入")
```

两个细节。一是空字符串就是里面一个字符都没有，写成 `""`；如果你在引号里敲了一个空格，那代表的是空格这个字符——空格也是一个字符，`" "` 不是空串，判断不出来「用户什么都没输」。二是两个条件之间连的是 `or` 不是 `and`：用户名空、密码空，任意一个为空都不算有效输入；用 `and` 就变成「两个同时为空才提示」，只漏一个照样往下走。

第三步，判断用户名和密码的正确性，执行登录操作。三组账号对应三个分支，最后一个 `else` 兜住全都不匹配的情况：

```python
if username == "admin" and password == "666888":
    print("登录成功，进入到B站首页")
elif username == "张三" and password == "123456":
    print("登录成功，进入到B站首页")
elif username == "涛哥" and password == "888666":
    print("登录成功，进入到B站首页")
else:
    print("用户名或密码错误，请重新输入")
```

同一个用户名下必须用户名与密码都对上才算成功，所以组内用 `and` 连接；三组之间是「或」的关系，用 `elif` 串起来最合适。缩进同样要盯住：每个分支里的 `print` 都比 `elif` 再缩进一级，它才是条件成立时执行的逻辑。

### 少了 break，登录成功也停不下来

先照上面写完，跑一遍。

输入 `admin` 加一个错误密码回车，程序提示「用户名或密码错误，请重新输入」，而且没有退出——运行按钮上的绿点亮着。接着又提示输入用户名，再输 `admin` / `666888`，这次对了，输出「登录成功，进入到B站首页」……可光标还在下面闪，程序又在等着输入下一个用户名。

原因很清楚：写的是 `while True`，它天然一直循环，而我们从头到尾没有在任何位置跳出它。需求说的是「直到登录成功，程序结束运行」，所以成功之后必须跳出循环——此时要请出第一个关键字 `break`。

> **定义**：`break` 只能出现在循环当中，单独写在外面是语法错误；它的含义就是结束循环、跳出循环。

用法极其直白：想在哪跳出，就把 `break` 放在哪。这里想在登录成功后跳出，那就把 `break` 写在「登录成功，进入到B站首页」这句输出之后。三组账号都是成功分支，所以三个分支里都要加 `break`——只给 `admin` 加、漏了「张三」和「涛哥」，用后两组账号登录照样退不出去。

改完再测：先输错误的用户名密码，程序提示错误但没结束，继续等输入；接着输 `admin` / `666888`，输出登录成功，然后程序真的停了。再拿「涛哥」试：`涛哥` 配 `123456` 是错的（涛哥的密码是 `888666`），回车后走 `else`，提示错误，再转一轮；改成 `涛哥` / `888666`，登录成功，`break` 一跳，循环结束。

这里还有个顺带要记住的点。前面讲过 `while` 后面可以配 `else`，那个 `else` 里的代码块是在循环正常结束之后才执行的；而 `break` 属于跳出循环，不是正常结束，所以一旦执行了 `break`，`while` 后面 `else` 里的代码就不会再执行。这个配合关系可以自己写个小例子跑一遍验证，比死记结论牢靠。

### continue：空密码的那一轮不该往下走

再测一种情况：用户名输 `admin`，密码什么都不输、直接回车。

程序先提示「输入的用户名和密码不能为空，请重新输入」——校验那一步生效了。可紧接着它又提示「用户名或密码错误，请重新输入」——这说明第三步那串判断也照样执行了一遍，`admin` 配空密码当然对不上三组账号，于是落到了 `else`。

问题来了：既然已经发现输入为空、已经让他重新输入，还有必要再去判断用户名和密码的正确性吗？没有。可现在的代码控制不住，它从上到下顺序执行，提示完继续往下走。

要打断这个流程，就得用第二个关键字 `continue`。`continue` 的意思是「继续」，同样只能出现在循环当中，作用是中断本次循环，直接进入下一次循环。

把 `continue` 加在「输入的用户名和密码不能为空，请重新输入」这句输出之后：

```python
if username == "" or password == "":
    print("输入的用户名和密码不能为空，请重新输入")
    continue
```

在 `continue` 那一行打个断点，用调试模式跑：输 `admin`，密码直接回车，程序停在断点处——此时 `password` 确实是一个空字符串。往下走一步，提示信息打印出来；再走一步，执行到 `continue`。接下来这一步是关键：它是继续顺着往下执行后面的判断，还是直接跳回循环开头？继续单步，你会看到它并没有往下走，而是回到了循环的第一行，重新提示输入用户名。

> **结论**：`break` 结束的是整个循环，`continue` 结束的只是这一轮。一个让循环彻底停住，一个让循环跳过头、马上开始下一轮。

打断点之后如果不想一步步跟，也可以让它直接跑到下一个断点位置——此时再输一次空密码，程序又停在断点那儿，能把同一段流程再验证一遍。

### 两个关键字的分工

整个案例的最终结构就是这三步，加上两个「半路掉头」的关键字：

```text
while True                        # 次数未知，条件已知：登录成功即结束
  ├─ 接收用户名 username
  ├─ 接收密码   password
  ├─ username 或 password 为空？
  │      └─ 是 → 提示"不能为空" + continue  ──┐
  │                                        │
  ├─ 三组账号逐一比对                        │
  │      ├─ 命中 → 提示"登录成功" + break    │
  │      └─ 全不命中 → 提示"错误，请重新输入" │
  └────────────────────────────────────────┘
         （continue 跳回开头，break 跳出整个循环）
```

图里两条向上的箭头，就是两个关键字的作用：`continue` 把控制权送回循环开头，`break` 送到循环外面。

| 关键字 | 允许出现的位置 | 作用 | 对 `while ... else` 的影响 |
| :--- | :--- | :--- | :--- |
| `break` | 只能在循环内 | 结束（跳出）整个循环 | `else` 里的代码不再执行 |
| `continue` | 只能在循环内 | 中断本次循环，直接进入下一次循环 | 不影响正常结束时的 `else` |

两个关键字都只服务循环，`while` 循环里能用，`for` 循环里也一样能用。区别只在它们走多远：一个走到循环外，一个走回循环头。

## 猜数字：让程序自己出一个数

登录那个案例搞定，第二个案例是个小游戏：猜数字。

规则一句话能说清——系统生成一个随机数，用户来猜，猜错了告诉你猜大还是猜小，接着猜；猜对了游戏结束。和上一个案例比，它多出一个新东西：这个数得由程序自己「想」出来，而不是我们提前写死。

### random.randint 生成那个不可预测的数

所谓随机数，就是一个不可预测、也没有规律的数字。要生成它，可以借 Python 自带的 `random` 模块：模块里的功能就能产出随机数，用之前先 `import` 把它导进来。

```python
import random

random_number = random.randint(1, 100)
```

`random.randint` 里要指定两个数字，一个是起始，一个是截止。写 `1, 100` 就是生成 1 到 100 之间的随机数，而且两端都包含——1 有可能出现，100 也有可能。生成的数用 `random_number` 接住，后面比较时用的都是它。

`randint` 背后的机制，后面的课程会专门剖析，现在先会用就够了。

### 先跑一遍只有一次的版本

第二步，用户猜数。要接收键盘输入，用 `input` 提示「请输入一个数字」。

这里有个类型问题必须处理：`input` 拿回来的一律是字符串，而上面生成的随机数是整数，两者直接比大小是不对的。所以接收的同时就要转成 `int`：

```python
number = int(input("请输入一个数字："))
```

第三步，比较。输入的数字比随机数大，说明猜大了；比随机数小，说明猜小了；既不大于也不小于，那就只能是相等，也就是猜对了。

```python
if number > random_number:
    print("您输入的数字太大了！")
elif number < random_number:
    print("您输入的数字太小了！")
else:
    print("恭喜您猜对了 666")
```

为了测试方便，可以临时把生成的随机数打印在最后（正式玩的时候当然不能给玩家看）：

```python
print(f"随机生成的数字是：{random_number}")
```

先跑一遍这个「只有一次机会」的版本。输入 60，程序提示「您输入的数字太小了！」；接着打出「随机生成的数字是：72」——没猜对，程序却直接结束了。

这就是问题所在：这段代码里一次循环都没有，从头到尾只执行了一遍。而需求要的是猜错之后给提示、然后继续输入，直到猜对才结束。

### 把猜的过程圈进 while True

该重复执行的，是「接收输入 → 比较 → 给提示」这一段。把它们放进循环里就行。至于 `while` 还是 `for`——还是老规矩：猜的次数完全不可预知，可能第一把就中，也可能猜上十几把；但退出条件很明确，猜对就结束。次数未知、条件已知，又是 `while True`。

圈范围的时候，有两行代码必须留在循环外面，一步都不能圈进去。

第一行是生成随机数那行。如果它在循环体内，每转一圈都会重新生成一个随机数——你猜的永远是上一轮的数字，这一轮的数又变了，这游戏就永远猜不对。随机数只生成一次，玩家猜的是同一个数，这样提示「大了」「小了」才有意义。

第二行是最后那句打印随机数的代码，它属于测试用途，放在循环后面即可。

所以循环体里只包中间那一段：

```python
import random

# 第一步：生成 1~100 之间的随机数（只生成一次，不能放进循环）
random_number = random.randint(1, 100)

while True:
    # 第二步：接收用户所猜的数字
    number = int(input("请输入一个数字："))

    # 第三步：比较大小并给出提示
    if number > random_number:
        print("您输入的数字太大了！")
    elif number < random_number:
        print("您输入的数字太小了！")
    else:
        print("恭喜您猜对了 666")
        break            # 猜对即跳出循环

# 便于测试：把生成的随机数打出来
print(f"随机生成的数字是：{random_number}")
```

### 灰色代码在提醒什么

刚把逻辑圈进 `while True`、还没写 `break` 的时候，开发工具会把最后那行打印随机数的代码显示成灰色。鼠标悬上去，提示是「此代码不可到达」。

这提示不是工具在挑刺。`while True` 是无限循环，而循环体里没有任何一处能跳出去，后面的代码永远轮不到执行——灰行不影响运行，却准确指出了漏洞：这个循环没有出口。

按需求，猜对就是游戏结束，也就该跳出循环。所以在 `else` 分支里、输出「恭喜您猜对了」之后加一个 `break`。加完再看，那行灰色代码立刻恢复正常颜色——因为它确实有可能被执行到了。

> **提示**：跳出循环用 `break` 而不是 `continue`。`continue` 只是结束当前这一轮、回到循环开头，猜对了还继续让你猜，游戏永远结束不了。

### 折半去猜，几步就到位

跑起来玩一局。因为随机数在 1 到 100 之间，怎么猜最快？从 1 顺着往上试当然也行，但那不叫快准狠。先猜中间的数，再根据提示把范围砍一半，这样最快。

一局实际过程：先猜 50，提示太小；那答案在 51 到 100 之间，取中间猜 75，还是太小；范围收到 76 到 100，猜 85，仍然太小；再猜 93，太小；接着猜 97，这次变成太大了——说明答案在 94 到 96 之间；猜 95，太小；那只能是 96。输入 96，屏幕上打出「恭喜您猜对了 666」，随机数正是 96，程序随之退出。

整局只用了七次。这就是「折半」的威力：每猜一次，可能的范围就少一半。

猜错的那几轮还验证了另一件事：程序没有结束，提示完继续等你输入下一个数字——正是需求里那句「猜错就继续猜，直到猜对为止」。

到这里，`while` 循环、`for` 循环、嵌套循环，以及 `break` 与 `continue` 这两个控制关键字，就都过完了。代码还没写完的，先把这三道案例自己敲一遍，再往下走。
