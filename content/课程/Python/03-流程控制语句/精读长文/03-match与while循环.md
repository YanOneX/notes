# match 模式匹配与 while 循环

前面几节，我们把 if 条件判断从单分支、双分支一路练到了 `if / elif / else` 这种多分支的组合。这里有个小案例：根据输入的星期，拿到对应的工作日程。

输入 1，从上往下匹配，命中 `day == "1"` 这一支，打印"周一：工作会议日"；输入 4，一路往下比，落到 `day == "4"` 那一支，打印"周四：代码审查日"；输入 6 或者 7，走到"周末"那一支，打印"周末：休息放松日"。

```python
day = input("请输入星期几：")

if day == "1":
    print("周一：工作会议日")
elif day == "4":
    print("周四：代码审查日")
elif day == "6" or day == "7":
    print("周末：休息放松日")
else:
    print("输入有误")
```

这段代码挺整齐，读起来也顺。但它有个小毛病：每一支的匹配方式其实是同一个——都在问 day 等不等于某个值，全是等值匹配。

问题就出在 if 本身。if 后面跟的必须是一个条件表达式，结果必须是布尔值：True 就是条件成立，False 就是不成立。所以 `day ==` 这一截躲不掉，一个字都不能省。分支一多，重复的代码就越堆越多，写起来也繁琐。

Python 为这类问题准备了专门的语法：结构模式匹配。

## 结构模式匹配：拿一个模板去套数据

> **定义**：结构模式匹配，就是通过一个清晰的模板，去精准地匹配数据的结构和数据的内容，匹配成功之后再执行对应的操作。

注意"结构"这两个字。它不只比对数据的内容，也能比对数据长什么形状——这一点在匹配列表、字典这类复合数据时会体现出来。眼下先用最简单的值匹配把语法立住。

这几句话里的关键字，其实就落在"匹配"两个字上：你给一个模板，它拿这个模板去套，看内容和结构对不对得上。语法用到 `match` 和 `case` 两个关键字，`match` 就是匹配的意思。

## 用 match case 把重复的 `day ==` 拿掉

接收键盘录入那一行原封不动，区别全在下面。

```python
day = input("请输入星期几：")

match day:
    case "1":
        print("周一：工作会议日")
    case "4":
        print("周四：代码审查日")
    case "6" | "7":
        print("周末：休息放松日")
    case _:
        print("输入有误")
```

先看 `match day` 这一行：意思是"我要拿 day 这个变量里的值去匹配"。冒号下面挂一串 case，一个 case 就是一种情况。跟 if 版对照着看——`case "1"` 后面没有 `day ==`，直接写要匹配的内容。省下来的，正是那部分重复代码。

匹配的过程是从上往下的：

1. 先算出 `match` 后面那个表达式的值；
2. 拿这个值跟第一个 case 后面的值比，对上了，就执行这个 case 底下的语句；
3. 这句执行完，整个 match 结构就结束了，后面的 case 一概不再看；
4. 对不上，就接着比第二个、第三个，依次往下。

> **注意**：所有 case 的缩进是平齐的，它们同属一个 match 分支序列；每个 case 底下的语句再往里缩一层。

> **提示**：`input()` 取回来的是字符串，所以 case 后面写的也是带引号的字符串。写成 `case 1:`（整数）就跟 `"1"` 对不上，永远匹配不中。

## case 后面的两种特殊写法

### 一条竖线，匹配多个值

`case "6" | "7":` 里那条竖线表示"或"：只要 day 是 6 或者 7，都会命中这一支，执行同一段操作。要匹配的项再多，继续用竖线往下串就行。

这条竖线怎么敲出来？就是回车键上面那个键。键帽上印着一条反斜线 `\` 和一条竖线 `|`，按住 Shift 再按它，敲出来的就是竖线。

### 一条下划线，兜住其余所有情况

最后那个 `case _` 匹配其他所有情况：从上往下一个一个比下来，前面都没对上，就落到它这里。

那这个 `case _` 相当于 if 里的哪个关键字？else。同样是"以上都不成立时走这里"。

> **易错点**：下划线不带引号，就是 `case _`，不是 `case "_"`。带上引号，它就变成"匹配一个下划线字符"，意思完全变了。

这个兜底分支可有可无，写不写看需求。有"其他情况"存在，写上更稳妥。

## 在调试器里把匹配过程走一遍

语法光看是记不住的，得让程序一步一步走给人看。在 `match day` 这一行打个断点，然后以调试模式运行。

这里有个小坑值得单独说：如果这个文件是刚建好、一次都没跑过的，你直接点工具栏上那只小虫子，跑的其实还是上一次运行的那个文件——运行配置里记着的还是旧文件。第一次要跑新文件，在编辑区右键，选以 Debug 模式运行当前文件；跑过这一次之后，它才会出现在运行配置的下拉列表里。

输入 4，回车。断点停住，此时 day 的值是字符串 `"4"`，在下方变量窗口里能看到，鼠标悬到变量上也能看到。

按 F8 往下走一步：是 1 吗？不是。再走：是 4 吗？是，进入 `case "4"`，控制台打出"周四：代码审查日"。再走一步——直接跳出了整个 match，后面的 `case "6" | "7"` 和 `case _` 根本不再看一眼。

再次运行，输入 7：一路比对下来，落到 `case "6" | "7"`，命中，输出周末休息放松日。一个 case 管住两个值，这一支自己就把"或"写进去了。

再运行一次，故意输入 9：前面每一个 case 都比不上，最后落到 `case _`，打印"输入有误"。兜底分支管不管用，这么一试就清楚了。

## 案例：用 match case 写一个四则运算计算器

需求：做一个简易计算器，支持加、减、乘、除四则运算；用户输入要计算的两个数以及运算符，程序按这个运算符去做对应的计算。

要收三次键盘录入：两个数，一个运算符。输入拿到的都是字符串，数字得转成 float——这里要支持浮点运算。

```python
number1 = float(input("请输入第一个数："))
number2 = float(input("请输入第二个数："))
oper = input("请输入运算符（+ - * /）：")

match oper:
    case "+":
        print(f"{number1} + {number2} = {number1 + number2}")
    case "-":
        print(f"{number1} - {number2} = {number1 - number2}")
    case "*":
        print(f"{number1} * {number2} = {number1 * number2}")
    case "/":
        print(f"{number1} / {number2} = {number1 / number2}")
    case _:
        print("操作不支持")
```

运算符是用户手敲的，他完全可能敲一个不在加减乘除里的符号，所以最后要有一条兜底，告诉他操作不支持。

搭骨架的阶段，可以在各个 case 里先写 `pass` 占位。pass 是个空语句，什么都不做，只负责把语法位置占住，等逻辑想清楚了再往里填。

格式化字符串里那两个加号，得分开看：

```python
print(f"{number1} + {number2} = {number1 + number2}")
```

大括号外面那个 `+`，是字符串里的一个普通字符，原样打印出来；大括号里面那个 `+`，才是参与算术运算的加号。这两个符号长得一样，干的活完全不同，写的时候别当成一回事。

测试两轮：输入 10、5，运算符输 `*`，得到 `10.0 * 5.0 = 50.0`——因为是用 float 接收的，10 变成 10.0，5 变成 5.0，结果自然是浮点。输入 10、2，运算符输 `/`，得到 `5.0`。

## 除数为零：case 后面还能挂条件

接着试 10、0、`/`。回车，报错了：`ZeroDivisionError: division by zero`。

> **提示**：`10 / 0` 里，10 是被除数，0 是除数。报错的原因是除数不能为 0，跟被除数没关系。

从需求上讲，这属于"操作不支持"，应该落到 `case _` 去给一句提示，而不是让程序崩掉。反过来想一步就通了：要让 `/` 这一支匹配成功，前提就是 number2 不等于 0。

match case 允许在 case 后面再挂一个条件判断：

```python
    case "/" if number2 != 0:
        print(f"{number1} / {number2} = {number1 / number2}")
```

这个 if 跟我们前面学的条件判断是一回事：条件成立，这个 case 才算匹配上；条件不成立，就当作没匹配上，继续往下比。

再打断点跑一次 10、0、`/`：加、减、乘都比不上；走到 `/` 时，oper 确实是斜杠，但 number2 是 0，条件不成立，这一支匹配不上；继续往下，落到 `case _`，输出"操作不支持"。问题解决。

## match case 替代不了 if

match case 是 Python 3.10 才加进来的语法，早期版本里根本没有，放到老版本上跑会直接报语法错误。

那它是不是可以把 if 取代掉？不能。两者各有各的地盘：

| 要判断的事情 | 更合适的写法 |
| :--- | :--- |
| 变量去匹配若干固定值（等值匹配） | `match` / `case` |
| 范围的比较、复杂的逻辑判断 | `if` / `elif` |
| 多个条件组合起来判断 | `if` / `elif` |

需要判断"分数在 60 到 70 之间"这种范围，或者把好几个条件用 and / or 组合起来，match case 就无能为力，还得回到 if。

> **结论**：等值匹配用 match case，范围与组合条件用 if。

## while：从单曲循环到轮播图

播放器里的单曲循环，一首歌反复播；列表循环，列表里的歌一遍一遍过。B 站首页那个轮播图，一轮大概九张图，依次播完，再从头播第二轮、第三轮。

共同点很清楚：同一件事被重复执行。

> **定义**：循环，就是重复地执行某件事。

Python 里做循环有两条路：`while` 和 `for`。这一章的顺序是：先 while，再 for，然后是循环里的一些高级语法（比如循环嵌套），最后拿一组案例把循环用熟。

## while 的语法结构

```python
while i < 10:
    print("人生苦短，我用 Python")
```

拆开看：`while` 关键字，空格，一个条件表达式，冒号。条件表达式的结果是布尔值——要么 True，要么 False。True 代表条件成立，才去执行下面缩进的那部分代码；这部分代码叫循环体。缩进表示层级，缩进了就属于 while。

执行流程是这一节的要害：

```text
① 判断条件表达式
      │
      ├── True ──► ② 执行循环体 ──► 回到 ①
      │
      └── False ─► ③ 结束循环
```

读这张图的关键在那一根回头的箭头：循环体执行完不是往下走到结束，而是回到条件判断再判一次。第二次判 True，就再执行一遍循环体；判 False，才往下走到结束。循环体到底跑多少遍，完全由这个条件表达式说了算。

如果条件表达式的值一直是 True，循环就一圈一圈停不下来，这叫无限循环，也叫死循环。死循环非常吃系统性能，写循环时对条件的把控必须上心。

## while 后面的 else

while 还能在整段循环后面跟一个 else：

```python
while 条件表达式:
    循环体语句
else:
    循环正常结束后执行的语句
```

else 里的逻辑，在条件为 False、循环正常结束时才执行。这一段可有可无，要不要写看需求。另外提一句：如果循环不是正常结束的（后面会讲到中途打断循环的情况），else 里的逻辑不会执行。

## 案例：打印十遍"人生苦短，我用 Python"

需求很直白：把"人生苦短，我用 Python"这句输出，重复十次。要关注的就两件事——条件表达式怎么写，条件的结果怎么被改变。

```python
i = 0
while i < 10:
    print("人生苦短，我用 Python")
    i += 1
else:
    print("循环正常结束")
```

i 的初始值是 0，0 < 10 成立，进循环体：先打印这一句，再做 `i += 1`（等价于 `i = i + 1`），i 变成 1。回到条件判断，1 < 10 成立，第二遍……一直走到 i 等于 9，还能进一次，这是第十遍；这一遍做完，i 变成 10，10 < 10 不成立，循环结束，接着执行 else，打印"循环正常结束"。

要是只写打印、不写 `i += 1` 呢？i 永远是 0，条件永远成立，控制台就一直往下刷，停不下来。运行时那一栏会一直是个绿点，表示程序还没执行完，只能手动去点停止。这就是活生生的死循环。

打断点跟着走一遍会更清楚：i 从 0 起步，0、1、2……每循环一次加一，控制台一行行往上堆；堆到第十行，i 变成 10，条件不成立，跳出循环进 else，整个结构走完。

## 案例：1~100 之间所有偶数的累加和

需求：计算 1~100 之间所有偶数的累加之和。"累加"就是把这一堆偶数全加到一起。

动手前先想清楚两个问题：

1. 怎么拿到 1~100 之间的偶数？用求模运算符 `%`——一个数模 2 等于 0，它就是偶数，否则是奇数。
2. 累加用什么运算符？`+=`，在前一个数的基础上再加一个数。

```python
total = 0
i = 1
while i <= 100:
    if i % 2 == 0:
        total += i
    i += 1

print(f"1~100 之间所有偶数的累加之和是：{total}")
```

total 记累加结果，初始给 0；i 是每一次循环遍历出来的数，从 1 开始。条件写 `i <= 100`——1 到 100 两头都要包含，所以是小于等于，不是小于。

循环体里先判断 i 是不是偶数，是就 `total += i`；判断完不管结果如何，i 都要加一往前走。i 不往前走，循环就卡死在原地了。

最后那行 print 是顶格的，不属于 while，要等整个循环结束后才执行。

> **注意**：`i += 1` 要写在 if 外面、循环体里面。要是写进了 if 里，i 碰到奇数时就不加一，循环立刻变成死循环。

断点跟着走一段：i = 1，奇数，跳过累加，i 变 2；i = 2，偶数，total 变 2；i = 3 跳过；i = 4，total 变 6……i = 6 累加完是 12，i = 8 累加完是 20。i 一路涨到 101，101 <= 100 不成立，退出循环，打印 2550。

顺带说一句：循环体里用的就是前面讲的 if 条件判断。循环和分支是可以套着用的，这一段代码就是最小的例子。

## 本讲提到的题目

**题干**：编写一个游戏角色控制系统。玩家输入不同的指令，控制游戏角色执行相应的操作，操作结果直接输出到控制台。比如玩家输入"上"，或者小写的 w，或者大写的 W，就输出"角色向上移动"；输入"下"，或者 s、S，就输出"角色向下移动"。

题干里只举了上、下两个方向，其余方向按同样的结构补全即可。

**解析**：这题的关键不在判断本身，而在把"多个写法指向同一个动作"这件事写干净。正文里那条竖线正好干这个活：`case "上" | "w" | "W":`，三种输入命中同一支，后面挂一句"角色向上移动"。方向多起来，一个方向一条 case；末尾再补一条 `case _` 兜底，玩家乱敲指令时提示输入有误。

**答案**：用 if 写，一个方向就得写成 `if cmd == "上" or cmd == "w" or cmd == "W"`，三种写法重复一遍，正是正文开头那段重复代码的翻版；换成 match case 加竖线，重复的部分全部收进 case 那一行里。
