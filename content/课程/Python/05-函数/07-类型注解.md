# 类型注解

* **变量与容器的注解**
* > **定义**：类型注解（类型提示）是 Python 的语法特性，用来明确变量、函数参数、函数返回值的数据类型；它声明的是这个位置将来存什么类型的数据，而不是存什么值。

* 写法是在变量名后面加冒号、冒号后面写类型，等号照常赋值：`a: int = 695`。
* 容器要写到元素这一层：`list[str]`、`set[str]`、`dict[str, int]`（前键后值）、`tuple[str, int, int]`（按位置逐个写）。
* 一个容器装多种类型时用竖线分隔：`list[str | int]`，读作"字符串或整数"。
* 类型推断依据赋给它的值：`a = 695` 推成 `int`，`names = ["张三", "李四"]` 推成 `list[str]`；没有值就没有推断依据。
* 直接赋值、参与运算、由容器推导出来的变量，注解都可以不写，工具推得出来。
* 注解不是强制约束：`list[str | int]` 里 `append(1.5)` 会标波浪线，运行起来照样进得去。Python 是动态类型语言，类型在运行时才真正绑定。
* 写注解的三个好处：代码更清晰更安全、代码提示更精准、提前发现潜在问题。

* **函数签名上的注解**
* 参数位置与变量注解写法相同：形参名后加冒号写类型，`scores: list[int]` 里的 `int` 说的是每个元素的类型，不是列表的类型。
* 返回值位置在参数列表右括号之后，先写箭头 `->` 再写类型；`return a, b, c` 返回的是元组，所以要按元组写 `-> tuple[int, int, float]`，顺序必须与 `return` 一致。
* 带星号的形参注解天然是"逐元素"的：`*args: tuple[str, float, int]` 表示收进来的每一样东西都是三元素元组，外面不要再套一层 `tuple[...]`。
* 有默认值的形参能推断出类型（`coupon: int = 0`），注解可省；形参没有默认值时推断结果是 `Any`，这时注解是唯一的信息来源。
* `float` 兼容 `int`，给 `float` 形参传 `10` 不报警也不损失精度；传字符串则在写下的瞬间就标红。

| 位置 | 写法 | 说明 |
| :--- | :--- | :--- |
| 普通形参 | `scores: list[int]` | 冒号后写类型，容器要写到元素层 |
| 带默认值的形参 | `coupon: int = 0` | 能推断，注解可省 |
| 不定长形参 | `*args: tuple[str, float, int]` | 写"每一个元素"的类型 |
| 返回值 | `-> tuple[float, float]` | 右括号后加箭头，多值按元组写 |

* **注解改变的是发现错误的时机**
* 没有注解时，把单价写成 `"88"` 编辑器一声不吭：`"88" * 1` 是合法的字符串乘整数，真正撞墙的是后面 `sum()` 把字符串加进金额里。
* 注解加上后，`("商品", "18.5", 1)` 的第二个位置、`(100, 99, 2)` 的第一个位置当场标红。
* 注解不会改变程序行为：解释器不做校验、不做转换，传错类型仍要等运行时那次运算才出错。
* 需要多人协作、长期维护的项目推荐加注解；工具能推断的参数加不加随你，推断不出来的（如带星号的）建议加。
