# 把函数用起来：三个小案例、作用域与传参

函数的定义、参数、返回值这三样讲完，语法层面其实已经齐了：能定义，能传参，能拿回结果。可"齐了"和"会用"是两回事。所以先不急着往下推新语法，而是摆出三个小需求，把刚学的东西从头到尾走一遍。三个案例都不难，难的是每一处细节都别写错——尤其是那个最容易翻车的 `return` 缩进。

## 三个需求，先看清单

这次一共三条需求：

- 定义一个函数，根据传入的底和高计算三角形的面积；
- 定义一个函数，根据传入的字符串，统计其中元音字母的个数；
- 定义一个函数，根据传入的班级学员高考成绩列表，计算最高分、最低分和平均分。

第一条的公式不用想：三角形面积等于底乘高除以二。第二条得先把"元音字母"说清楚——A、E、I、O、U，一共五个；统计的时候小写要算，大写也得算，所以真正要认的是十个字符。

第三条藏着两个小尾巴。一是传进来的是个列表，不是一个数；二是平均分除出来多半带小数，只保留一位。

> **提示**：第三条这种"一次要交出好几个结果"的需求，正好是返回值语法存在的理由——结果不打印在函数里，而是交回调用处，由调用方决定怎么用。

需求清楚了就动手。新建一个单独的 Python 文件，把三条需求抄在文件顶部当注释，然后一条一条实现。

先说一个不起眼但很真实的环节：函数名怎么起。三角形这个词一时想不起来，查个翻译就有了——`triangle`。名字定了，函数就叫 `triangle_area`。

## 三角形的面积：一次完整的定义与调用

第一个函数写出来是这样：

```python
def triangle_area(b, h):
    """
    根据传入的底和高，计算三角形的面积
    :param b: 三角形的底长
    :param h: 三角形的高
    :return: 三角形的面积
    """
    return b * h / 2


print("底长为30，高为20的三角形面积为:", triangle_area(30, 20))
```

`def` 开头，函数名后面跟一对括号，括号里是形参，冒号收尾，函数体缩进——结构和之前写过的函数一模一样，唯一需要动脑的是形参取什么名。底用 `b`，高用 `h`，`h` 就是 height 的首字母。这两个名字你随便写，`x`、`y` 也行，不影响运行；只是过两天自己回来看，`b`、`h` 显然比 `x`、`y` 好认。

函数体只有一行 `return b * h / 2`。注意这里是 `return`，不是 `print`——算出来的面积要交回调用处，不是就地打印掉。

接着补函数的说明文档。三个引号一回车，编辑器自动把结构补好了，`:param:` 和 `:return:` 各就各位，照着填空即可：底长、高、返回三角形的面积。这段文档看着可有可无，但函数一多，它就是最省事的备忘录。

调用写在函数下面：

```python
print(triangle_area(30, 20))
```

底 30、高 20 按顺序传进去，函数返回结果，外面套一层 `print` 把它打出来。

控制台会显示 `300.0`。数值上就是 300，那个 `.0` 是因为 `/` 除法得到的是浮点数，不用怀疑自己算错了。

第一个需求就此收工，难度不大，可以把注意力放到下一个案例上。

## 元音字母统计：return 该放在哪一行

第二个需求是统计字符串里的元音字母个数。函数名 `count_aeiou`，形参 `s`。

先别急着敲代码，用十秒钟想想思路。要在字符串里数元音，第一步必然是把字符串里的字符一个一个取出来；每取到一个，就判断它是不是那十个元音字符之一；是，计数加一；不是，接着看下一个。三步：取字符、判断、累加。

```python
def count_aeiou(s):
    number = 0
    for w in s:
        if w in "aeiouAEIOU":
            number += 1
    return number
```

逐行看：

- `number = 0` 写在循环外面。放在循环里就坏了——每转一圈都清零，最后要么是 0，要么是 1。
- `for w in s` 把字符串逐个字符遍历出来，`w` 就是当前这一轮取到的那个字母。
- `if w in "aeiouAEIOU"` 用 `in` 判断成员：当前字符在不在这一串里。大小写十个字符拼成一个字符串，正好当"元音集合"用。
- `number += 1` 命中就加一。
- `return number` 返回统计结果。

代码逻辑不复杂，但这里有个必须讲清楚的坑。

> **易错点**：`return` 的缩进位置。如果把它缩进到 `if` 里面，写成下面这样，代码照样能跑，结果却是错的。

```python
def count_aeiou(s):
    number = 0
    for w in s:
        if w in "aeiouAEIOU":
            number += 1
            return number   # 错的：第一个元音一到手就返回了
```

如果 `return` 缩在 `if` 里面，那么字符串里第一个元音一被找到，函数立刻就把 `number` 交出去了。这时候后面的字符一个都还没看——函数不是"数完返回"，而是"数到第一个就返回"。对一个有七个元音的字符串，它会老老实实返回 1。

所以 `return` 必须与 `for` 平级：整个循环彻底走完，才把累计的结果交出去。

```text
def count_aeiou(s):
    number = 0
    for w in s:          ← 循环走完
        if ...:
            number += 1
    return number        ← 与 for 平级，循环结束后才执行
```

读图说明：`return` 少缩进一级，从 `if` 的肚子里退到函数体的顶层，执行时机就从"命中即返回"变成了"遍历结束再返回"。

改对之后补上说明文档：统计字符串中元音字母的个数，参数是字符串，返回元音字母的个数。

验证时随手写个字符串，先自己数一遍，再让程序数一遍对答案：

```python
print(count_aeiou("hello Python hello world OK"))
```

`hello` 里两个（e、o），`Python` 里一个（o），第二个 `hello` 两个（e、o），`world` 一个（o），到这里六个；末尾那个 `OK` 里的 `O` 是大写，照样算，第七个。运行输出 7，和手数的一致。

> **提示**：这个案例真正的考点不是 `for` 也不是 `in`，而是"循环里能不能提前 `return`"。凡是要把整批数据统计完才出结果的函数，`return` 都得站在循环外面。

## 一个班的成绩：三个返回值怎么交出去

第三个需求给的是一条列表：班级学员的高考成绩。要算出最高分、最低分、平均分。函数叫 `calc_score`，形参 `score_list`。

```python
def calc_score(score_list):
    """
    计算成绩的最高分、最低分以及平均分
    :param score_list: 分数列表
    :return: 最高分、最低分、平均分
    """
    max_s = max(score_list)
    min_s = min(score_list)
    avg_s = round(sum(score_list) / len(score_list), 1)
    return max_s, min_s, avg_s
```

最高分和最低分不用自己写循环比大小，Python 自带 `max` 和 `min` 两个内置函数，把列表丢进去就分别拿到最大值和最小值。按住 Ctrl 点一下函数名，能跳进它的定义：`def` 开头、一段英文说明文档，但函数体是空的。这不是源码残缺，而是因为这些内置函数压根不是用 Python 写的，底层是 C 语言实现，在这一层看不到具体实现。看不到不影响用，知道它干什么就行。

平均分按定义来：先把列表里的分数全部累加，再除以元素个数。至于"保留一位小数"，交给 `round`——第二个参数写 1，就是保留一位。

最后一行把三个结果一起返回，逗号分隔。

```python
return max_s, min_s, avg_s
```

Python 遇到逗号分隔的多返回值，会自动把它们打包成一个元组交出去。调用处要接住，就用三个变量按顺序接：

```python
scores = [589, 609, 605, 643, 677, 455, 477, 489, 503]

max_score, min_score, avg_score = calc_score(scores)

print("最高分:", max_score)
print("最低分:", min_score)
print("平均分:", avg_score)
```

这一步叫解包：元组里有三个元素，左边就摆三个变量，一一对应。顺序千万别对错——第一个位置是最高分，第二个是最低分，第三个是平均分，接反了程序不报错，但输出会张冠李戴。

运行结果：最高分 677，最低分 455，平均分 560.8。

平均分那个 560.8 值得多看一眼：`round` 无论是除得尽还是除不尽，结果都会落在一位小数上。这正是需求里"保留一位小数"的要求。

> **提示**：`return max_s, min_s, avg_s` 也可以写成一行不带中间变量的形式，把三个表达式直接塞进 `return`。功能一样，但分开写更好读，也方便调试时单独看某一个值。

顺带一个小细节：变量名打错时，编辑器会在下面划一道波浪线。`score` 敲成 `square` 就是典型，改回来波浪线立刻消失——这类提示别忽略，它经常是拼写错误的唯一线索。

三个案例到此走完。案例之后还配了四道练习，要求还是那两件事：照着需求把函数定义出来，再把它调用起来。先自己动手写，写完再往下看进阶的内容。

## 变量的作用域：谁能看见谁

函数的入门部分到此闭环，接下来是进阶内容，共四块：变量作用域、参数详解（传参方式与高级参数写法）、匿名函数、一组综合案例。前面定义的函数都有名字，匿名函数要解决的是"没有名字的函数怎么写"，那部分稍后再谈。现在先啃第一块：变量作用域。

所谓变量的作用域，就是变量的作用范围：这个变量在哪儿能用，在哪儿不能用。

看这样一段代码：

```python
number = 100
count = 0
c_area = 0


def circle_area(r):
    pi = 3.14
    area = pi * r * r
    return area
```

函数内部有 `pi` 和 `area`，还有一个形参 `r`；函数外部有 `number`、`count`、`c_area`。位置不同，身份就不同。

> **定义**：在函数外部定义的变量叫全局变量；在函数内部定义的变量叫局部变量，形参本质上也是局部变量。

全局变量一般写在文件顶部，整个 Python 文件里任何位置都能访问——函数外面能读，函数内部也能读。

局部变量只在函数内部有效，出了这个函数就不认识了。而且函数执行完毕，内部的局部变量会被自动销毁。

```text
Python 文件
├── number = 100            全局变量：整个文件都能用
│
└── def circle_area(r):
    ├── r                   形参，也是局部变量
    ├── pi = 3.14           局部变量
    ├── area = pi * r * r   局部变量
    └── return area

函数外 print(number)  →  100
函数外 print(pi)      →  NameError
```

读图说明：`number` 站在文件的最外层，函数体内外都够得着；`pi`、`area`、`r` 关在 `def` 这一层的缩进里，出了这个范围就不存在了。

验证很直接。先在函数外面打印 `number`，输出 100；再把同一句搬进函数内部，输出还是 100——说明全局变量在函数里读得到。

反过来，在函数外面打印 `pi`：

```python
print(pi)
```

编辑器立刻在 `pi` 下面划红线，鼠标悬停提示"未解析的引用 pi"，意思是它找不到这个名字。硬跑一下，控制台报：

```text
NameError: name 'pi' is not defined
```

`area` 和 `r` 一样，都在函数外面报同样的错。而且这类错误有个连带后果：报错那一行之后的代码全部不再执行。

> **易错点**：`NameError` 不是"值取不到"，而是"这个名字根本不存在"。函数一结束，局部变量就被销毁了，外面压根没有这个名字可查。

## 同名不同身：函数里赋值改不到外面

再看一个现象，这是很多人第一次真正栽跟头的地方。

```python
number = 100


def func():
    number = 10000
    print("函数内:", number)


func()
print("函数外:", number)
```

全局 `number` 是 100，函数里又给它赋了个 10000，然后把它打印出来。函数调用结束，外面再打印一次。

先别往下看，自己猜一猜：这两次输出各是多少？

实际运行：

```text
函数内: 10000
函数外: 100
```

函数里明明赋了 10000，外面怎么一点没变？

因为函数里那一句 `number = 10000`，Python 根本不认为你在修改外面的 `number`，它认为你在函数内部新建了一个局部变量，名字碰巧也叫 `number`。这两个 `number` 自始至终是两个不同的变量，只是名字撞了车。

函数里的局部 `number` 被赋成 10000，打印出来当然是 10000；函数一结束，它就被销毁。外面那句 `print` 找的是全局 `number`，从头到尾没人动过它，还是 100。

> **结论**：在函数内部给变量赋值，等于新建一个局部变量，而不是修改同名的全局变量。函数内部对全局变量只有"读"的资格，没有"写"的资格。

这条规则一次性解释了两个现象：为什么函数里读 `number` 没问题（读是允许的），为什么函数里写 `number` 外面不变（写变成了新建）。

## global：明确声明要改外面那个

那如果本意就是要改外面那个全局变量呢？

Python 给了一个关键字：`global`。它的作用就是明确告诉解释器——接下来提到的这个名字是全局变量，不是局部变量。

```python
number = 100


def func():
    global number
    number = 10000
    print("函数内:", number)


func()
print("函数外:", number)
```

加上 `global` 之后，两次输出都是 10000。

写法很简单：单独一行，变量名前面加 `global`，位置在赋值之前。

> **注意**：先声明，后使用。`global number` 必须写在任何针对该变量的赋值之前；顺序反了，Python 在编译阶段就报语法错误——因为那句赋值已经被当成"创建局部变量"处理掉了。

不过，能这么写不代表该这么写。

实际项目里基本不用它。原因很实在：函数里改了全局变量，这个函数调用一次就改一次，调用两次就改两次，谁也不知道运行到某一刻时这个变量到底是几。代码一长、函数一多，这种隐式修改就是 bug 的温床，维护和调试都变难。

更推荐的做法是：需要数据就通过参数传进去，算完了通过返回值带出来。函数的输入输出全写在签名和 `return` 上，谁看都清楚。

那 `global` 什么时候用？典型场景是记录程序的状态、配置，或者做计数器。

比如一个调试开关：

```python
debug_mode = False


def enable_debug():
    global debug_mode
    debug_mode = True


def disable_debug():
    global debug_mode
    debug_mode = False
```

这个全局变量记录的是"程序现在要不要进调试模式"。它是状态，不是某个函数的中间结果——想开就调 `enable_debug()`，想关就调 `disable_debug()`，这时候在函数里操作全局变量是合理的。

再比如记录某个函数被调用了多少次：全局放一个计数变量，函数每执行一次就让它加一。这种"全局只有一份、需要跨多次调用持续累计"的数据，才是 `global` 的用武之地。

> **提示**：判断标准很简单——这个数据是不是全局只有一份、并且要跨多次调用持续存在？是，才考虑 `global`；如果只是把数据从 A 传到 B，用参数和返回值就够了。

## 传参的两种写法：位置与关键字

作用域讲完，接着是参数。参数这块有两件事容易混：定义函数时形参怎么写，调用函数时实参怎么传。这一节讲的是后者——传参方式。

方式就两种。

### 位置参数：按顺序对号入座

位置参数指的是：调用时传的实参，按定义时形参的先后顺序一一对应。

```python
def reg_stu(name, age, gender, city):
    ...


reg_stu("张三", 18, "男", "北京")
```

四个形参，四个实参，第一个给 `name`，第二个给 `age`，第三个给 `gender`，第四个给 `city`。

前面那三个案例用的全是位置参数——`triangle_area(30, 20)`、`count_aeiou("...")`、`calc_score(scores)`，都是按位置传进去的。

位置参数的要求只有一条：实参的顺序必须和形参的顺序完全一致，数量也要对上。

### 关键字参数：名字对上了就不怕乱序

关键字参数换了个思路：传参时把形参名写出来，用"键等于值"的形式。

```python
reg_stu(name="王林", age=28, gender="男", city="北京")
```

这里的 `name`、`age`、`gender`、`city` 不是随便起的名字，它们必须是形参名；等号后面才是要传的值。

好处立刻显现：顺序无所谓。下面这样写，效果和上面完全一样。

```python
reg_stu(gender="女", city="北京", age=20, name="李慕婉")
```

每个值都指明了交给哪个形参，解释器不需要靠位置去猜。打印出来依然是 `name` 是李慕婉、`age` 是 20、`gender` 是女、`city` 是北京。

## 混着用：位置在前，关键字在后

两种方式可以混着写：

```python
reg_stu("赵四", 28, gender="男", city="上海")
```

前两个是位置参数，后两个是关键字参数。

但这里有一条硬规矩。

> **易错点**：混用时，位置参数必须全部写在关键字参数前面。反过来写，Python 直接报错 `positional argument follows keyword argument`。

```python
reg_stu(name="赵四", age=28, "男", "上海")   # 报错
```

为什么不允许？因为前面已经用 `name=` 和 `age=` 把两个形参占掉了，后面这两个没名没姓的值，解释器只能按位置往剩下的形参上套——剩下的是 `gender` 和 `city`，哪个是哪个？它不知道。

```text
def reg_stu(name,      age,      gender,      city)

reg_stu("赵四",        28,       gender="男",  city="上海")
        └── 位置 ──┘  └── 位置 ──┘ └── 关键字 ──┘
        ←──────── 位置参数在前，关键字参数在后 ────────→
```

读图说明：位置参数靠"排第几"确定归属，关键字参数靠"叫什么"确定归属；一旦某个值靠名字定位，排在它后面的无名值就失去了排序依据，所以只能让位置参数先走。

规则记两条就够：位置参数在前，关键字参数在后；关键字参数彼此之间随便排。

## 怎么选：半年后还看得懂，就用位置参数

两种方式都学会了，项目里到底用哪种？

先看写法差异。同样是注册学生，位置参数是 `("张三", 18, "男", "北京")`，关键字参数是 `(name="张三", age=18, gender="男", city="北京")`——后者明显啰嗦。

但啰嗦换来了别的东西。

| 对比项 | 位置参数 | 关键字参数 |
| :--- | :--- | :--- |
| 写法 | `f(87, 68, 92, 85)` | `f(math=87, chinese=68, english=92, computer=85)` |
| 顺序要求 | 必须与形参一一对应 | 无要求 |
| 优点 | 简洁 | 可读性强，易维护扩展 |
| 缺点 | 可读性差，容易出错，维护难 | 书写繁琐 |
| 适用场景 | 参数少且不易混淆 | 参数多且容易混淆 |

位置参数的短板在可读性。`("张三", 18, "男", "北京")` 还能猜：18 是年龄，男是性别，北京是城市。可换成这样一个调用：

```python
calc(87, 68, 92, 85)
```

四个数字，类型一样，大小也接近。谁是数学，谁是语文，谁是英语，谁是计算机？光看这一行调用，答不上来。

同一个函数换成关键字参数：

```python
calc(math=87, chinese=68, english=92, computer=85)
```

每个数字是干什么的，一眼就清楚。这就是关键字参数的可读性优势——代码首先是写给人看的，机器只是顺便执行一下。

所以选择的原则可以归成一句话：写完之后假设半年后回看，如果一眼能看出每个参数的含义，就用位置参数，简洁；如果看不出、还容易混淆，就用关键字参数。

再具体一点：参数只有两三个，含义差别大、顺序也自然（姓名、年龄、性别、城市），位置参数更合适；参数有四五个甚至七八个，而且类型相同、语义接近（比如一堆分数），就该上关键字参数。

> **结论**：两种传参方式没有绝对的好坏，只有合不合适。一切以代码的可读性和可维护性为准。

三个案例、变量作用域、传参方式，函数这一层的东西到这里就串成一条线了：定义时想清楚形参要什么，调用时想清楚实参怎么给，函数体内想清楚变量从哪儿来、结果往哪儿去。
