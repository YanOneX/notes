# 函数的入口与出口：参数、返回值与嵌套调用的执行顺序

## 括号里放什么，末尾那一行写什么

函数的骨架不难记：`def`、函数名、一对括号、冒号，加上缩进的函数体。写着写着，真正让人停住的是另外两个问题——括号里到底该放几个名字？函数算完的结果怎么交回给调用它的地方？

这两个问题没有标准答案，唯一的依据是业务需求。你要这个函数干什么，就直接决定了它需要从外面拿什么，又该往外还什么。算圆的面积，面积由半径决定，那半径就必须从外面传进来；算完的面积要交给调用者，函数体里就必须有一行 `return` 把结果交出去。

参数写在定义函数时的那对括号里，多个参数之间用逗号分隔。返回值写在函数体末尾，用 `return` 跟上具体的结果。

> **易错点**：`return` 必须放在函数体的最后一行。这不是排版上的讲究，而是执行语义决定的——一旦执行到 `return`，这个函数就立刻结束了，它带着结果返回调用处，`return` 之后的语句再也不会被执行。把 `return` 写在中间，等于把后面那些代码全部变成死代码。

所以写 `return` 的正确姿势是：把所有该做的计算做完，把结果准备好，最后一行交出去。

> **提示**：`return` 只负责把结果交回去，它没有打印功能。想在控制台上看到结果，得先找变量把返回值接住，再自己调用 `print` 输出。这两件事经常被混为一件事，下面那段代码就会露出马脚。

## 圆和长方形：两个有进有出的函数

### 半径进去，面积出来

第一个函数算圆的面积。圆面积是 $\pi r^2$，这里的 $\pi$ 取 3.14，那函数就只需要一个形参 `r`：

```python
def circle_area(r):
    area = 3.14 * r ** 2
    return area


result = circle_area(10)
print(result)
```

这段代码里有三个值得停一下的地方。

括号里的 `r`，写上去就等于声明了一个变量名，它的值不由函数自己决定，而是等调用方给。函数体里 `3.14 * r ** 2` 中的 `**` 是乘方，`r ** 2` 就是 $r$ 的平方；写成 `3.14 * r * r` 效果完全一样，看个人习惯。

计算结果先装进 `area` 再 `return area`，也可以省掉这个中间变量，直接 `return 3.14 * r ** 2`。我保留变量，是为了让"先算、再返回"这两步在结构上一眼可见。

调用 `circle_area(10)` 时，10 会传给 `r`，此时 `r` 就是 10，`r ** 2` 得到 100，乘上 3.14 得到 314.0。

第一次运行时，我其实只写了调用，没写接收，也没写输出。右键运行，控制台一片空白。代码没写错，是没人让它说话：整个文件里连一个 `print` 都没有，返回值被交回到调用处之后就被丢掉了。补上 `result = circle_area(10)` 把它接住，再 `print(result)`，314.0 才出现在屏幕上。

> **结论**：函数有返回值，只代表它能交出一个结果；这个结果要不要显示，是调用方的事。

### 长和宽，两个参数怎么排

长方形面积是长乘宽，需要两个数据，那就有两个形参，中间用逗号分隔：

```python
def rectangle_area(l, w):
    return l * w


print(rectangle_area(20, 10))
```

`l` 取自 length，代表长；`w` 取自 width，代表宽。函数名 `rectangle_area` 里的 rectangle 是长方形——这个单词要是拿不准，查一下词典比猜一个缩写强。命名这件事值得较真：变量名、函数名尽量专业，做到见名知意，多个单词之间用下划线分隔。项目里尤其如此，你随手起的 `a1`、`b2`，三个月后连自己都认不出来。

这次没有中间变量，函数体只有一行 `return l * w`。调用时传 20 和 10，20 给 `l`、10 给 `w`，输出 200。

因为调用表达式本身就是一个值，所以可以直接把它塞进 `print` 里：

```python
print(rectangle_area(20, 10))   # 200
```

有返回值，才有这个便利：调用表达式本身就是一个值，可以打印、可以赋给变量，也可以继续参与运算。

## 形参与实参：位置对上了，值才不会错

前面两个函数里出现的参数，其实分属两个不同的角色，各有各的名字。

定义函数时括号里写下的 `r`、`l`、`w`，叫**形参**，全称形式参数，简称形参。它本质上就是一个变量名，和你在函数体里 `area = ...` 起的名字没有区别，只是它的值要等调用时才有着落。

调用函数时括号里填进去的 `10`、`20`、`10`，叫**实参**，也就是实际传入的参数。它是真正参与运算的数据，函数最终算出什么，由它决定。

| 对比项 | 形参（形式参数） | 实参（实际参数） |
| :--- | :--- | :--- |
| 出现位置 | 定义函数时的括号里 | 调用函数时的括号里 |
| 本质 | 一个变量名，只在函数内部有效 | 真正参与运算的数据 |
| 作用 | 占住位置、接下传进来的值 | 提供这次运算的具体数值 |
| 多个时 | 逗号分隔 | 逗号分隔，且顺序与形参一致 |

> **定义**：形参是定义时括号里的变量名，实参是调用时括号里的实际数据；调用发生的那一刻，实参按位置依次赋值给形参。

形参还有一个容易被忽略的性质：它只在函数内部有效。`l` 和 `w` 出了 `rectangle_area` 这个函数，在下面的代码里就不存在了。这类只能在函数内部使用的变量叫**局部变量**，它的作用域问题后面单独讲，现在先记住"形参是函数内部的私有变量"就够了。

> **易错点**：实参的顺序必须和形参的顺序一致。形参第一个是长、第二个是宽，实参第一个也得是长、第二个也得是宽。写反了不会报错，20 和 10 照样能乘，只是长宽互换，结果看着还挺合理——这种错最难查。

调用时第一个实参交给第一个形参，第二个实参交给第二个形参，这条规则是位置对位置的。理解了这一点，也就理解了为什么 `rectangle_area(10, 20)` 和 `rectangle_area(20, 10)` 会给出同样的 200 却含义不同：一个是长 10 宽 20，一个是长 20 宽 10。

## 一个函数能不能返回多个值

能。而且写法比你想的简单：多个值之间用逗号分隔就行。

### 逗号一分隔，两个结果一起回来

这次的需求是同时算圆的面积和周长。两者都只依赖半径，所以形参还是一个 `r`：

```python
def circle_area_length(r):
    return 3.14 * r * r, 2 * 3.14 * r


al = circle_area_length(10)
print(al)          # (314.0, 62.8)
print(type(al))    # <class 'tuple'>
```

`return` 后面跟两个表达式，中间一个逗号：前一个是面积 $\pi r^2$，后一个是周长 $2\pi r$。不需要先定义两个变量把结果接住、再把两个变量返回，直接 `return` 计算结果即可。

用一个变量 `al` 接住调用结果，打印出来是带着一对小括号的两项。小括号里包着多个元素——前面讲数据容器时见过这个形式，它是一个**元组**。再用 `type(al)` 一看，输出 `<class 'tuple'>`，坐实了。

> **结论**：所谓"函数返回多个值"，实际返回的是**一个元组**，Python 在 `return` 处把逗号分隔的多个结果自动打包了进去。多个返回值之间用逗号分隔，接收到的就是一个元组。

### 小数位收一下：round

3.14 是 $\pi$ 的近似值，乘出来带着一串小数，浮点数运算本身还有精度损失，这在前面讲数据类型时已经踩过一次。让结果保留一位小数，看起来干净得多。

Python 内置了一个专门做四舍五入的函数 `round`，不需要 import，拿来就能用：

```python
def circle_area_length(r):
    return round(3.14 * r * r, 1), round(2 * 3.14 * r, 1)
```

`round` 接收两个参数：第一个是要处理的数字，第二个是保留的小数位数。`round(3.14 * r * r, 1)` 就是对面积四舍五入、保留一位小数；周长同理，后面也补一个 `, 1`。

```python
print(circle_area_length(10))   # (314.0, 62.8)
```

两个值都收成了一位小数。

### 解包：一步拿到两个结果

拿到元组之后，如果只想要面积，可以写 `al[0]`；想要周长，写 `al[1]`。但两个都要的时候，有更省事的写法：

```python
area, length = circle_area_length(10)
print(area, length)   # 314.0 62.8
```

等号左边两个变量，右边一个装着两个元素的元组。执行时第一个元素赋给 `area`，第二个赋给 `length`——这就是元组的解包。它把"从容器里一个个往外取"这件事，压缩成了一行赋值。

> **提示**：解包靠的是位置——左边第一个变量拿元组的第一个元素，第二个拿第二个。变量个数要和元素个数对上，多一个少一个都不成立。

## 说明文档：写给下一个调用它的人

换个位置想一想。把刚才那两个函数摆在你面前，`l` 是什么意思、`w` 是什么意思、这两个返回值哪个是面积哪个是周长？你刚写完，当然答得上。但如果这两个函数不是你写的，是项目里别人写好的，你只有一个函数名和几个单字母参数，能确定吗？

不能。代码里没有任何解释，形参叫 `l`、`w`，返回值是两个裸数字，全靠猜。这样的代码难读，也难维护——三个月后改这段代码的人，很可能就是你自己。

解决办法是给函数配一份说明文档。

### 三引号写在函数体第一行

说明文档写在函数体的最开头，紧跟在 `def` 那行下面，用三引号包起来。三引号前面讲多行注释时用过，位置换到函数体的第一行，它就有了专门的身份：函数的说明文档，英文叫 docstring。

内容分三块：第一行一句话说清这个函数干什么；`:param 参数名:` 逐个说明形参的含义；`:return:` 说明返回值是什么。

```python
def rectangle_area(l, w):
    """
    根据长方形的长度和宽度，计算长方形的面积
    :param l: 长方形的长度
    :param w: 长方形的宽度
    :return: 长方形的面积
    """
    return l * w
```

几个形参就写几个 `:param`，这里两个形参，所以两条。函数有 `return`，才需要写 `:return:`。

返回值有多个时，`:return:` 里按返回顺序把每个值都交代清楚：

```python
def circle_area_length(r):
    """
    根据圆的半径，计算圆的面积和周长
    :param r: 圆的半径
    :return: 圆的面积, 圆的周长
    """
    return round(3.14 * r * r, 1), round(2 * 3.14 * r, 1)
```

敲起来也不费事。在函数体第一行敲三个引号再回车，IDE 会自动把骨架铺好：上面一个空行留给你写功能，有几个形参就生成几条 `:param`，有 `return` 才生成 `:return`。你只需要往模板里填内容。

### 三种查看方式

写完之后，别人想知道这个函数怎么用，有三条路。

第一条，直接翻到函数定义的那段代码，从头读一遍。

第二条，用内置函数 `help` 查：

```python
help(rectangle_area)
```

`help` 是 Python 自带的，专门用来查看指定函数的说明文档。注意后面**不加括号**——`rectangle_area` 是把这个函数对象交给 `help`，而 `rectangle_area()` 是调用它，两者完全不同。执行后，说明文档会原样打印出来。

第三条，也是最常用的：鼠标悬停在函数名上。IDE 会弹出一个小窗，函数功能、每个形参的含义、返回值的含义都在里面，就是你在 docstring 里写的那几句话。

顺带看一眼 Python 自己的函数。按住 `Ctrl` 键，鼠标点在 `print` 上再点击，就跳进了它的源码——`print` 是内置函数，它同样带着一段三引号包起来的说明文档。同一层源码里，其他内置函数也都有各自的文档。

> **结论**：好的文档让代码更容易理解、更容易使用，也更容易维护。项目里定义的函数，尽可能都配上详细的说明文档。

## 嵌套调用：谁最后进来，谁最先出去

一个函数里可以调用另一个函数，这叫函数的嵌套调用。写起来平平无奇，跑起来却有个非常具体的顺序问题：A 调到 B、B 又调到 C，C 结束之后程序回到哪儿？

先看这段代码，三个函数层层调用：

```python
def function_a():
    print('a before')
    function_b()
    print('a after')


def function_b():
    print('b before')
    function_c()
    print('b after')


def function_c():
    print('c ...')


function_a()
print('函数调用完毕')
```

先明确一件事：`def` 只是把函数定义出来，定义本身不执行。这三个函数摆在那里，一行函数体都不会跑，只有当 `function_a()` 被调用的那一刻，函数体里的逻辑才开始执行。

### 栈的规矩：只能从一端进出

函数调用遵循**栈**结构。栈是一种数据结构，它只允许在一端操作，这一端叫栈顶。往里存数据叫入栈，从里面删数据叫出栈，两个动作都只能发生在栈顶。

它的特点是 LIFO：last in first out，后进先出，反过来念就是先进后出。

这个结构在生活里有现成的对照——手枪弹夹。弹夹只能从顶部那一端压子弹，也只能从同一端退子弹；最先压进去的子弹排在最低下，最后才打出去，最后压进去的那颗反而最先出膛。函数调用一模一样：最后被调用的函数在最上面，最先结束、最先离开。

程序运行时，永远执行栈顶那一段代码。这条规则是理解整个流程的钥匙。

### 三步入栈，三步出栈

```text
[1] 调用 function_a()
+------------------+
| function_a       |  <- 栈顶（正在执行）
+------------------+
| <module>         |
+------------------+

[2] function_a 里执行到 function_b()
+------------------+
| function_b       |  <- 栈顶（正在执行）
+------------------+
| function_a       |
+------------------+
| <module>         |
+------------------+

[3] function_b 里执行到 function_c()
+------------------+
| function_c       |  <- 栈顶（正在执行）
+------------------+
| function_b       |
+------------------+
| function_a       |
+------------------+
| <module>         |
+------------------+
```

三张图是同一次调用的三个阶段：每调用一层，新函数就压在栈顶，原来的函数被压在下面，但它没有消失，只是暂停在那里等着。

整个流程按步拆开是这样的：

1. 调用 `function_a()`，`function_a` 入栈，成为栈顶，程序开始执行它的函数体。
2. 打印 `a before`。接着遇到 `function_b()`，`function_b` 入栈，成为新的栈顶，`function_a` 沉到下面；程序转去执行 `function_b`。
3. 打印 `b before`。接着遇到 `function_c()`，`function_c` 入栈，成为栈顶。
4. `function_c` 打印 `c ...`，函数体结束。这一层的活儿干完了，`function_c` 出栈。
5. 栈顶回到 `function_b`。它从 `function_c()` 那一行的下一行继续：打印 `b after`。有返回值就先交回给调用处，没有就到此为止，然后 `function_b` 出栈。
6. 栈顶回到 `function_a`。它从 `function_b()` 的下一行继续：打印 `a after`，随后 `function_a` 出栈。
7. 栈空了，回到模块顶层，打印 `函数调用完毕`，这块栈空间随之释放。

```text
a before
b before
c ...
b after
a after
函数调用完毕
```

注意中间那三行的顺序：`b after` 排在 `c ...` 后面，`a after` 排在 `b after` 后面。每个函数的"后半段"都要等它调用的那个函数彻底结束、从栈里退出之后，才轮得到执行。这就是嵌套调用看起来"进去一层、再进去一层，然后一层层退回来"的原因。

> **易错点**：别把"调用顺序"当成"执行顺序"。调用顺序是 A → B → C，执行完的顺序却是 C → B → A。写代码时想不清楚，就把栈画出来，谁在栈顶谁在跑。

### 用断点把这段流程看一遍

光看文字容易点头，实际跑一遍才踏实。在 `function_a()` 那一行打个断点，用 Debug 模式启动，程序就会停在那里。

单步执行有两种走法。按 F8 是单步跳过：它不进入被调用的函数，直接执行完这一行、停在下一行。按 F7 是单步进入：它会钻进函数内部，让你一行一行看函数体怎么执行。

更直观的办法是在 `function_a`、`function_b`、`function_c` 三个函数体的第一行各打一个断点，让程序自己停在每一层。打开左侧的"线程和变量"面板，那里显示的就是调用栈：最上面一行是栈顶，也就是正在执行的函数；往下依次是等着它返回的调用者。

按照断点的节奏点下去，你能亲眼看到 `function_a` 入栈、`function_b` 压上去、`function_c` 再压上去；`function_c` 执行完从栈里消失，回到 `function_b` 的后半段，再回到 `function_a` 的后半段。断点全部取消、直接运行，输出顺序和上面分析的完全一致。

自己把这段代码敲一遍，跟着断点走一趟，比背"后进先出"这四个字管用得多。
