# 位置与关键字参数

* **形参与实参**
* > **定义**：定义函数时括号里的变量名是形参（形式参数），本质是一个只在函数内部有效的变量名；调用时括号里的数据是实参（实际参数）。

* 调用发生的那一刻，实参按位置依次赋值给形参。
* 形参是函数内部的私有变量，出了这个函数就不存在。

| 对比项 | 形参（形式参数） | 实参（实际参数） |
| :--- | :--- | :--- |
| 出现位置 | 定义函数的括号里 | 调用函数的括号里 |
| 本质 | 只在函数内部有效的变量名 | 真正参与运算的数据 |
| 作用 | 占住位置、承接传入的值 | 提供本次运算的具体数值 |
| 多个时 | 逗号分隔 | 逗号分隔，顺序与形参一致 |

* **位置参数**
* 按定义时形参的先后顺序一一对应，第一个实参给第一个形参，数量也必须对上。
* `rectangle_area(10, 20)` 与 `rectangle_area(20, 10)` 结果都是 200，含义却分别是长 10 宽 20 和长 20 宽 10。
* > **易错点**：实参顺序与形参不一致不会报错，两个数照样相乘，只是含义互换、结果看着还挺合理，这种错最难查。

* **关键字参数**
* 传参时写出形参名，形式为 `键=值`，等号左边的键必须是形参名。
* 顺序无所谓，每个值靠名字定位：`reg_stu(gender="女", city="北京", age=20, name="李慕婉")` 与按定义顺序传的效果一致。

* **混用规则**
* 位置参数必须全部写在关键字参数前面；反写直接报 `positional argument follows keyword argument`。
* 原因是靠名字定位之后，排在后面的无名值失去了排序依据，解释器无法判断它该落到哪个形参上。
* 关键字参数彼此之间可以任意排序。

* **两种方式的取舍**

| 对比项 | 位置参数 | 关键字参数 |
| :--- | :--- | :--- |
| 写法 | `f(87, 68, 92, 85)` | `f(math=87, chinese=68, english=92, computer=85)` |
| 顺序要求 | 必须与形参一一对应 | 无要求 |
| 优点 | 简洁 | 可读性强，易维护扩展 |
| 缺点 | 可读性差，容易出错，维护难 | 书写繁琐 |
| 适用场景 | 参数少且不易混淆 | 参数多且容易混淆 |

* 判断标准：假设半年后回看，一眼能看出每个参数含义就用位置参数；看不出、容易混淆就用关键字参数。
* 参数只有两三个、语义差别大、顺序自然（姓名、年龄、性别、城市）时，位置参数更合适；四五个以上、类型相同语义接近（一堆分数）时，该上关键字参数。
